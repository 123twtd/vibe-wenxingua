# ADR-0015：卦条 v1 扩到两法（小六壬分支）

| 项 | 内容 |

| 状态 | 已接受 |
| 日期 | 2026-10-07 |

| 影响的模块 | `core/guaTiao.mjs`、`core/divination.mjs`、`core/xiaoliuren.mjs`、`schema/gua-tiao.schema.json`、`server/index.mjs`、`web/views.js`、`agent/tools.mjs`、`tools/check.mjs`、`tools/check-web.mjs`、`docs/规范.md` |

## 背景

「卦条 v1」是 `core/guaTiao.mjs` 定义的纯文本导入契约（[ADR-0005](./ADR-0005-卦条v1导入契约.md)）。它从立起就只描述梅花易数：四张表（`GUATIAO_VERSION`／`FIELD_ALIASES`／`METHOD_NAMES`／`BOOL_TRUE`）里只登记了梅花四种起卦法，`METHOD_NAMES` 也只在中英互转那四种。

小六壬是另一套占法，自 v1.2.0 起与梅花并列（`core/xiaoliuren.mjs`：`XLR_METHODS` 两种、`XLR_PALACES` 六宫、`castXlr()`／`interpretXlr()`），它的 `chart` 走三宫形态（`kind: 'xlr'`、`palaces`、`result`、`casting`、`calendar`），不设六爻与体用。`schema/record.schema.json` 早已为它开出 `chart`／`reading` 的 `oneOf` 双分支。

但**导入这一层把小六壬挡在门外**：`core/guaTiao.mjs` 认出「法」里的六壬字样就返回 `unsupported: 'xlr'` 并列入 `missing`，`toGuaTiao()` 也把小六壬卦录导出成一张「本文件只作文字存档之用」的说明（`xlrToNotice`），`docs/规范.md` §2.3 明写「小六壬不走卦条导入」。于是小六壬只能从起卦台手点、或让助手用 `cast` 录入，历史之课没法像梅花那样成批粘进来。

界面侧同样只有梅花：导入页的模板、字段字典、格式速查全取自 `GET /api/spec` 的 `guaTiao` 单份数据；卦典页只列六十四卦与三百八十四爻辞，`XLR_PALACES` 那张六宫表（名／六神／五行／方位／神数／口诀／吉凶）在界面里看不到。

## 决策

1. 卦条 v1 **必须**按「法」分为两个分支：梅花（现有字段，一字不改）与小六壬。「法」写小六壬字样（`小六壬报数`／`小六壬月日时辰`）时**必须**走小六壬分支，**不得**再返回 `unsupported`。
2. 小六壬分支**必须**支持这些字段：`数`（报数起课，1–3 个数）、`时`、`历`（`农历`／`公历`，月日时辰起课用；不写时按农历并在 `warnings` 里写明）、`三宫`（可选，只作对校）。
3. **课仍由引擎算。** 三宫**必须**由 `core/divination.mjs` 的 `cast()`（`method: xlrNumbers｜xlrTime`）重算；卦条里写的「三宫」与重算不符时**必须**记入校勘，**不得**被当成结果直接采信。这与梅花分支写「互卦／变卦」同一条规矩（[ADR-0004](./ADR-0004-cast是唯一真源.md)）。
4. `toGuaTiao()` **必须**对小六壬卦录产出**可再导入的真卦条**（含时、法、数、历），**不得**再产出只供阅读的说明文件。
5. 公共字段（题／问／类／背景／签／标签／复盘／复盘条目／问答／原文／方案／校勘）两法**必须**共用同一套键与别名；`title`／`localTime` 等别名表**不得**为两法各写一份。
6. 模板**必须**由 `core/guaTiao.mjs` 生成两套（梅花、小六壬）并随 `GET /api/spec` 下发；界面**不得**把模板或字段字典硬编码在视图里。
7. 缺项**必须**报缺（写进 `missing`），**不得**猜补；这条与 ADR-0005 一致，两法同样适用。
8. 六宫表与两法的数法说明**必须**取自 `core/xiaoliuren.mjs` 的 `XLR_PALACES`，经 `GET /api/knowledge/xlr` 供卦典页渲染；界面**不得**另抄一份六宫数据。

## 理由

1. **小六壬在别处都是一等公民，只有导入不是。** 列表、详情、导出、应期、走势排除、助手工具、schema 双分支全都按 `chart.kind` 分好了；导入这一层的拒收是**遗留的不对称**，不是设计取舍。
2. **历史之课需要批量录。** 梅花的旧卦可以粘对话文本或写卦条成批进来；小六壬若只能手点起卦台，等于把它降级成「不能整理旧课的占法」。用户提出的正是这一条（「导入、卦典、文档都没有区分出来小六壬专属的模板、解析器、卦典类似的东西」）。
3. **分流判据是现成的、不含糊。** 两法的必填字段完全不同：梅花要「本卦＋动」或「数＋动」，小六壬要「数」或「时＋历」。判据落在「法」这一键上，不需要从其它字段猜——这正是 ADR-0005「宁可少认，不可错认」的用法。
4. **不动梅花的任何字段。** 新增的 `历` 与 `三宫` 只在小六壬分支出现，梅花卦条一个字不用改；`FIELD_ALIASES` 只增不改（既有兼容承诺不变）。
5. **一处实现多处复用。** 模板、解析、入库、导出仍全在 `core/guaTiao.mjs` 一份里，导入页、`tools/import.mjs`、agent 的 `save_gua_tiao`、`tools/validate.mjs` 四处入口自动同时获得小六壬支持，不需要各自加分支。

## 后果

### 正面

- 小六壬之课可以像梅花一样写卦条、粘文本、让助手代录，且**导出→改→再导入**闭环成立（往返一致有自检断言）。
- 导入页与卦典页都能按占法分区呈现，用户不必再猜「小六壬为什么不在模板里」。
- 六宫表从代码里的常量变成界面可见的知识（卦典页两栏），补上了「卦典」对小六壬的空缺。
- 拒收逻辑删除后，`unsupported` 这条分支只剩「认不出的东西」一种含义，语义更干净。

### 负面

- **旧导出文本不再可往返。** v1.6.0 之前 `toGuaTiao()` 对小六壬产出的是说明格式（带「此条为小六壬卦录…」注释、且**故意不写时与数**）。这类文本再导入会因缺「数／时」而报缺——不会错认成梅花（注释行被忽略、法仍是小六壬），但也不再是「原样进原样出」。这是本次唯一的兼容性代价，接受它，因为那种导出**从来就没有承诺过可再导入**（它自己写着「本文件作文字存档之用」）。
- **模板从一份变两份。** 导入页要多一处说明，用户要先认出自己那一课属于哪种占法。这一层认知成本换的是「两法各自字段清楚」，值得。
- **schema 变宽。** `fields.method` 的 enum 从 4 项到 6 项、`claimed` 多一小六壬分支；校验器对新字段的约束比梅花松一些（三宫只校验数量与名字）。宽度换来的是两法共用一套结构。
- **`数` 在两法里含义不同**（梅花：报数除六取动爻；小六壬：顺数落宫）。歧义由「法」消解，但读卦条的人必须看「法」——文档里要把这点写显眼。

## 备选方案与为何不选

| 方案 | 为什么没选 |
|---|---|
| 保持拒收，只把「怎么录」在导入页说清楚 | 治标。用户要的正是「小六壬有自己的模板与解析器」；只给说明等于承认这块永远不行，历史之课仍只能手点。 |
| 另立「课条 v1」新格式（`# 课条 v1`，字段全套另写） | 会多出一套解析器、一套 schema、一套别名表、一套模板与自检——凡是有小六壬的地方都要写两遍。两法共用公共字段（题／问／类／背景／签／复盘…）的收益远大于「格式名字不同」带来的清晰。 |
| 小六壬只支持 JSON 导入（不走纯文本） | JSON 手写门槛高、AI 也更容易写错结构；纯文本是「人三十秒能写完」的那一层，正是导入的价值所在。 |
| 让「三宫」直接入库（不重算） | 违背「卦象只能由引擎算」这条全项目最硬的约束（ADR-0004）。手抄的三宫一旦错一位，卦录就永久错下去；而重算＋对校能当场把不一致记进校勘。 |
