# ADR-0014：皮肤由插件提供（registerSkin 扩展点）

| 项 | 内容 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-07 |
| 决策者 | 项目维护者 |
| 影响的模块 | `server/plugins.mjs`、`web/skin.mjs`、`web/app.js`、`web/views.js`、`web/style.css`、`data/plugins/skins.mjs`、`tools/check.mjs`、`tools/check-web.mjs`、`tools/check-desktop.mjs`、`docs/08-前端设计与交互规范.md`、`docs/12-插件与扩展开发指南.md` |

## 背景

界面原先只有一条主题轴：`web/style.css` 顶部两组令牌（`:root` 是宣纸，`:root[data-theme="night"]` 是夜读），`web/app.js` 的 `applyTheme()` 把 `data-theme` 设在 `<html>` 上，选择记在 `localStorage` 的 `qxg.theme`。这条轴只调明暗，不动设计语言——材质、字体、色彩、控件形状、装饰、密度、动效全归 `web/style.css` 一份实现。

插件宿主 `server/plugins.mjs` 已有四类注册：`registerRoute`／`registerPage`／`registerPanel`／`registerExporter`，另有 `ctx.on`、`ctx.store`、`ctx.core`、`ctx.assetsDir`。现有随包样例三个（`review-watch`／`stats-plus`／`html-card`，见 `data/plugins/`）。插件页面是**静态 HTML 字符串**——`web/app.js` 的 `render()` 以 `root.innerHTML = out.html` 插入，页面里的脚本不执行；因此插件要让「整套设计语言」作用于外壳部件（顶栏、侧栏、卡片、弹层），唯一的落点是宿主开一个扩展点，由外壳来应用。

需求（来自使用者）：做一款皮肤插件，提供四种风格（唐风宫苑、宋瓷汝窑、竹影清舍、星野玄穹），每种都自带宣纸与夜读两式；皮肤是插件，因此必须能停用与启用，停用时界面回落默认样式。

## 决策

1. 插件宿主**必须**提供 `ctx.registerSkin({ id, name, hint, swatch, css })`；`css` 是一整段样式文本，宿主**必须**自动把它挂为 `GET /api/plugins/<插件id>/skin/<皮肤id>.css`（`Content-Type: text/css; charset=utf-8`，`Cache-Control: no-store`），并把皮肤列进 `/api/meta` 的 `plugins.skins`。
2. 皮肤 id **必须**全局唯一。冲突时**必须**跳过后来者并在插件页报出原因，**不得**静默覆盖。
3. 皮肤 CSS **必须**自带两式，并**必须**自行作用域化：宣纸式写在 `[data-skin="<id>"]` 下，夜读式写在 `[data-skin="<id>"][data-theme="night"]` 下；不含 `data-skin` 字样的样式宿主**必须**拒绝注册并报错——否则会泄漏到全局，污染其他皮肤与默认样式。
4. 外壳**必须**以「`<html data-skin="<id>">` ＋ 一张 `<link rel="stylesheet" id="skin-css">`」应用皮肤；选择记在 `localStorage` 的 `qxg.skin`（`{ id, url }`），模块加载时就套用，**不**等 `/api/meta`（避免先闪一下默认样式）。
5. 默认皮肤**必须**是内置的宣纸水墨（没有 `data-skin` 属性即默认）。已选皮肤在 meta 清单里找不到（插件停用、载入失败或已删除）时，外壳**必须**回落默认**并保留选择**；插件重新启用后自动恢复，**不得**报错。
6. 昼夜（宣纸／夜读）仍是原来那条轴，由顶栏按钮切换；皮肤与它正交，四款皮肤**必须**在两式下都可用。
7. 选择入口**应当**集中在设置页的「外 观」区；插件页**应当**列出该插件提供的皮肤，停用与启用要能看出影响面。

## 理由

1. **扩展点只能开在宿主。** 插件页面是静态 HTML 字符串（`innerHTML` 插入、脚本不执行），皮肤要触达顶栏、侧栏、助手面板、弹层这些外壳部件，插件自身够不着。
2. **与既有主题轴正交。** 「宣纸／夜读」解决明暗，「皮肤」解决设计语言，`data-theme` 与 `data-skin` 是两个独立属性；四款皮肤 × 两式 = 八组令牌组合，由 CSS 选择器自然组合出来，外壳不需要为组合枚举。
3. **meta 驱动的清单让停用语义自动成立。** 清单里没有的皮肤，外壳自然回落；插件停用、删除、载入失败三条路径共用同一条回落逻辑，外壳不需要认识任何具体插件。
4. **单文件插件，零新增工程面。** CSS 作为字符串随 `.mjs` 走现有热载与 seed 分发，无需静态资源目录、无需 `.gitignore` 例外、无需处理文件缓存。
5. **同一份契约对第三方开放。** 与 [ADR-0007](./ADR-0007-插件用文件模块.md) 的取向一致：能力开在注册面上，官方四款皮肤只是第一个消费者，不是特权实现。

## 后果

### 正面

- 官方皮肤插件 `data/plugins/skins.mjs` 随包分发（seed-data），四款皮肤各带两式，可随时停用与启用。
- 任何插件都能注册皮肤；皮肤不必改动 `web/style.css`，也不必碰外壳代码。
- 自检可以直接断言契约：注册齐备、两式齐全、路由回 `text/css`、id 冲突被拒、停用后清单清空且外壳回落。
- 切换即时生效，不需重启，也不需重载插件。

### 负面

- **CSS 以 JS 模板字符串存在**：编辑器对它的支持弱于独立 `.css` 文件（没有补全、没有独立格式化）。接受这个代价，换「一个 `.mjs` 即一套皮肤」的分发与热载。
- **宿主只能做最弱的静态校验**（非空、含 `data-skin`、id 唯一）。两式是否真齐全、对比度是否可读，宿主验不了——由官方插件的自检断言与作者自觉承担。
- **两式必须齐全不是可选项**：皮肤 `<link>` 晚于 `web/style.css` 加载，`[data-skin="x"]` 与 `:root[data-theme="night"]` 同权重时文件在后者胜出——只写宣纸式的皮肤在夜读下会亮着白纸。
- **首帧可能闪一下默认样式**：用 `localStorage` 直读加模块顶部立刻套用来缓解；皮肤样式尚未返回前的视觉就是默认样式（可接受，也正好是停用后的正确视觉）。
- 皮肤允许写组件级规则（限定在 `[data-skin]` 下），表达力更强，也意味着更大的「改坏对比度」空间，属于刻意接受。

## 备选方案与为何不选

| 方案 | 为什么没选 |
|---|---|
| 外壳硬编码读某个特定插件（如 `/api/plugins/skins/list`） | 外壳与具体插件耦合，第三方无法提供皮肤；插件停用后外壳还得专门处理，违背插件可插拔的前提。 |
| 皮肤 CSS 放静态资源目录 `data/plugins/<id>/*.css` | 要开 `.gitignore` 例外、要新增资源目录约定、要处理浏览器缓存；收益仅是编辑体验，不值这份工程面。 |
| 皮肤写进 `web/style.css`、由外壳内置 | 与「皮肤是插件、可停用」的需求直接冲突；四款皮肤的维护也不该挤进外壳样式表。 |
| 用 `registerPage` 让插件自渲染一个皮肤设置页 | 页面只占主区、脚本不执行，改不到外壳；可作为补充入口，替代不了宿主扩展点。 |
| 只允许皮肤覆盖 CSS 令牌（不许写组件规则） | 令牌表达不了材质纹理、卡片形状、动效这些设计语言差异，四款皮肤会退回「只换颜色」，正是使用者明确不要的。 |
