# ADR-0001：零第三方依赖

| 项 | 内容 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-03 |
| 决策者 | 项目维护者 |
| 影响的模块 | `package.json`、`core/schema.mjs`、`core/calendar.mjs`、`core/hexagram.mjs`、`server/index.mjs`、`web/chart.js`、`web/md.js`、`agent/provider.mjs`、`agent/mcp-server.mjs`、`tools/*.mjs` |

## 背景

`package.json` 里 `dependencies` 是一个空对象，`engines.node` 写的是 `>=18`。这不是尚未添加依赖，而是刻意的结果：全仓的运行时依赖只有两类——Node 内置模块（`node:fs`、`node:path`、`node:http`、`node:readline`、`node:url`、`node:child_process`、`node:os`）与浏览器原生 API（原生 ES 模块、`fetch`、SVG、`localStorage`）。

放弃生态之后，凡是要用库的地方都改成了自己写：

- `core/schema.mjs`（约 140 行）是一个手写的 JSON Schema 校验器，只支持一份**明确的子集**：`type`／`enum`／`const`／`properties`／`required`／`additionalProperties`／`items`／`minItems`／`maxItems`／`minimum`／`maximum`／`minLength`／`maxLength`／`pattern`／`oneOf`／`anyOf`。它显式不支持 `$ref`／`allOf`／`not`／`if-then-else`／`dependentSchemas`／`patternProperties`，遇到这些关键字会**报「不支持」而不是静默放过**。
- `web/chart.js`（约 180 行）自己拼 SVG，实现多线叠加、图例、平滑、十字准星与点击跳转。
- `web/md.js`（约 130 行）是极简 Markdown 渲染器，覆盖标题、粗体斜体、行内码、链接、列表、引用、表格、围栏代码块、水平线、段落——刚好够把导入的原文与卦录导出显示得体面。
- `core/calendar.mjs` 自己算儒略日、太阳视黄经、均时差、节气月建与日干支，是**低精度天文近似**（太阳视黄经误差约 0.01°，折合时刻误差 ≲ 15 分钟），足够定节气、月建与时辰，不充当历书。
- `agent/mcp-server.mjs` 用 `node:readline` 逐行读 stdin，自己实现 JSON-RPC 2.0 的 `initialize`／`tools/list`／`tools/call`／`resources/*`／`prompts/*`。
- `agent/provider.mjs` 只用 `fetch` 与 `AbortController`，不引任何厂商 SDK。
- `server/index.mjs` 用 `node:http` 手写路由，没有 Web 框架。

项目里唯一带 `node_modules` 的目录是 `desktop/`，其中 `electron` 与 `electron-builder` 属于**开发期打包工具**，不在运行时依赖链上——打包产物 `desktop/dist/win-unpacked/` 里带着 Electron 自有的 Chromium 与 Node 运行时，用户机器上什么都不用装。`knowledge/64gua.json`（64 卦）与 `knowledge/yaoci.json`（384 爻）是数据资产而非代码依赖，缺失时 `core/hexagram.mjs` 会退化为内置卦表并给出告警。

## 决策

`package.json` 的 `dependencies` **必须**永远是空对象。新增能力一律自己写：需要校验就扩受支持的 schema 子集，需要画图就扩 `web/chart.js`，需要解析就往 `core/importer.mjs` 的 `parseMany` 加分支。**不得**为了少写三十行而引库，也**不得**用 `optionalDependencies`／`peerDependencies`／动态 `import()` 的第三方包绕过这条规则。`desktop/` 的 `electron`、`electron-builder` 应当继续留在 `devDependencies`，这不构成破例。

## 理由

1. **十年后还要能跑起来。** 这是本项目的立项前提：卦录是要陪用户几十年的东西，程序本身也应当能陪。依赖树会随 npm 生态漂移——包被删除、被改名、被投毒、上游 breaking change、lockfile 与 registry 状态不一致。零依赖把这整类风险一次削掉：只要有 Node 18+，把文件夹拷到任何机器上都能 `node server/index.mjs` 起服务。
2. **供应链面为零。** 单机软件保存的是用户几十年的私事记录。不安装第三方包，就不存在 `postinstall` 脚本、传递依赖投毒、构建期代码执行的暴露面。
3. **自己的东西自己修得动。** 七套自检（`tools/check.mjs` 152 项、`check-validate.mjs` 6 项、`check-mcp.mjs` 14 项、`check-hermes.mjs` 62 项、`check-desktop.mjs` 45 项、`check-web.mjs` 80 项、`check-docs.mjs` 25 项，合计 384 项）与 `tools/validate.mjs` 能对内核做细粒度断言，前提是内核的每一行都在本仓里。引一个库进来，出问题时先要判断是库的问题还是调用方式的问题；扩一个库的能力，先要读它的源码或文档。
4. **体积与冷启动。** 服务端没有任何依赖安装步骤，桌面包直接进 NSIS 安装器；`tools/check.mjs` 不需要起服务就能跑完内核断言。

## 后果

### 正面

- 无安装步骤：命令行版 clone 完即可运行，桌面版把 `win-unpacked` 拷到 U 盘即可运行。
- 无版本冲突、无 lockfile 漂移、无 registry 可用性问题（在国内网络环境下这一点尤其实际）。
- 自检能断言到「校验器必须抓得出错」这一层：`tools/check-validate.mjs` 故意注入未声明字段、打乱七段顺序、把动爻阴阳改成与六爻不符，全部必须报错——一个永远通过的校验器等于没有。
- 代码可读性由体量保证：单个模块普遍在 100–600 行，任何一个文件都能一次读完。

### 负面

- **开发速度换来的。** 每加一个能力都要自己写，且要自己写测试。上文列出的六个自写模块合计约一千行，是本决策的直接代价。
- **上限是「够用」，不是「最好」。** `core/schema.mjs` 不支持 `$ref`，因此 `schema/record.schema.json` 不能像标准写法那样抽公共子结构，只能适度重复；`web/chart.js` 不是通用图表库，只有折线叠加与它需要的交互；`web/md.js` 不覆盖 CommonMark 全量语法。
- **历法精度有明确天花板。** `core/calendar.mjs` 不引天文库，误差 ≲ 15 分钟，已在文档中如实标注为「低精度近似，不当历书用」。要提升精度必须自己继续写摄动项，没有现成轮子可搭。
- **人才门槛。** 新维护者熟悉的库在这里都不存在，需要先读内核。这一点用 `AGENTS.md` 的「硬规矩」与「扩展点速查」两节来补偿。

### 对模块边界的约束

零依赖同时约束了分层：`core/` 只能依赖 `core/` 与 Node 内置模块，不碰网络、不碰 DOM；`server/` 依赖 `core/`；`web/` 只与 HTTP 接口说话；`agent/` 依赖 `core/` 与 `server/store.mjs`。任何越界的 `import` 都意味着同时破了两条规矩。

## 备选方案与为何不选

| 方案 | 为什么没选 |
|---|---|
| 全量引入成熟依赖（ajv + chart.js + marked + express 之类） | 把「十年后还能跑」换成「今天写得快」。卦录的寿命按十年计，而依赖树的寿命按季度计，两者不匹配。 |
| 只引「小而稳」的几个包 | 「小而稳」是当下的判断，不是十年后的保证；且一旦开了口子，后续每一次「就差一个库」都会以同样的理由通过。 |
| 引入依赖但把 `node_modules` 提交进仓库 | 体量巨大且把供应链风险变成仓库风险；同时 `git diff` 失去可读性。 |
| 用标准 JSON Schema 全量支持换取通用性 | 需要数千行并引入正则回溯等性能与安全风险；本项目的 schema 只服务两份自家契约（`schema/record.schema.json`、`schema/gua-tiao.schema.json`），明确子集足够，而且「不支持的关键字必须报错」比「悄悄忽略」安全得多。 |
| 历法改用成熟天文库 | 会把运行时依赖、平台二进制或数据表带进来，收益只是把 15 分钟误差压到秒级；而对定节气、定月建、定时辰这个用途，15 分钟误差不影响结论。 |
