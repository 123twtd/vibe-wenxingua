## 一、通用约定

### 1.1 基址与端口
| 项 | 值 |
|---|---|
| 默认端口 / 主机 | `19730` / `127.0.0.1` |
| `QXG_PORT` / `QXG_HOST` | 环境变量，优先级高于 `--port` / `--host` |
| `QXG_DATA_DIR` | 数据目录，最高优先级；桌面版在载入服务前设定 |
| 基址 | `http://127.0.0.1:19730/` |
| 命令行 | `node server/index.mjs [--port 19730] [--open]` |
桌面版在**同一进程内** `import` 服务模块并调 `app.listen()`，不 spawn 子进程；固定 `listen(19730,'127.0.0.1')`，端口被占时系统分配（`listen(0)`）。命令行版端口占用报 `EADDRINUSE`，退出码 1。

### 1.2 内容类型
`application/json; charset=utf-8`（绝大多数，`JSON.stringify(data, null, 2)`）、`text/plain; charset=utf-8`（卦条模板、卦签、`ctx.text()`）、`text/markdown; charset=utf-8`（Markdown 导出、MCP 单卦资源）、`text/html; charset=utf-8`（界面、插件页面、`ctx.html()`）；插件导出器经 `mime` 自报，缺省 `text/plain; charset=utf-8`。静态扩展名映射：`.html`、`.js`/`.mjs`、`.css`、`.json`、`.svg`、`.png`、`.woff2`、`.md`、`.txt`；未命中回落 `application/octet-stream`。

### 1.3 时间与日期格式
| 字段类别 | 格式 | 示例 |
|---|---|---|
| 钟表时间 `cast.localTime` | `YYYY-MM-DD HH:mm`（严格两位补零） | `2026-09-28 03:38` |
| 卦录 id | `YYYYMMDDHHmm` ＋ `-` ＋ 两位序号 | `202609280338-01` |
| `createdAt`/`updatedAt`/`generatedAt` | ISO 8601 UTC，含毫秒与 `Z` | `2026-10-03T11:31:55.462Z` |
| `review.reviewedAt` | ISO 8601 或 `null` | `2026-12-20` |
| `review.log[].at` | 自由字符串，惯例为日期 | `2026-12-20` |
| `calendar.trueSolarTime` | `HH:mm` | `02:17` |
| `GET /api/health` 的 `at` | ISO 8601 | `2026-10-03T11:31:55.462Z` |

### 1.4 命名法：英文键与中文键的混用规则
这是最易被误读的一处约定，规则是**分层的**：

| 层 | 命名 |
|---|---|
| 持久化层 `data/records/*.json` | 全英文 camelCase，对外契约 |
| REST 请求体与响应体的**记录字段** | 同持久化层；`cast`/`chart`/`reading`/`review` 内部无中文键 |
| REST 的**统计类聚合值** | 英文 camelCase（`byCategory`/`byGrade`/`byRelation`/`byReview`…） |
| Agent 工具的**返回值** | 中英混用，业务实体用中文键（`起卦时间`/`本卦`/`动爻`/`体用`/`总评`/`分数`/`谶`/`复盘`/`校勘数`；`chartBrief` 产出 `卦录`/`起卦推演`/`时间`/`断语`） |
| Agent 工具的**入参名** | 全英文 camelCase，与 REST 请求体同名 |
| MCP 工具入参 / 返回 | 同 Agent 工具（一套实现三处复用） |
| 枚举值 | 中文（`category`、`review.status`、`grade.label`） |
| 插件注册 id | 英文小写连字符（`html-card`、`review-watch`、`stats-plus`） |
记录结构**不得**出现中文键（根级 `additionalProperties: false` 会抓出写错的字段名）；中文键只出现在「给人/给模型读的摘要视图」里。

### 1.5 信封
成功 `{ "ok": true, ... }`；失败 `{ "ok": false, "error": "人话错误信息" }`。`error` 恒为字符串，取自 `Error.message`，非 Error 值走 `String(err)` 兜底；**不存在** `code`、`details`、`errors[]` 这类附加字段。例外两处：静态文件（`/`、`/web/*`、`/plugin-assets/*`）返回裸文本或裸字节；导出类端点返回文件内容本身。

### 1.6 下载头与 RFC 5987
HTTP 头只能是 latin-1，中文文件名必须走 RFC 5987：`Content-Disposition: attachment; filename="<ASCII 兜底名>"; filename*=UTF-8''<百分号编码的中文名>`。实现为 `attachment(filename, asciiFallback = 'wenxingua.txt')`，`filename*` 由 `encodeURIComponent(filename)` 生成。

| 端点 | `filename` | ASCII 兜底 |
|---|---|---|
| `GET /api/records/:id/export?format=md` | `<id>.md` | 同左 |
| `GET /api/records/:id/export?format=json` | `<id>.json` | 同左 |
| `GET /api/records/:id/export?format=slip` | `<id>-卦签.txt` | `<id>-qian.txt` |
| 插件导出器 | `<id>.<ext>` | 同左 |
| `GET /api/export?format=md` | `问心卦-卦录总览.md` | `wenxingua-index.md` |
| `GET /api/export?format=json` | `问心卦-整包备份.json` | `wenxingua-backup.json` |
消费方**应当**优先读 `filename*`，取不到时回落 `filename`。

### 1.7 CORS 与缓存
| 头 | 值 | 范围 |
|---|---|---|
| `Access-Control-Allow-Origin` | `*` | 每一个响应（含静态与错误响应） |
| `Access-Control-Allow-Methods` | `GET,POST,PATCH,DELETE,OPTIONS` | 同上 |
| `Access-Control-Allow-Headers` | `Content-Type` | 同上 |
| `Cache-Control` | `no-cache` | 仅静态文件 |
| `Content-Length` | 实际字节数 | 每一个响应（`send()` 统一设置） |
`OPTIONS` 一律以 `204` 空响应结束，**不进入路由匹配**。API 响应**不得**被缓存——服务自身不发 `Cache-Control`，消费方**应当**按不缓存处理。由于 `Allow-Headers` 只声明 `Content-Type`，跨源调用**不得**附加自定义请求头（如 `Authorization`）；`apiKey` 只存在于服务端本地配置，不经 HTTP 头传递。

### 1.8 请求体
流式累积后 `Buffer.concat` 按 UTF-8 解码；上限 **32 MiB**（`32 * 1024 * 1024` 字节），超限抛 `请求体过大` → `400`；空体返回 `{}`；非 JSON 体返回 `{ "_raw": "<原始文本>" }` 且**不报错**。`POST /api/import/parse`、`/api/guatiao/parse`、`/api/validate` 在无 `text` 时回落 `body._raw`。

### 1.9 路由与静态资源
路径参数写法 `:name`，匹配段 `[^/]+`，值经 `decodeURIComponent`。主处理顺序（**顺序即优先级**）：

1. 设 CORS 头；`OPTIONS` → `204`；
2. `store.maybeRescan()`——`data/records/` 目录 mtime 变了就重扫一次；
3. **插件路由** `/api/plugins/<id>/*`，命中即接管，未显式结束响应时补 `{ok:true}`；
4. **插件静态** `/plugin-assets/<pid>/<rest...>`；
5. **内置 REST 路由**，按注册顺序线性匹配；
6. `/api/` 未命中 → `404 {ok:false,error:"未知接口 <path>"}`；
7. **静态界面** `web/`，未命中回落 `index.html`。

因此**插件路由优先于内置路由**（插件路由按 `path` 长度降序排序，可用更长路径遮蔽同前缀端点）。静态服务只允许落在基目录内，越界返回 `403 forbidden` 裸文本。

### 1.10 变更通知
**不提供** SSE、WebSocket 或长轮询。状态变化只经两条路径：插件事件钩子（进程内，第四节）与桌面版 IPC 事件通道 `qxg:navigate`（第五节）。

## 二、错误码与错误语义
| 码 | 触发条件 | 响应体 | 典型 `error` 文案 |
|---|---|---|---|
| `200` | 成功 | `{ok:true,…}` 或文件内容 | — |
| `204` | `OPTIONS` 预检 | 空 | — |
| `400` | 字段缺失/非法、起卦输入不足、模型未配置好、备份包非法 | `{ok:false,error}` | `起卦需要时间（精确到分钟）。`、`无法识别卦名：<输入>`、`动爻须为 1-6（自下而上第六爻写作 6）。`、`卦录缺少 id`、`AI 助手未配置好：<reason>。到「助手」页填好模型与密钥即可。`、`messages 为空`、`请求体过大` |
| `403` | 静态路径越出基目录 | 裸文本 | `forbidden` |
| `404` | 资源不存在；或 `/api/` 下的未知路径 | `{ok:false,error}` 或裸文本 | `未找到该卦录`、`未找到该卦`、`没有名为 <name> 的 schema`、`未找到该插件页面`、`未找到该插件面板`、`未知接口 <path>`；静态为 `not found` |
| `500` | 未捕获异常 | `{ok:false,error}` | 异常自身的 `message`；完整栈进服务端 `console.error` |
端点级差异：`POST /api/agent/tool/:name` 的工具抛错返回 **`400`＋`{ok:false,error}`**（不是 500）；`POST /api/import/commit` 单条失败**不**影响整批，详情进 `failed[]` 且 HTTP 仍 `200`；`POST /api/validate` 校验不通过**不是** HTTP 错误（`200`＋`{valid:false,errors[]}`）；`GET /api/trend` 参数非法不报错（`mode` 不认识按 `fortune`，`rangeDays` 非数字按 `0`）；`POST /api/shutdown` 先返回 `200` 再 `setTimeout(() => process.exit(0), 200)`；插件路由抛错冒泡到主 `try/catch` → `500`。

| 方法 | 路径 | 说明 | 写盘 | 幂等 |

| GET | `/api/update-check` | 向 GitHub 的「最新发行版」接口问一次版本号；失败静默 | 否 | 是（成功结果缓存 6 小时；`updateCheck:false` 时不出网） |

无参数。**这是本程序唯一的主动外呼**（见 [11-安全与隐私设计.md](11-安全与隐私设计.md) 第 6.3.3 节）：固定域名 `https://api.github.com`、只发一个 GET、不带任何本机数据与密钥、4 秒超时、响应上限 256 KB。

| 字段 | 类型 | 说明 |
|---|---|---|
| `enabled` | boolean | `false` = 设置里关掉了检测（此时 `latest` 为空串，且**不发任何请求**） |
| `current` | string | 本机版本（取自 `package.json`） |
| `latest` | string | 最新发行版 tag 去掉前缀 `v`（如 `1.1.0`）；取不到时为空串 |
| `url` / `name` / `publishedAt` | string | 发行页地址、发行标题、发布时间（仅成功时有） |
| `error` | string | 只在取不到时有：失败原因（断网、被墙、限流）。**失败仍返回 HTTP `200` 与 `ok:true`** |

```json
{
  "ok": true,
  "enabled": true,
  "current": "1.3.0",
  "latest": "1.1.0",
  "url": "https://github.com/123twtd/vibe-wenxingua/releases/tag/v1.1.0",
  "name": "v1.1.0 · 首个公开版",
  "publishedAt": "2026-10-04T17:05:48Z"
}
```
版本比较（谁比谁新）**不在服务端**：服务端只回事实，界面用 `hasNewerVersion(current, latest)` 按数字段比。检测失败**不报错、不重试**——界面上什么都不显示，等同于「没有新版本」。

#### A4 `POST /api/config` — 写顶层配置（白名单）
| 方法 | 路径 | 说明 | 写盘 | 幂等 |
|---|---|---|---|---|
| POST | `/api/config` | 只允许改 `lastSeenVersion` 与 `updateCheck` 两项 | **是**（写 `config.json`） | 是 |

请求体只认这两个键，其余一律忽略；**一个都不认**（如只传 `appName`）→ `400` ＋ `{ok:false,error}`，`config.json` 一字不动。`lastSeenVersion` 会 `trim()`，超过 32 字符 → `400`；`updateCheck` 收布尔（只有显式传 `false` 才关）。

```json
{ "lastSeenVersion": "1.3.0", "updateCheck": true }
```

响应：`{ok:true, config:{lastSeenVersion, updateCheck}}`（只回这两项，不回整份配置）。错误：`400`。

> 为什么要有白名单：`config.json` 里还有数据位置、插件开关、`agent.apiKey` 这类「改了要出事」的项，它们各有各的专用入口（`POST /api/agent/config`、`POST /api/plugins/:id/toggle`）。顶层写入口只开给界面那几个无害的开关，**不得**为了省事改成整份覆盖。

| `xMode` | string | 否 | `index` | `index`/`time`；仅严格等于 `time` 时生效 |

分支二（卦录）：无 `text` 时执行，取 `body.record ?? body` 作为待校验对象——**可以直接把卦录作为整个请求体提交**。
```json

  "valid": false,
  "errors": [
    {
      "path": "(根)",
      "keyword": "additionalProperties",
      "message": "不允许出现未声明的字段「fidelity」（如为新增字段，请先更新 schema）"

      "path": "reading.tone",
      "keyword": "minItems",
      "message": "至少 7 项（实际 6）"
    }

```
校验器为项目自带的零依赖实现（`core/schema.mjs`），支持 `type`、`enum`、`const`、`properties`、`required`、`additionalProperties`、`items`、`minItems`、`maxItems`、`minimum`、`maximum`、`exclusiveMinimum`、`exclusiveMaximum`、`minLength`、`maxLength`、`pattern`、`oneOf`、`anyOf`；**不支持** `$ref`、`allOf`、`not`、`if/then/else`、`dependentSchemas`、`patternProperties`，遇到即报「不支持」而非静默放过。两份 schema 均以 `strict: true`（默认）调用，故未知关键字会被报出。错误：`400`（`readBody` 失败）；校验不通过**不是** HTTP 错误。

#### I7 `POST /api/agent/chat` — 助手对话
| 方法 | 路径 | 说明 | 写盘 | 幂等 |
|---|---|---|---|---|
| POST | `/api/agent/chat` | 返回回复、工具调用轨迹与用量 | 间接（模型可能调入库类工具） | 否 |
| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `messages` | array | **是**（非空） | `[]` | `[{role, content}]`；`role` 只接受 `user` 与 `assistant`，`content` 必须是字符串。界面会带上自己那份历史作**兜底**，但**服务端能用存档就一定用存档**（见下）——兜底只在老会话不可回推时才生效 |
| `sessionId` | string | 否 | `""` | 会话 id。带了它、且该会话存档「可回推」时，历史 = 存档里的模型侧消息（含成对的 `tool_calls` 与工具结果，不截断）+ 本轮这句；存档不可用则退回用 `messages`（只收 `user`／`assistant`，最多 **20 条**） |
| `maxRounds` | number | 否 | 已解析配置的 `maxRounds` 或 `6` | `Number(body.maxRounds) \|\| resolved.maxRounds \|\| 6`，故传 `0` 会回落默认值 |
| `stream` | boolean | 否 | `false` | 为 `true` 时响应变成 **NDJSON 流**（`Content-Type: application/x-ndjson`）：逐行 `{"type":"event","event":{…}}`（与 `events` 数组里同形的原始事件，`round`／`thinking`／`tool`／`confirm`／`assistant`／`error`），跑完最后一行 `{"type":"done", …}`——载荷与非流式响应**完全一致**；中途出错则发一行 `{"type":"error","error":"…"}` 后结束。界面靠它做「边跑边显示」，脚本仍可用非流式 |

> **历史为什么由服务端给**：界面手里只有展示用的 `trace`，里面**没有工具返回**。早先由界面重拼历史，模型下一轮就看不到自己算过的卦、查过的爻辞，只能凭记忆复述——复述错了就变成「编卦象」。存档里的 `messages` 本来就是为这件事存的。历史按**字符预算（60000）＋ 轮数上限（40）**从最新一轮往回装，且**按用户消息整轮切**（避免把 `tool_calls` 与结果切开）；长会话里不会因为「超过 12 轮」而把用户正讨论的那一卦切出去。

```json
{
  "messages": [{ "role": "user", "content": "顺便看看我最近的走势" }],
  "sessionId": "202610050520-01",
  "maxRounds": 6
}
```
```json
{
  "ok": true,
  "reply": "卦象已由引擎算出：山雷颐䷚，动在初九……",
  "events": [
    {
      "type": "tool",
      "name": "cast",
      "args": {
        "localTime": "2026-10-05 05:20",
        "numbers": [
          63
        ],
        "placeName": "上海"
      },
      "phase": "start"
    },
    {
      "type": "tool",
      "name": "cast",
      "args": {
        "localTime": "2026-10-05 05:20",
        "numbers": [
          63
        ],
        "placeName": "上海"

```
事件类型（`agent/loop.mjs`）：`assistant`（附加 `text`、`mode`，可选 `truncated:true` 表示被 `max_tokens` 截断，`partial:true` 表示「边说边做」）；`tool`（附加 `name`、`args`、`phase`（`start`/`done`），`phase=done` 另有 `ok`、`ms`、`result`——**HTTP 层把 `phase=done` 的 `result` 序列化并截断到 4000 字符**）；`error`（附加 `text`，例如工具参数不是合法 JSON）。

> `usage` 里两个 prompt 数不是一回事：`prompt_tokens` 是**本请求内逐轮累加**的和（含每次工具调用后的重新请求，用来算账）；`contextTokens` 是**最后一轮**的 prompt tokens，也就是「这一轮真正发出去的上下文有多大」。助手面板的「上下文占用」chip 取后者，读不到才退回前者。

`mode` 说的是**这一轮有没有调工具**（`native-tools`／`hermes-xml`／`text-fence`／`plain`＝本轮未调工具），不是「工具协议开没开」；实际用的协议看 `protocol`（`openai-native`／`hermes-xml`／`text-fence`／`plain`）。`historySource` 说明这一轮的历史是从哪来：`store`（会话存档，含工具结果，最全）／`trace`（老会话的存档不可回推，由展示用的轨迹重塑出 `tool_calls` 与工具结果）／`client`（只剩界面那份文本，**模型看不到工具返回**）。排障时一眼能看出模型这一轮到底看到了什么——面板脚注会把这三个值写成「历史 存档／由轨迹重塑／仅界面文本」。`usage` 的 `prompt_tokens`／`completion_tokens`／`total_tokens` 为各轮累加值（`contextTokens` 例外，见上）。副作用：触发 `agent.reply`，载荷 `{reply, rounds}`。错误：`400 AI 助手未配置好：<reason>。到「助手」页填好模型与密钥即可。`；`400 messages 为空`。

#### I9 `GET /api/agent/balance` — 厂商余额
| 方法 | 路径 | 说明 | 写盘 | 幂等 |
|---|---|---|---|---|
| GET | `/api/agent/balance` | 服务端代理查厂商余额（当前仅 DeepSeek 有公开接口） | 否 | 是 |

查询参数 `force`（string，可省）：传 `1` 时绕过服务端 60 秒缓存、强制重新查询（供界面「点击 chip 刷新」）。

**只认 `balanceProfile` 里带 `url` 的厂商**；认不出时**一个请求都不发**，直接回兜底。三种响应形状：

| 字段 | 类型 | 出现在 | 说明 |
|---|---|---|---|
| `ok` | boolean | 全部 | 不支持余额时也为 `true`（不是错误，只是没有这个能力）；失败才为 `false` |
| `supported` | boolean | 全部 | `false` = 该厂商不提供余额接口 |
| `hint` | string | 不支持 | 人话说明（「该厂商不提供余额接口，去控制台看」） |
| `console` | string | 不支持 | 该厂商控制台地址，可能为空串 |
| `at` | string | 成功 | 查询时刻 ISO 8601 |
| `isAvailable` | boolean | 成功 | 厂商返回的 `is_available` |
| `currency` | string | 成功 | 币种（如 `CNY`） |
| `total` / `granted` / `toppedUp` | string | 成功 | 余额合计／赠金／充值，**字符串金额**（厂商原样返回） |
| `error` | string | 失败 | 人话原因，**HTTP 仍为 200**（不抛 500） |

```json
{ "ok": true, "supported": true, "at": "2026-10-04T02:11:07.000Z",
  "isAvailable": true, "currency": "CNY", "total": "110.00", "granted": "10.00", "topped_up": "100.00" }
```
```json
{ "ok": true, "supported": false, "hint": "该厂商不提供余额接口，去控制台看", "console": "" }
```

超时 **8 秒**（`BALANCE_TIMEOUT_MS`）；请求前先过 `agent/sources.mjs` 的私网/保留地址守卫。**成功结果服务端缓存 60 秒**（前端连点时不至于把厂商接口打爆），失败不缓存（改完密钥能立刻重试）。**API Key 只进 `Authorization` 请求头，绝不出现在响应或错误文案里，也不离开本机。**

#### J1 `GET /api/records/:id/export` — 单条导出

## 四、插件派生接口

### 4.1 路由注册与匹配
| 项 | 规则 |
|---|---|
| 前缀 | `/api/plugins/<插件 id>/`，由宿主拼接，插件**不得**自行包含 |
| 注册 | `ctx.registerRoute(method, subPath, handler)`；`method` 被 `toUpperCase()`；`subPath` 前导 `/` 被剥掉 |
| 注册名 | 记的是 `${method} ${完整路径}`，见 `GET /api/plugins` 的 `plugins[].routes[]` |
| 排序 | 全部插件路由按 `path.length` **降序**排序后线性匹配 |
| 精确匹配 | `pathname === r.path` → `params = {}` |
| 通配匹配 | `path` 以 `/*` 结尾且 `pathname` 以该前缀开头 → `params = { rest: <剩余路径，含前导 /> }` |
| 优先级 | **高于**内置 REST 路由、高于 `/plugin-assets/`、高于静态界面 |
| 未结束响应 | 处理器返回非 `false` 且响应未结束时，宿主补发 `{"ok":true}` |
| 返回 `false` | 宿主**不**补发任何内容，由插件自行结束响应（仅 `false` 被识别） |
```js
export default {
  id: 'stats-plus', name: '卦气统计', version: '1.0.0',
  activate(ctx) {
    ctx.registerRoute('GET', 'trend', ({ json, store }) => { json({ ok: true, data: analyze(store) }); });
  },
};
```
对应端点：`GET /api/plugins/stats-plus/trend`。内置的 `/api/plugins/:pid/page/:pageId` 与 `/api/plugins/:pid/panel/:panelId` 是**兜底**：只有当没有任何插件路由以更长路径匹配时才会走到。

### 4.2 处理器 `ctx` 的完整成员
| 成员 | 类型 | 说明 |
|---|---|---|
| `req` / `res` | `http.IncomingMessage` / `http.ServerResponse` | 原始请求与响应（CORS 头与 `Content-Length` 由宿主 `send()` 统一处理） |
| `url` | `URL` | 已解析的请求 URL |
| `params` | object | 路径参数；精确匹配为 `{}`，通配匹配为 `{rest}` |
| `store` | `Store` | 宿主存储（`list/get/save/remove/ids/stats/getConfig/setConfig/backup/restore`） |
| `core` | object | 全部内核：`calendar`、`bagua`、`hexagram`、`divination`、`verdict`、`record`、`render`、`importer`、`trend`、`schema`、`guaTiao`、`migrate` |
| `plugins` | `PluginHost` | 插件宿主自身 |
| `json(data, code = 200)` | function | `JSON.stringify(data, null, 2)` ＋ `application/json; charset=utf-8` |
| `send(body, code = 200, headers = {})` | function | 裸发送；`body` 可为 Buffer 或任意可 `String()` 值，UTF-8 编码 |
| `html(body, code = 200)` | function | `send` ＋ `text/html; charset=utf-8` |
| `text(body, code = 200)` | function | `send` ＋ `text/plain; charset=utf-8` |
| `readBody(limit)` | function | 读请求体；非 JSON 时返回 `{_raw}`；`limit` 省略为 32 MiB |
| `query(k)` | function | `url.searchParams.get(k)`，缺失返回 `null` |
**注意**：`ctx.config` 与 `ctx.log`/`ctx.warn`/`ctx.assetsDir` 存在于 `activate()` 的上下文里，但**不在**路由处理器的 `ctx` 上；处理器内取配置请用 `store.getConfig()`。

### 4.3 页面、面板与导出器
| 注册方法 | 产出 | HTTP 端点 |
|---|---|---|
| `ctx.registerPage({id,label,icon='◇',order=100,render})` | 侧栏页面 | `GET /api/plugins/<id>/page/<pageId>` |
| `ctx.registerPanel({id,label,order=100,render})` | 卦录详情页的一块 | `GET /api/plugins/<id>/panel/<panelId>?recordId=…`；同时出现在 `GET /api/records/:id` 的 `panels[]` |
| `ctx.registerExporter({id,label,ext,mime,render})` | 新导出格式 | `GET /api/records/<id>/export?format=<id>` |
页面 `render` 可返回字符串（直接输出 HTML）或对象（包进 `{ok,page}` 信封）；面板返回对象、导出器返回字符串或 Buffer。`mime` 缺省 `text/plain; charset=utf-8`。插件静态资源放在 `data/plugins/<插件 id>/` 下，经 `/plugin-assets/<插件 id>/<相对路径>` 访问；`activate()` 的 `ctx.assetsDir` 即该目录绝对路径。

`qxg:info` 字段细节：`version`（`electronApp.getVersion()`，即打包版本）、`electron`/`chrome`/`node`（运行时版本号）、`platform`（`process.platform`，如 `win32`）、`dataDir`（当前生效的数据目录）、`dataMode`（`chosen` 用户选过 / `dev` 开发态项目目录 / `appdata` 安装态用户目录）、`packaged`（`electronApp.isPackaged`）、`url`（最近一次监听的地址）、`userDataDir`（Electron `userData` 目录）。

`qxg:export-backup` 默认文件名为 `问心卦-备份-<YYYY-MM-DD>.json`。`qxg:choose-data-dir` 只切换目录，**原目录数据不会自动搬移**；选「立即重启」时执行 `electronApp.relaunch()` ＋ `electronApp.exit(0)`。

时序约束：**全部 `ipcMain.handle` 必须在 `mainWindow.loadURL()` 之前注册**。页面加载完即可能调用，注册过晚会得到 `No handler registered for 'qxg:info'`。此外 `qxg:export-backup` 内部 `fetch` 当前监听地址，故必须**在服务 `listen()` 成功之后**调用。

## 六、MCP 接口

### 6.1 协议与传输
| 项 | 值 |
|---|---|
| 协议 / 传输 | JSON-RPC 2.0；stdio，**换行分隔**（`readline`，`crlfDelay: Infinity`） |
| 协议版本 | `2024-11-05`（`initialize` 与 `GET /api/agent/mcp` 中均为该值） |
| 服务标识 | `{name:'wenxingua', title:'问心卦 · 卦录台', version:<package.json 版本>}` |
| 能力声明 | `{tools:{listChanged:false}, resources:{listChanged:false}}` |
| 启动 | `node agent/mcp-server.mjs`（或 `npm run mcp`） |
| 日志约束 | **stdout 只允许 JSON-RPC 消息**；日志、就绪提示、错误一律走 stderr |
| 数据目录 | 固定 `path.join(ROOT,'data')`——**不读 `QXG_DATA_DIR`**，与 HTTP 服务可能指向不同目录 |
| 批量请求 | 请求体为数组时并发处理（`Promise.all`），逐条写出响应（通知不产出响应） |
| 通知 | `id` 为 `undefined` 或 `null` 视为通知：执行副作用但不返回内容 |
**方法 9 个**：`initialize`、`ping`、`tools/list`、`tools/call`、`resources/list`、`resources/read`、`prompts/list`、`prompts/get`，以及被显式吞掉通知的 `notifications/initialized`（别名 `initialized`）。

| `chart` | `method`、`inputs`、`calendar`、`casting`、`lines`、`ben`、`hu`、`bian`、`moving`、`tiyong`、`score`、`generatedAt` |

| `chart.moving` | `position`、`isYang`、`yaoTitle`、`yaoText`、`positionSymbol`、`positionName`、`inUpper` |
| `chart.tiyong` | `ti`、`yong`、`relation`、`huTri`、`huRelation`、`bianTri`、`bianRelation`、`wang`、`tiRange`、`yongRange` |
