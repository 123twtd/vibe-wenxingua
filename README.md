# 問心卦 · 梅花易数卦录台

> 一卦一录，久而成史。
> 起卦、断卦、存卦、复盘、看势，都在本机，数据是你自己的纯文本。

---

## 一、这是什么

「问心卦」是一个**跑在你自己电脑上的卦录软件**，有**桌面版**（Electron，双击即开）与命令行版两种形态。不需要联网（两条例外都可以不由程序发起：你自己开的 AI 助手，以及启动时看一眼 GitHub 有没有新版本——后者在设置里一键关掉，关掉后程序完全不出网），不需要账号，零第三方依赖（内核只用 Node 内置模块）。

它做七件事：

| | |
|---|---|
| **起卦** | 报数、择时、定地，按梅花易数正法起卦，即时给出卦象与断语；另收录**道教传统小六壬**（三宫之课，末宫为主断） |
| **导入** | 三种入口同一套解析器：粘贴对话文本、写「卦条」纯文本、命令行导入；自动认出卦、爻、时、数、体用，复核后入库 |
| **存录** | 一条卦录一个 JSON 文件，含全部时间与历法信息、卦象、断语、原文、复盘；有正式的 JSON Schema 与版本迁移 |
| **断语** | 体用生克定骨、月令旺衰定气、本互变三卦之卦德定肉、动爻之辞定应——**文言定调 + 白话解释**两层 |
| **复盘** | 独立一页（`#/review`）：待办清单 + 条目流——先挑未了结的，再一条条写下后来怎样了；条目可改可删，默认只读防手滑 |
| **走势** | 把卦录按时间铺开，**多个领域叠在同一张图里**：总评分、体用生克、变卦对体、体卦旺衰、体卦刚柔；另有五行占比、分类别均值 |
| **AI 助手** | 一个能真正动手的 agent：自己调工具起卦、存档、写复盘、看走势。**卦象一律由引擎算出，模型不许编**；同一套工具也走 **MCP**，Codex / Claude / DSH 可直接驱动 |

外加：**校勘**（照出当初口头解读里与本程序重算不符的地方）、**复盘**（记录后来实际如何）、**插件系统**（改完不用重启）、**Hermes 信使层**（统一接多家模型，协议不一致与网络抖动在这一层收敛）、**版本更替看得见**（打开新版本时弹一次「这一版更新了什么」，看过即记下；启动时顺带问一次 GitHub 有没有新发行版，有就在顶部挂一条提示）。

> 需要给编码 agent 的项目说明（改代码前先读）：[AGENTS.md](AGENTS.md)。
> 数据格式的规范文本：[docs/规范.md](docs/规范.md)。
> 全套工程文档（SDD / 架构框图 / 接口 / ICD / Agent / Hermes / 前端规范 / ADR…）：[docs/00-文档索引.md](docs/00-文档索引.md)。
>
> **怎么用这个界面**：侧栏常驻六项、永不出现滚动条，底部另有一组「插件」（插件管理 + 各插件页面，插件多了只在这一组内滚动）；其余入口（文档、卦典、设置、各种一次性操作）全在 **`Ctrl`/`⌘` + `K` 的命令面板**里，也可以直接按 `/` 打开，或点侧栏底部的「更多」。每页自己的筛选与操作在**页内工具栏**，全局散信息在**底部状态栏**一行。`Alt`+`1`…`6` 可直跳侧栏第 N 项。

## 二、快速开始

### 需要什么

**桌面版什么都不用装**——Electron 自带 Chromium 与 Node 运行时。
只有走「命令行版」时才需要 Node.js 18+（[nodejs.org](https://nodejs.org)）。

### 桌面版是什么形态

独立窗口、独立任务栏图标、托盘、中文菜单、开始菜单与桌面快捷方式，**不需要浏览器，也不需要你机器上装 Node**。服务跑在应用自己的主进程里，所以既不会闪出黑色控制台，也不会另起一个 `node.exe`。（「开浏览器访问 localhost」的形态仍然保留，作为开发与调试入口，见下面「方式三」。）

### 方式一（推荐）：桌面版

仓库里**不含安装包**（二进制不进 git，走 Releases）。两条路：

- **直接下载**：[Releases · v1.5.0](https://github.com/123twtd/vibe-wenxingua/releases/latest) → `wenxingua-1.5.0-setup.exe`（约 78 MB，中文向导，双击安装）
- **自己打**，约两分钟：

```
cd desktop
npm install
npm run dist           # 产物：desktop\dist\问心卦-安装包-<版本>.exe
```

装好后：安装器是中文的、可以改安装目录、会建**桌面与开始菜单快捷方式**，卸载时**不会删你的卦录**（数据在 `%APPDATA%\问心卦\data`，与程序分开）。

**免安装版**（不想装就直接跑）：

```
desktop\dist\win-unpacked\问心卦.exe
```

整个 `win-unpacked` 文件夹拷到哪都能跑，适合放 U 盘。

**从源码跑桌面版**（改代码时用这个，改完刷新即可）：

```bash
cd desktop
npm install          # 首次；国内走镜像见下
npm start            # 或 npm run dev（带开发者工具）
```

> Electron 的二进制在 GitHub 上，国内可能连不上。走镜像：
> ```bat
> set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
> set ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
> npm install
> ```
> 若 `npm install` 报了 `connect ETIMEDOUT` 但 `node_modules\electron\dist` 里只有一个
> `LICENSES.chromium.html`，说明 zip 下好了却没解压——从
> `%LOCALAPPDATA%\electron\Cache\<hash>\electron-v33.x.x-win32-x64.zip` 手动解压到
> `node_modules\electron\dist` 即可。

**自己打包**：

```bash
cd desktop
npm run dist        # 出 NSIS 安装包到 desktop\dist\
npm run dist:dir    # 只出免安装目录
```

### 方式二：桌面窗口（零安装兜底）

不想装 Node、也不想用 Electron 时，双击 **`问心卦(桌面窗口).vbs`**：

**「数据 → 更换数据目录…」** 可以改到别处（比如放到 OneDrive 或 git 仓库里）。

## 三、日常怎么用

### 3.1 起卦（「起卦台」）

1. 选**起卦之法**：
   - **一数 + 时辰**（最常用）：上卦取数除八之余，下卦取时辰数除八之余，动爻取二者之和除六之余。
   - **两数**：先报数为上卦，后报数为下卦，两数之和除六取动爻。
   - **年月日时**：不报数，以年支数＋月＋日为上卦，再加时辰为下卦，总和除六取动爻。
   - **已知卦象**：直接指定本卦与动爻——用于录入别人替你起的卦。
2. 填**报数**、**起卦时间**（钟表时间）、**地点**（或自定义经度）。
3. 选**定时辰之法**——这一项很重要：
   - **真太阳时**（推荐）：真太阳时 = 钟表时间 + 经度时差 + 均时差。兰州与北京时间差约一小时，时辰常因此改换（例：钟表 03:38 在兰州是丑时，取数 2，而非寅时的 3）。
   - **钟表时间**：直接按钟表时刻定时辰。
4. 填**所问之事**（一事一占，单一、具体、可验证）与**类别**。
5. 右侧**即时**出现卦象、六爻、体用、断语。满意就点「录下此卦」。

> 起卦要诀：一事一占。问得越单一，卦象越不散。
> 忌：「我能上岸，同时找到好工作，还能攒十万吗？」——三个目标，卦会散。

### 3.2 导入旧卦（「导入」）

把整段起卦文本粘进文本框，点「解析」。解析器会：

- 认出**本卦／互卦／变卦／动爻／体用**；
- 认出**起卦时间、地点、经度、报数**；
- 顺手把**所问之事**从上下文里提出来；
- 把**原文整段**保留下来，存进卦录的「原文存录」。

然后逐条复核（所有字段都可改），点「入库」。解析原则是**宁可少认，不可错认**：认不准的会标红并列出「缺什么」，而不会猜。

也支持：

- 按「读取文本文件」导入 `.md` / `.txt`；
- 按「恢复 JSON 备份」导入整包数据。

### 3.3 「卦条」——以后新导入就照这个写

粘贴对话文本方便，但不稳定（各家的格式不一样）。所以另立了一种**保证稳定的导入契约**：**卦条 v1**。一行一个字段的纯文本，人三十秒能写完，脚本能生成，AI 能照着写。

```
# 卦条 v1
题: 换城之占
问: 换一座城市重新开始，可行吗？
类: 决策取舍
时: 2026-10-05 05:20
地: 上海
经: 121.47
真太阳时: 是
法: 一数一时辰
数: 63
动: 4
原文: |
  （可省。把当初的解读原文粘在这里，多行不限。）
```

- 以 `#` 开头的整行是**注释**，随便写，删掉也行。
- 键名可用中文全称或简写：`时`／`时间`／`localtime` 是同一个字段。完整字典见「导入与格式」页或 [docs/规范.md](docs/规范.md)。
- **多条卦条用单独一行 `---` 分隔**，一次可以贴几十条。
- **必填只有「时」**。`法` 为「已知卦象」时再填「本卦」与「动」；其余起卦法要填「数」与「动」。
- **缺什么就报什么**：解析器宁可返回「缺：起卦时间」，也不会替你猜一个年份。认不出的键名（写错字）会单独列出。

三个入口共用同一套解析器，所以行为一致：

```bash
node tools/import.mjs --template > 我的卦条.txt   # 生成模板照着填
node tools/import.mjs 我的卦条.txt --dry          # 先看认得对不对，不落盘
node tools/import.mjs 我的卦条.txt                # 真入库
node tools/validate.mjs 我的卦条.txt              # 只校验不导入
```

网页上在「导入与格式」页可以**在线校验**（粘贴框本身就是校验），也能直接入库。

> **一个小聪明**：别人给你的卦往往只写「报数 9、辰时、动爻第 3 爻」而不说用哪一路取法。程序会拿这两个结果去比对——`9 % 6 = 3` 是「仅以报数除六」，`(9+5) % 6 = 2` 是常法——所述动爻对得上哪一路，就按哪一路还原，**忠实复现原卦而不是误记成校勘**。

### 3.4 走势（多领域多线叠加）

「走势」页把卦录按时间铺开，**多个领域叠在同一张图里**。这是回答「我最近这一段运气走势如何」的地方。

三种模式：

| 模式 | 画什么 |
|---|---|
| **吉凶诸线** | 总评分、体用生克、变卦对体、体卦旺衰、吉凶等级、体卦刚柔——六条线叠在一张图上 |
| **五行占比** | 木火土金水各一条线，体卦五行在滚动窗口内的占比（看此消彼长） |
| **分类别均值** | 每个类别一条累计均值线，另加一条全体基准线（虚线） |

可调的：**叠加哪些领域**（自由勾选）、**时间范围**（全部／一年／90 天／30 天／7 天）、**平滑窗口**（1／3／5／10 卦移动平均，原始序列以淡线一并画出）、**横轴**（按卦序，或按时间比例）。图例可点选隐藏某条线；鼠标悬停出十字准星与多值提示；**点图上任一处跳回那一卦**。

设计上的两条讲究：

- 除五行占比（0~100%）外，各线都**归一到同一量程 −100 ~ +100**，所以能真的叠着看：**同向＝彼此印证，背离＝卦气与结论有张力**。量程不同的线绝不硬画在一根轴上。
- 时间跨度不足一日时，时间轴会**退化为等距并在页面上说明**，不假装是真时间轴。

### 3.5 卦录与复盘

- 「卦录」可按关键词、类别、吉凶、复盘状态筛选。
- 点开任一条，看到：**卦象**（三卦 + 六爻图 + 体用生克条）、**卦象定调**（谶／主／互／变／断／宜／忌／应期）、**通俗解**、**古辞佐证**、**吉凶权衡**（各项权重与得分）、**校勘**、**起卦推演**、**时间与历法**、**原文存录**、**补充存录**（背景／方案／人工校勘／原文问答）。**复盘不在这一页**——它有自己的页，详情页页头只留一个「复 盘 · 状态」按钮。
- **复盘**（`#/review`）是这套东西最值钱的部分：左边挑一条（默认只列「未了结」的），右边写下后来发生了什么、卦在何处应了、何处没应。复盘是一串**条目**：最早那条通常就是首回复盘，之后每条都是追记；条目可以改、可以删——但要先点「开启操作」（默认只读，防手滑）。插件「应期提醒」会按动爻之位推算应期窗口，把「时间该到了、还没复盘」的卦挑出来。
- 可导出：单条 Markdown ／ 卦签（纯文本，便于打印或抄写）／ 单条 JSON ／ 离线 HTML 卡片（插件提供）；全录 Markdown ／ 整包 JSON 备份。

### 3.6 AI 助手

「AI 助手」页是一个**能真正动手**的 agent。它不是在聊天框里凭记忆讲卦，而是通过工具去操作这个程序：

| 工具 | 干什么 |
|---|---|
| `cast` | 起一卦看结果（不入库） |
| `save_record` / `save_gua_tiao` | 起卦并入库／用卦条文本批量入库 |
| `list_records` / `get_record` / `update_record` | 查与改旧卦 |
| `update_review` | 写复盘：改状态，或追加一条复盘／追记（最早那条通常就是首回复盘） |
| `trend` / `stats` | 看走势与总览 |
| `hexagram_lookup` | 查卦典（卦名、卦序、卦符、卦辞、爻辞、卦德都能搜） |
| `parse_import` / `format_spec` | 解析任意起卦文本／读格式规范 |

**一条硬规矩写在 system prompt 里：卦象一律由工具算出，模型不得自行编造。** 这是这套东西能不能长期用的分水岭——模型会记错卦，引擎不会。

配置（「AI 助手」页填，存在本机 `data/config.json`）：

| 服务商 | 说明 |
|---|---|
| **DeepSeek** | 与 OpenAI 兼容，`deepseek-chat` 支持 function calling |
| **OpenAI** | 同上 |
| **本地 Ollama** | 完全离线，无需 Key（`qwen2.5:7b` 之类） |
| **自定义** | 任何 OpenAI 兼容端点（vLLM、LM Studio、自建网关） |

页面上有「测连通」与「拉模型列表」。多数本地小模型不支持 function calling，此时把「工具调用方式」切成**文本协议降级**——模型输出 ```json {"tool":"cast","args":{...}} ```，程序自己解析，7B 的模型也能把活干完。

> API Key 以明文存在 `data/config.json`。这是本地程序，但**别把 `data/` 提交到公开仓库，也别放同步盘**。

### 3.7 用 MCP 把问心卦接给别的 agent

同一个工具集也走 **MCP**（JSON-RPC 2.0 over stdio），Codex CLI / Claude Code / DSH 可以直接驱动：

```bash
node agent/mcp-server.mjs      # 或者 npm run mcp
```

Codex：

```toml
# ~/.codex/config.toml
[mcp_servers.wenxingua]
command = "node"
args = ["<项目绝对路径>/agent/mcp-server.mjs"]
```

Claude Code / DSH（`.mcp.json`）：

```json
{ "mcpServers": { "wenxingua": { "command": "node",
  "args": ["<项目绝对路径>/agent/mcp-server.mjs"] } } }
```

「AI 助手」页底部有可直接复制的现成片段。MCP 服务暴露 21 个工具、3 个资源（全部卦录／卦条规范／统计）与 2 个提示模板（`divine`、`review_due`）。

### 3.8 导入与格式页

规范与录入在同一页——粘的东西就按这份规范认，认完就入库，中间不必再跳一次。页内依次是：粘贴框与解析结果（**粘贴框本身就是在线校验**：粘进去就知道能不能入库）、卦条模板（可一键复制／载入粘贴框／下载）、25 组字段别名的完整字典与必填规则、卦录 JSON 的版本与迁移说明、以及命令行与 Agent 的用法。

> 旧地址 `#/spec` 仍然可用，会转发到这一页（桌面菜单、书签与旧文档里可能还指着它）。

### 3.9 卦典

## 四、断语是怎么来的

### 4.1 两层结构

**第一层「卦象定调」**——立卦之骨，用文言之气：

| | |
|---|---|
| **谶** | 总纲四句，一卦气质最重处。如：「火烁其金，权归我掌。速断则利，久缠则伤。」 |
| **主** | 体用生克为骨 → 月令旺衰为气 → 本卦卦德为肉 → 动爻爻辞为应 |
| **互** | 互卦 = 事情**中段**的光景：意象 + 五行机理 |
| **变** | 变卦 = **归宿**：意象 + 五行机理 + 变卦卦辞 |
| **断** | 总断：吉凶等级 + 三卦合观的一句话 |
| **宜／忌** | 由体用关系 + 变卦结局 + 占问类别三者合成 |
| **应期** | 由动爻之位定常期，再由体卦旺衰提前或推迟 |

**第二层「通俗解」**——说人话，落到地上：一句话结论、要旨、为什么这样说、怎么做。

### 4.2 体用生克

**正法**：动爻所在的卦为**用**，另一卦为**体**。体为我，用为事。

| 关系 | 骨 | 气 |
|---|---|---|
| 用生体 | 来者资我，不求而自至 | 吉 |
| 体用比和 | 同气相求，谋之必谐 | 吉 |
| 体克用 | 权操于我，然克者耗也，宜速不宜久 | 可成而耗 |
| 体生用 | 我往资彼，费而不获 | 小耗 |
| 用克体 | 势在人不在己，强争则伤 | 凶 |

### 4.3 吉凶权衡

八项各自归一到 −100 ~ +100，再按权重加权平均，得分落在 −100 ~ +100：

| 项 | 权重 |
|---|---|
| 体用生克（本卦） | 3.0 |
| 变卦对体（结局） | 2.2 |
| 互卦对体（中途） | 1.0 |
| 体卦旺衰 | 1.4 |
| 用卦旺衰 | 0.6 |
| 本卦卦德 | 3.2 |
| 变卦卦德 | 2.2 |
| 动爻得位 | 1.0 |

等级：**大吉** ≥55　**吉** 25~54　**中吉** 0~24　**平** −8~−1　**小凶** −40~−9　**凶** <−40。

权重经过校准：让「体克用而结局受制、卦德又不吉」（如雷泽归妹）落于**小凶**，而「势在我、结局来济、卦德亦吉」落于**中吉**至**吉**。界面里每一项的权重、归一值与说明都摊开显示，不服可以改 `core/divination.mjs` 的 `scoreChart`。

### 4.4 断语为什么稳定

同一卦局重算，其文必同——变体按「卦局指纹」（本卦／互卦／变卦／动爻／体用／所问）取散列选定，不是随机。所以年初看到的断语，年底再看还是那几句。

## 五、校勘：一个附带的用处

导入旧卦时，本程序会把它自己**按正法重算**的结果与「当初所述的卦」逐项对照，不同处列进「校勘」。已有六条历史卦录里，就照出了两处：

- **天泽履**（考研主线之占）：当初写「体卦兑金，用卦乾金」，按正法则「动爻在下卦，故下卦兑为用、上卦乾为体」，应为**体乾、用兑**。（两卦同属金，体用比和的结论不受影响。）
- **雷泽归妹**（完全不投递之占）：当初写互卦为「山火贲」，按正法互卦取「二三四爻为下、三四五爻为上」，应为**水火既济**。

另外还存录了两类**取法存异**（不是错，是当初用了另一路取法）：

- 首占「泽火革」的动爻，当初以 `82 ÷ 6` 单独取（得第四爻「改命吉」）；梅花易数常法为「数与时之和除六」（得初爻）。本卦录按原卦保留第四爻，并注明若改常法重算会得到什么。
- 两个「对照卦」（泽雷随／泽风大过）当初用的是**下卦取「数与时之和除八」**的另一路取法，与「一数＋时辰」的默认取法不同。本卦录用「已知卦象」模式忠实保留原卦。

> 这些都属于**存录**，不是删改。原有解读的原文完整保留在「原文存录」里。

```jsonc
{

  "category": "考研学业",

    "method": "numberAndTime",
    "numbers": [1],
    "localTime": "2026-09-28 03:38",
    "useTrueSolarTime": true,
    "placeName": "兰州", "longitude": 103.83
  },

  "reading": { /* 断语快照：signature + tone[7] + classical + plain + grade */ },
  "claimed": { "ben": "天泽履", "hu": "风火家人", "bian": "乾为天",
               "moving": 3, "tiyong": "体卦兑金，用卦乾金，体用比和" },
  "corrections": [ /* 校勘 */ ],
  "review": { "status": "待应验", "result": "", "log": [] },
  "narrative": "……当初的完整原文……",
  "background": "……求测人背景：身份、处境、动机……",
  "plan": "……断语是通则，这里存落到这个人、这件事上的具体做法……",
```

## 七、扩展：写一个插件

可扩展性在这里落地。**一个插件就是一个 `.mjs` 文件**，放在 `data/plugins/` 下，导出一个带 `activate(ctx)` 的对象：

```js
// data/plugins/my-plugin.mjs
export default {
  id: 'my-plugin',
  name: '我的插件',
  version: '1.0.0',
  description: '一句话说明',

  activate(ctx) {
    // 1) 加接口：GET /api/plugins/my-plugin/hello
    ctx.registerRoute('GET', 'hello', ({ json, store }) =>
      json({ ok: true, count: store.list().length }));

    // 2) 加一个侧栏页面
    ctx.registerPage({
      id: 'main', label: '我的面板', icon: '◆', order: 50,
      render: ({ store, core }) => ({ html: '<p>共 ' + store.list().length + ' 条卦录</p>' }),
    });

    // 3) 在每条卦录详情页加一块
    ctx.registerPanel({
      id: 'note', label: '我的批注', order: 10,
      render: ({ record }) => ({ html: '<p>本卦 ' + record.chart.ben.fullName + '</p>' }),
    });

    // 4) 加一种导出格式：/api/records/<id>/export?format=my-fmt
    ctx.registerExporter({
      id: 'my-fmt', label: '我的格式', ext: 'txt',
      render: (rec, { core }) => core.render.toSlip(rec),
    });

    // 5) 监听事件
    ctx.on('record.created', (rec) => ctx.log('新卦录', rec.id));
  },
};
```

`ctx` 上有：

| | |
|---|---|
| `registerRoute(method, path, handler)` | 加 REST 接口，挂在 `/api/plugins/<id>/` 下 |
| `registerPage({id,label,icon,order,render})` | 加侧栏页面 |
| `registerPanel({id,label,order,render})` | 在卦录详情页加面板 |
| `registerExporter({id,label,ext,mime,render})` | 加导出格式 |
| `on(event, handler)` | 事件：`app.start`、`record.created`、`record.updated`、`record.deleted`、`cast.preview` |
| `store` | 全部卦录与配置（`store.list() / get(id) / save() / stats() / getConfig() / setConfig()`） |
| `core` | 全部内核（`core.divination`、`core.verdict`、`core.hexagram`、`core.calendar`、`core.render`、`core.importer`、`core.guaTiao`、`core.trend`、`core.schema`、`core.migrate`、`core.record`） |
| `config` / `log` / `warn` / `assetsDir` | 配置、日志、静态资源目录（HTTP 路径 `/plugin-assets/<id>/…`） |

路由 `handler` / 页面 `render` 拿到的 `ctx` 里有已绑定 `res` 的 `json(data)`、`send(body, code)`、`html(body)`、`text(body)`、`readBody()`、`query(k)`。

改完插件**不用重启**：到「插件」页点「热载全部插件」，或 POST `/api/plugins/reload`。

已内置三个可用样例：

- **应期提醒**（`review-watch.mjs`）：按动爻之位推算应期窗口，把该复盘还没复盘的卦挑出来；并在每条卦录详情页加一块应期进度。
- **卦气统计**（`stats-plus.mjs`）：体卦五行分布、五行 × 吉凶交叉表、按时间排列的卦气走势；并自注册接口 `GET /api/plugins/stats-plus/trend`。
- **单卦 HTML 卡片**（`html-card.mjs`）：给卦录加一种**离线单文件 HTML 导出**（`?format=html-card`）——自带样式、不依赖本程序也不依赖网络（字体走系统字体栈），可以直接发给别人，也可以存十年。

## 九、已知限制与往后可加的东西

**限制**

- 历法是**低精度天文近似**（太阳视黄经误差约 0.01°，折合时刻误差 ≲ 15 分钟）。定节气、月建、时辰足够；**不当历书用**。真太阳时的差异在历史卦录里已核实过（本程序取均时差 +9.21 分，比常见的 +10.4 分更接近实际，但时辰结论不变）。
- 断语是**规则引擎**，不是语言模型。它的强项是稳定、可复现、可追溯（每一项得分都摊开）；弱项是文采的上限固定。想让它更活，扩 `verdict.mjs` 的词库即可。
- 卦典的释义字段（`coreMeaning`／`keywords`／`advice`／`fortune`）是**编写的释义**，不是古籍原文；卦辞、大象辞、爻辞是原文。个别异文（如既济卦辞的断句「亨小，利贞」／「亨，小利贞」）已在知识库里注明。
- **走势图在数据少的时候不好看**：横轴会挤在一起，几条线互相穿插。它是**按数据量设计的**，等积累到几十卦、跨几个月，趋势才显出来。
- AI 助手需要你自己提供模型 Key 或本地模型。程序本身不带模型，**没有 Key 时助手页只显示配置表单**，其余功能全部可用。
- 断语的口径是从「体用生克 + 月令旺衰 + 卦德 + 动爻」四样里拼出来的。**这个口径合不合你的意，只有你能判断**——不合就改 `core/verdict.mjs` 顶部的词库，然后对旧卦点「重算断语」。

**还没做的**

| 想法 | 现状 |
|---|---|
| 卦录的日历热力图 | 没有。走势图是时间线，不是日历 |
| 全文检索高亮 | 有关键词筛选，但不标黄 |
| 打印版式（A4／PDF） | 只有卦签纯文本导出（可打印）与离线 HTML 卡片 |
| 移动端 | 接口齐了，但没做手机端 |
| 六爻／纳甲／奇门 | 没有。插件接口留好了，可自己加 |
| 多用户／云端同步 | 刻意不做。这是单机软件，数据只在你本机 |
| 爻辞异文校勘 | 知识库里注明了已知异文，但没有做多底本对照 |
| AI 流式输出 | 已有过程级流式：思考、工具、回答逐条出现；但模型单轮的输出仍是整段返回，所以一轮要等几秒 |

**往后可加**

- 六爻／纳甲／奇门等其他起卦体系的插件
- 卦录的日历热力图、标签体系、全文检索高亮
- 打印版式（卦签已可导出，可再加 A4 排版的 PDF）
- AI 逐字流式输出（现在按轮推送）与多轮上下文压缩
- 移动端：接口已经齐了，写个手机端直连本机即可
