本表给每个词**一个**定义，并指明它在项目里对应哪个字段或文件。读文档、读代码、写卦条、让 AI 替你录卦，遇到不确定的词都以此为准。**易学术语的定义采用本项目的口径**（即梅花易数正法在本程序里的实现方式），不展开各家异说。

## 一、领域术语（易学侧）

### 1.1 卦象结构

| 术语 | 定义 | 在本项目里的位置 |
|---|---|---|
| **八卦** | 乾☰、兑☱、离☲、震☳、巽☴、坎☵、艮☶、坤☷，各有五行属性、阴阳与方位。 | `core/bagua.mjs` 的 `TRIGRAMS`；卦录里出现在 `chart.ben.upper`／`chart.ben.lower` |
| **六爻** | 由下卦三爻＋上卦三爻组成的六个阴阳位，自下而上记。数组里的 `1` 表示阳爻、`0` 表示阴爻。 | `core/hexagram.mjs` 的 `sixLines()`；`chart.lines`（长度必须为 6） |
| **本卦** | 所起之卦，代表事情的当下格局。「体用生克」在本卦上定。 | `chart.ben`（`id`／`name`／`fullName`／`symbol`／`upper`／`lower`／`guaci`／`xiang`／`coreMeaning`／`fortune`）；卦条键名「本卦」 |
| **互卦** | 由本卦中间四爻重组成的卦，看事情的**中段**。取法固定为「二三四爻为下卦、三四五爻为上卦」。 | `core/hexagram.mjs` 的 `mutualLines()`；`chart.hu`；卦条键名「互卦」 |
| **变卦** | 动爻阴阳反转后得到的卦，代表事情的**归宿**。 | `core/hexagram.mjs` 的 `changedLines()`；`chart.bian`；卦条键名「变卦」 |
| **动爻** | 发生变动的那一爻，自下而上第 1–6 位。它是定体用、定变卦、定应期的关键。 | `chart.moving`（`position`／`isYang`／`yaoTitle`／`yaoText`／`positionSymbol`／`inUpper`）；卦条键名「动」／「动爻」 |
| **用九／用六** | 乾卦六爻皆阳时的「用九」、坤卦六爻皆阴时的「用六」，是乾坤两卦独有的断辞。 | `knowledge/yaoci.json` 的 `yong`（键 `1`、`2`） |
| **卦符** | 六十四卦的 Unicode 符号，如 `䷀`（乾为天）、`䷮`（泽水困）。 | `chart.*.symbol`，数据源 `knowledge/64gua.json` 的 `symbol` |
| **卦序** | 周易通行本的卦次（1–64），本项目按通行本。 | `chart.*.id`，数据源 `knowledge/64gua.json` 的 `id` |
| **卦宫** | 京房八宫归属（如泽水困属兑宫），用于检索与归类。 | `knowledge/64gua.json` 的 `palace`，随卦典展示（卦典页） |
| **上下卦（内外卦）** | 一个六爻卦由上下两个三爻卦组成；上卦又称外卦，下卦又称内卦。 | `chart.ben.upper`／`chart.ben.lower`；`knowledge/64gua.json` 的 `upper`／`lower` |
| **三卦合观** | 把本卦（当下）、互卦（中段）、变卦（归宿）合起来读，是本断语「断」段的骨架。 | `core/verdict.mjs` 的 `totalJudgement()`；`reading.tone` 的 `duan` 段 |

### 1.2 体用与旺衰

| 术语 | 定义 | 在本项目里的位置 |
|---|---|---|
| **体卦** | 不动的那一卦，代表**我**。定法：动爻在下卦则上卦为体，动爻在上卦则下卦为体。 | `core/hexagram.mjs` 的 `tiYongOfLines()`；`chart.tiyong.ti`（`name`／`element`／`nature`／`position`／`direction`） |
| **用卦** | 动爻所在的那一卦，代表**事**。 | `chart.tiyong.yong`；同上 |
| **体用生克** | 体与用两个卦的五行关系，是断卦之骨。五类：用生体、体用比和、体克用、体生用、用克体。 | `core/bagua.mjs` 的 `wuxingRelation()`；`chart.tiyong.relation`（`key`／`label`／`detail`／`grade`）；键名 `yong_sheng_ti`／`bihe`／`ti_ke_yong`／`ti_sheng_yong`／`yong_ke_ti` |
| **变卦对体** | 变卦中与「用位」同侧的那一卦对体卦的生克，看事情的结局。 | `chart.tiyong.bianRelation` 与 `chart.tiyong.bianTri` |
| **互卦对体** | 互卦中与「用位」同侧的那一卦对体卦的生克，看事情的半途。 | `chart.tiyong.huRelation` 与 `chart.tiyong.huTri` |
| **旺衰（旺相休囚死）** | 五行在月令之下的五种状态：当令为「旺」、得生为「相」、休歇为「休」、受克为「囚」、被克至极而为「死」。决定「气」的强弱。 | `core/bagua.mjs` 的 `wangShuai()`／`WANG_SHUAI_SCORE`／`WANG_SHUAI_PHRASE`；`chart.tiyong.wang.ti`／`wang.yong`（含 `state`／`season`／`phrase`） |
| **月建** | 以**节气**为界定的月支（立春起寅月），与农历月份不同。断旺衰以此为准。 | `core/calendar.mjs` 的 `monthBuild()`；`chart.calendar.monthZhi`／`monthIndex`／`jie`／`term`／`nextJie` |
| **节气** | 太阳视黄经每 15° 为一个节气；本项目只用十二「节」来定月建，并给出下一个节气的近似时刻用于谈应期。 | `core/calendar.mjs` 的 `SOLAR_TERM_NAMES`／`JIE_NAMES`／`nextJieTime()`；`chart.calendar.jie`／`term`／`nextJie`；文句出现在 `reading.tone` 的 `yingqi` 段 |
| **卦德** | 卦典里为每卦标注的吉凶倾向与一句话要义，用作断语的「肉」。 | `knowledge/64gua.json` 的 `fortune`（大吉／吉／中吉／平／小凶／凶）与 `coreMeaning`／`keywords`／`advice`；`chart.ben.fortune`／`chart.bian.fortune` |
| **刚柔（体卦阴阳）** | 体卦属阳（乾震坎艮）或属阴（坤巽离兑）。走势里以 ±100 表示，平滑后即一段时期的刚柔之比。 | `core/trend.mjs` 的 `DOMAINS` 中 `tiYangRatio` 一项；`chart.tiyong.ti.name` |
| **五行** | 木火土金水。用于生克关系、旺衰、走势的五行占比。 | `core/bagua.mjs` 的五行常量与 `core/trend.mjs` 的 `ELEMENTS`／`ELEMENT_COLORS` |
| **爻位** | 动爻所处之位及其评价：二、五得中为吉，三、四多惧为不利，初、上为终始之位居中。 | `core/divination.mjs` 的 `POS` 表与 `core/verdict.mjs` 的 `YAO_PLAIN`；`chart.moving.positionSymbol`／`positionName` |

### 1.3 时间与历法

| 术语 | 定义 | 在本项目里的位置 |
|---|---|---|
| **时辰** | 两小时为一个时辰，以十二地支记（子时含 23:00–00:59）。梅花易数取数用其序数（子 1 … 亥 12）。 | `core/calendar.mjs` 的 `hourZhi()`／`zhiNumber()`；`chart.calendar.trueHourZhi`／`trueHourNumber`／`clockHourZhi`／`clockHourNumber` |
| **钟表时间** | 用户填写的本地标准时（北京时间），格式 `YYYY-MM-DD HH:mm`。 | `cast.localTime`；`chart.calendar.localTime`／`dateTime` |
| **真太阳时** | 钟表时间 ＋ 经度时差 ＋ 均时差。取时辰默认用它，因为同一钟点在不同经度的时辰可能不同。 | `core/calendar.mjs` 的 `trueSolarTime()`；`chart.calendar.trueSolarTime`／`trueSolarHour`；起卦输入 `cast.useTrueSolarTime` |
| **均时差** | 真太阳时与平太阳时之差（分钟），由地球轨道偏心率与黄赤交角造成，随日期在 ±16 分钟内变化。 | `core/calendar.mjs` 的 `equationOfTime()`；`chart.calendar.equationMinutes` |
| **经度时差** | 当地经度相对标准时中央经线（东经 120°）的时间差，每度 4 分钟，东经为正。 | `core/calendar.mjs` 的 `longitudeOffsetMinutes()`／`CHINA_STANDARD_MERIDIAN`；`chart.calendar.longitudeMinutes`／`offsetMinutes` |
| **日干支** | 以儒略日连续推六十甲子得到的日柱（甲子为 0）。 | `core/calendar.mjs` 的 `dayGanZhi()`；`chart.calendar.dayGanZhi`／`dayGanZhiIndex` |
| **年干支** | 以**立春**为界的年柱；年月日时起卦取年支之数参与运算。 | `core/calendar.mjs` 的 `yearGanZhi()`；`chart.calendar.yearGanZhi` |
| **儒略日** | 连续日数（含日内小数），本项目所有历法换算的中间量。 | `core/calendar.mjs` 的 `julianDay()`／`fromJulianDay()`；`chart.calendar.julianDay` |
| **应期** | 事情可能应验的时间窗口。由动爻之位定常期，再由体卦旺衰提前或推迟。 | `core/verdict.mjs` 的 `YING_QI_POSITION`／`timingFor()`；`reading.tone` 的 `yingqi` 段；插件 `data/plugins/review-watch.mjs` 复用它做提醒 |
| **一事一占** | 一次只问一件单一、具体、可验证的事。问得越单一，卦象越不散；多个目标同问则卦散。 | 面向用户的规矩，写在 `README.md` 与 `agent/loop.mjs` 的 `SYSTEM_PROMPT`；`cast.question` 与 `record.question` 是它落到的字段 |

### 1.4 文辞与判断

| 术语 | 定义 | 在本项目里的位置 |
|---|---|---|
| **卦辞** | 《周易》每卦的断语（如泽水困「亨，贞，大人吉，无咎。有言不信。」），是古籍原文。 | `knowledge/64gua.json` 的 `guaci`；`chart.ben.guaci`；`reading.classical.guaci` |
| **大象辞** | 《象传》里对卦象的解说（如「泽无水，困，君子以致命遂志。」），是古籍原文。 | `knowledge/64gua.json` 的 `xiang`；`reading.classical.xiang`／`huXiang`／`bianXiang` |
| **爻辞** | 三百八十四爻各自的辞，加乾坤的用九用六，是古籍原文。 | `knowledge/yaoci.json`；`chart.moving.yaoText`；`reading.classical.yaoci` |
| **释义** | 卦典里为每卦编写的 `coreMeaning`／`keywords`／`advice` 三项。它们**是编写的释义，不是古籍原文**，与卦辞、爻辞、大象辞区别对待。 | `knowledge/64gua.json` 的 `coreMeaning`／`keywords`／`advice` |
| **吉凶等级** | 六档：大吉 ≥55、吉 25~54、中吉 0~24、平 −8~−1、小凶 −40~−9、凶 <−40（总分 −100 ~ +100）。 | `core/divination.mjs` 的 `gradeOf()`；`chart.score.grade`（`key`／`label`／`tone`／`desc`）与 `reading.grade` |
| **断语** | 由规则引擎生成的两层解读：文言的「卦象定调」（谶 ＋ 七段）与白话的「通俗解」。 | `core/verdict.mjs` 的 `interpret()`；`reading`（`signature`／`tone`／`classical`／`plain`／`grade`） |
| **谶（谶语）** | 断语的总纲四句，一卦气质最重处。可由卦条键名「签」／「谶」直接指定，否则由引擎按卦局指纹选取。 | `core/verdict.mjs` 的 `SIGNATURE` 词库与 `pick()`；`reading.signature`；工具 `trend` 与总览页会展示它 |
| **卦气** | 体用两卦在月令之下的气的对比，即旺衰之比。「卦气不顺」即体弱用强。 | `core/verdict.mjs` 的 `comparePlain()`／`qiExtra`；`chart.tiyong.wang`；插件 `stats-plus.mjs` 的「卦气走势」 |
| **校勘** | 把「当初口头所述的卦」与「本程序依正法重算的卦」逐项对照，把差异记录下来。 | `core/record.mjs` 的 `audit()`；`record.claimed` 与 `record.corrections`（`field`／`label`／`stated`／`computed`／`note`） |
| **取法存异** | 一种特殊校勘：所述与原述都对，只是当初用了另一路起卦或取动爻之法。本项目忠实保留原卦，只把差异记下来。 | `corrections[].field` 为 `movingRule`／`castingRule` 的条目（见 `data/records/202609280312-01.json` 等） |

## 二、工程术语

| 术语 | 定义 | 在本项目里的位置 |
|---|---|---|
| **卦录** | 一条完整的记录：起卦输入 ＋ 卦局快照 ＋ 断语快照 ＋ 原文 ＋ 复盘。是本程序存储与操作的基本单位。 | `data/records/<id>.json`；模型在 `core/record.mjs`；`record` 字段贯穿全项目 |
| **卦录编号（id）** | `YYYYMMDDHHmm`（起卦时间）＋ 两位序号，形如 `202609280338-01`。一经生成不再更改。 | `core/record.mjs` 的 `stampOf()`／`makeId()`；`record.id`；文件名即 id |
| **卦条** | 「卦条 v1」：一行一个 `键: 值` 的纯文本导入格式，是本项目**保证稳定的导入契约**。多条用单独一行 `---` 分隔。 | `core/guaTiao.mjs`；`schema/gua-tiao.schema.json`；`docs/规范.md` 第二节 |
| **卦局** | 一次起卦算出的全部内容：起卦推演、本卦、互卦、变卦、动爻、体用、旺衰、吉凶评分、历法。 | `core/divination.mjs` 的 `cast()`／`buildChart()` 返回值；落盘为 `record.chart` |
| **起卦（cast）** | 依梅花易数正法由输入推出卦象的动作，也是卦录里**唯一真源**的那个字段名。 | `core/divination.mjs` 的 `cast()`；`record.cast` |
| **唯一真源** | 唯一有权决定其余内容的那一份数据。在卦录里就是 `cast`：任何一条卦录都能由它重算。 | `record.cast`；见 [ADR-0004](./adr/ADR-0004-cast是唯一真源.md) |
| **快照** | 某个时刻由引擎算出并冻结下来的结果。引擎升级不改变已存的快照。 | `record.chart`（卦局快照）、`record.reading`（断语快照） |
| **重算** | 用当前引擎按 `cast` 重新生成 `chart` 与 `reading` 的**显式**操作，只替换这两样并递增 `revisionCount`。 | `core/record.mjs` 的 `recompute()`；`POST /api/records/:id/recompute`；界面「重算断语」按钮 |
| **七段** | 断语「卦象定调」的固定顺序：主 → 互 → 变 → 断 → 宜 → 忌 → 应期。顺序不可变，改了就要升 schema 版本。 | `core/verdict.mjs` 的 `tone` 数组；`tools/validate.mjs` 校验标签串必须等于 `主互变断宜忌应期` |
| **通俗解** | 断语的白话层：一句话结论、要旨、为什么这样说、怎么做。与文言的七段配套。 | `reading.plain`（`oneLine`／`focus`／`why[]`／`how[]`）；界面「通 俗 解」卡片 |
| **古辞佐证** | 断语引用的古籍原文集合：本卦卦辞、象传、动爻爻辞、互卦象传、变卦象传，各带出处。 | `reading.classical`（`guaci`／`xiang`／`yaoci`／`huXiang`／`bianXiang`，各含 `text`／`source`） |
| **吉凶权衡** | 界面里把八项评分的权重、归一值与说明逐项摊开的那一块，用来解释总分是怎么来的。 | `chart.score.breakdown[]`（`label`／`weight`／`value`／`pct`／`note`）；`web/api.js` 的 `scoreHtml()` |
| **走势领域** | 走势图里一条可勾选的序列。每个领域由卦录算出一个数值序列，量程只能是 `signed`（−100~100）或 `percent`（0~100）。 | `core/trend.mjs` 的 `DOMAINS`（`score`／`relation`／`bian`／`tiWang`／`grade`／`tiYangRatio`） |
| **量程** | 一条线允许的取值范围。不同量程的线**不得**画在同一根轴上；五行占比单独成一个模式。 | `core/trend.mjs` 的 `SCALE`（`signed`／`percent`）；接口参数 `GET /api/trend?mode=` |
| **平滑窗口** | 走势图的移动平均窗口（1–12 卦）。只影响显示，原始序列以淡线一并画出。 | `core/trend.mjs` 的 `movingAverage()`／`rollingShare()`；接口参数 `smooth` |
| **复盘** | 记录后来实际发生了什么、卦在何处应了何处没应。本程序认为这是最值钱的部分。 | `record.review`（`status`／`result`／`reviewedAt`／`log[]`）；状态枚举见 `core/record.mjs` 的 `REVIEW_STATUS` |
| **校勘 vs 校验** | **校勘**比的是「当初所述」与「重算结果」（内容层，存录差异）；**校验**比的是「数据」与「schema 及语义约定」（结构层，报错不放行）。 | 校勘在 `core/record.mjs` 的 `audit()`；校验在 `core/schema.mjs` 与 `tools/validate.mjs` |
| **插件** | 数据目录下的一个 `.mjs` 文件，导出 `{ id, name, version, activate(ctx) }`，通过 `ctx` 注册路由、页面、面板、导出器与事件钩子。 | `server/plugins.mjs` 的 `PluginHost`；`data/plugins/*.mjs`；`docs/规范.md` 与 [插件与扩展开发指南](./12-插件与扩展开发指南.md) |
| **热载** | 不重启进程重新加载全部插件。实现方式是给 `import()` 的 URL 加时间戳查询串让模块缓存失效。 | `server/plugins.mjs` 的 `loadAll()`；`POST /api/plugins/reload`；界面「插件」页按钮 |
| **插件上下文（ctx）** | 插件拿到的能力对象：`registerRoute`／`registerPage`／`registerPanel`／`registerExporter`／`on`／`store`／`core`／`config`／`log`／`warn`／`assetsDir`。 | `server/plugins.mjs` 的 `makeContext()` |
| **MCP** | Model Context Protocol。问心卦以 JSON-RPC 2.0 over stdio 暴露 21 个工具、3 个资源与 2 个提示模板，供 Codex／Claude／DSH 等外部 agent 驱动。 | `agent/mcp-server.mjs`；`tools/check-mcp.mjs`；见 [ADR-0009](./adr/ADR-0009-MCP接入面.md) |
| **REST 接口** | 本地服务暴露的 HTTP 接口，挂在 `127.0.0.1` 上，供界面、脚本与调试使用。 | `server/index.mjs`；完整清单见 [接口文档](./03-接口文档.md) |
| **IPC** | 进程间通信。桌面版用它把主进程的能力（打开数据目录、导出备份、定位卦录文件…）递给渲染进程。 | 通道名 `qxg:info`／`qxg:open-data-dir`／`qxg:open-backups`／`qxg:export-backup`／`qxg:reveal-record-file`／`qxg:choose-data-dir`／`qxg:navigate`；两端在 `desktop/main.mjs` 与 `desktop/preload.cjs` |
| **preload** | Electron 的预加载脚本，在页面脚本之前运行，用 `contextBridge` 把受控能力挂到 `window.__qxgDesktop`。本项目里**必须是 `.cjs`**。 | `desktop/preload.cjs` |

## 五、容易混淆的词

| 易混对 | 区别 |
|---|---|
| **卦辞** vs **爻辞** | 卦辞是整卦的断语（每卦一条，共 64 条）；爻辞是每一爻的辞（每卦六条，共 384 条，另加乾坤的用九用六）。卦辞在 `chart.ben.guaci`，爻辞在 `chart.moving.yaoText`。 |
| **卦辞** vs **大象辞** | 卦辞是《周易》经文，讲吉凶断语；大象辞是《象传》对卦象的解说，讲「君子以……」。前者如「亨，贞，大人吉」，后者如「泽无水，困，君子以致命遂志」。 |
| **卦辞** vs **卦德** | 卦辞是**古籍原文**；卦德（`fortune` ＋ `coreMeaning`）是**本项目编写的释义**，用于评分与断语。异文与编写内容在知识库里分别标注。 |
| **互卦** vs **变卦** | 互卦由本卦**中间四爻**重组而成，看事情的**中段**；变卦由**动爻反转**而成，看事情的**归宿**。互卦不需要动爻就能算，变卦必须有动爻。 |
| **本卦** vs **变卦** | 本卦是当下格局（体用生克在此定）；变卦是结局。断语里「主」讲本卦，「变」讲变卦。 |
| **体卦** vs **用卦** | 体是我，用是事。定法只有一条：**动爻所在之卦为用，另一卦为体**。写反了会进校勘（天泽履那条就是实例）。 |
| **校勘** vs **校验** | 校勘比「当初所述」与「重算结果」，输出到 `corrections` 并存录，**不阻断**任何操作；校验比「数据」与「schema 及语义约定」，输出错误并**阻断**落盘。前者是内容层，后者是结构层。 |
| **自动校勘** vs **人工校勘** | 自动校勘（`claimed`＋`corrections`）由程序在导入时重算对校，是**结构化的差异**；人工校勘（`collation`）是人写的一段话，记程序算不出的措辞更正（如「阳变阴」应作「六四阴爻动，变阳」）。两者分开存，互不覆盖，免得分不清哪条是机器算的。 |
| **校勘** vs **复盘** | 校勘发生在**导入时**，对象是「卦象本身说得对不对」；复盘发生在**事后**，对象是「这卦应验得怎么样」。前者由程序自动产出，后者由用户手写。 |
| **断语** vs **通俗解** | 断语（`reading`）是整块，含文言定调、通俗解与古辞佐证；通俗解（`reading.plain`）只是其中白话的那一层。说「断语七段」时指的是定调那七段，不含通俗解。 |
| **卦象定调** vs **吉凶权衡** | 定调是**文字**（谶 ＋ 七段文言），给人读；权衡是**数**（八项权重、归一值、总分），给人查。界面里是两块卡片。 |
| **卦条** vs **卦录** | 卦条是**导入用的纯文本**（人、脚本、AI 都能写）；卦录是**程序存的 JSON**（含快照、校勘、复盘）。卦条经解析后变成卦录，二者不是同一层的东西。 |
| **卦条** vs **对话文本** | 卦条是**有契约的**（键名字典、必填规则、schema、校验器）；对话文本是**自由的**（靠启发式识别，认不准就报缺）。两条路径在 `core/importer.mjs` 的 `parseMany()` 里自动分流。 |
| **重算** vs **迁移** | 重算换的是 `chart` 与 `reading`（内容），由用户显式触发；迁移换的是**记录结构**（`schema` 版本），在载入时自动发生且先备份原件。两者都能改到同一条卦录，但改的东西不重叠。 |
| **快照** vs **原文存录** | 快照（`chart`／`reading`）是**程序算出来的**，可重算、可升级；原文存录（`narrative`）与补充存录（`background`／`plan`／`qa`／`collation`）是**用户带来的**，程序永不改写它们。 |
| **唯一真源** vs **快照** | 唯一真源（`cast`）是权威输入，快照是它的计算结果。真源变了快照才需要重算；快照过时不影响真源。 |
| **旺衰** vs **吉凶等级** | 旺衰说的是**五行在月令下的气**（旺相休囚死，五种状态）；吉凶等级说的是**整卦的综合判断**（大吉到凶，六档）。旺衰是评分的八项之一，不是结论。 |
| **无卦象** vs **未知关系** | `relation.key` 取 `unknown` 表示体用关系未能判定（断语会退化为「体用生克未明，姑且平看」）；这不是「没有卦」，卦一定算得出来。 |
| **时辰** vs **钟表时间** | 钟表时间是用户填的那一串 `YYYY-MM-DD HH:mm`；时辰是由它（或真太阳时）换算出的两小时区段。是否用真太阳时定时辰由 `useTrueSolarTime` 决定，**这一项会改变整个卦**。 |
| **真太阳时** vs **北京时间** | 北京时间是标准时（东经 120° 的平太阳时）；真太阳时还需加经度时差与均时差。兰州与北京时间可差约一小时，时辰因此常改换。 |
| **月建** vs **农历月** | 月建以**节气**为界（立春起寅月），农历月以朔望为界。断旺衰用月建，不用农历月。 |
| **插件** vs **扩展点** | 插件是**不改内核**就能加的能力（`data/plugins/*.mjs`）；扩展点是**要改源码**才能加的能力（如 `core/trend.mjs` 的 `DOMAINS`、`core/divination.mjs` 的 `METHODS`）。`AGENTS.md` 的扩展点速查两列都列了。 |
| **热载** vs **重启** | 热载只重新执行插件模块（`?t=` 让模块缓存失效），服务与卦录缓存不动；重启会重新载入全部内核与数据。热载**不清理**插件自己起的定时器与句柄。 |
| **主进程** vs **渲染进程** | 主进程跑服务、窗口、菜单、托盘、IPC；渲染进程只跑界面，且拿不到 Node。两者之间只有 preload 暴露的那几个口子。 |

## 六、项目自造词

本项目的自造词都为了同一件事：**把「一条记录」这件事在中文里说得准确、不歧义、能长期用下去**。已有词汇（记录、数据、结果）在软件语境里太泛，需要区分「导入用的文本」与「存下来的结构化记录」时就会打架。所以造了下面这几个词。

| 自造词 | 为什么造它 | 对应的代码标识符 |
|---|---|---|
| **卦录** | 「记录」太泛（日志也是记录），「占卜结果」太长且只强调结果。卦录＝一卦一录：既指那条 JSON，也指这件事本身（起卦、断卦、存卦、复盘、看势的完整单位）。序言里那句「一卦一录，久而成史」就是这个意思。 | `record`；`core/record.mjs`；`data/records/`；`/api/records` |
| **卦条** | 需要一种「人、脚本、AI 三方都能产出」的导入格式，且要比 JSON 好手写、比对话文本稳定。取「一条一条」之意：一行一个字段，多条用 `---` 分隔。 | `guaTiao`；`core/guaTiao.mjs`；`schema/gua-tiao.schema.json`；`save_gua_tiao`；`/api/guatiao/*` |
| **卦局** | 「卦象」常被理解为六十四卦中的一个（本卦）；但本程序一次算齐本卦、互卦、变卦、六爻、动爻、体用、旺衰、评分与历法。「局」字强调这是一整套摆开的局面，不是单个符号。 | `chart`；`core/divination.mjs` 的 `buildChart()`；`record.chart` |
| **断语** | 「解读」「分析」都带主观色彩，而这一块是**程序按规则算出来的**文本，需要与「聊天记录里别人说的话」区分开。断语＝断卦之语，且明确指引擎产出的那一份。 | `reading`（引擎 `interpret()`）；`core/verdict.mjs`；`reading.tone` |
| **七段** | 定调有七块，且**顺序不可变**（`tools/validate.mjs` 会验）。给它一个便于引用的名字，是为了让「顺序」这件事有一个可以在文档、自检与口头沟通中共同指称的对象。 | `reading.tone` 数组（`main`／`hu`／`bian`／`duan`／`yi`／`ji`／`yingqi`） |
| **谶** | 总纲四句是一卦气质最重处，既不是卦辞（古籍原文），也不是断语的某一段。用「谶」这个单字，是为了强调它**短、断、可记**——用户往往只记得住这四句。 | `signature`；`reading.signature`；`core/verdict.mjs` 的 `SIGNATURE` 词库；卦条键「签」／「谶」 |
| **体用** | 不是自造词，但在本项目里被收紧为一个**只有一种定法**的术语（动爻所在之卦为用）。造这个约束是为了让「体用写反」成为可以被程序照出来的错误。 | `tiyong`；`chart.tiyong`；`core/hexagram.mjs` 的 `tiYongOfLines()` |
| **旺衰** | 用「旺相休囚死」五字太啰嗦，且需要与「吉凶」明确区分（旺衰是气，不是结论）。两个字就够指称那五种状态。 | `wang`；`chart.tiyong.wang`；`core/bagua.mjs` 的 `wangShuai()`；走势领域 `tiWang` |
| **取法存异** | 需要区分「当初写错了」（校勘）与「当初用了另一路取法」（不是错）。造这个词是为了让程序能**忠实保留原卦**而不把它当错误改掉。 | `corrections[].field` 为 `movingRule`／`castingRule`；`core/divination.mjs` 的 `inferMovingFrom()`；`cast.movingFrom` |
| **走势领域** | 「指标」是金融词，「维度」太抽象。「领域」既指一个可勾选的量，也暗示它各管一件事（总分、生克、结局、旺衰、等级、刚柔）。 | `domain`；`core/trend.mjs` 的 `DOMAINS` |
| **量程** | 不同线不能画在同一根轴上，需要一个词来指「这条线的取值范围」。 | `scale`；`core/trend.mjs` 的 `SCALE` |
| **热载** | 「重新加载」会被误解为重启服务。热载特指**不重启**前提下重新执行插件模块。 | `reload`；`POST /api/plugins/reload`；`PluginHost.loadAll()` |
| **唯一真源** | 需要一个短词来表达「这一份是权威，其余都是它的派生」。它同时是数据模型的核心约定与口头沟通的抓手。 | `record.cast`；[ADR-0004](./adr/ADR-0004-cast是唯一真源.md) |
| **界面形态（桌面窗口）** | 指「不用 Electron、用系统浏览器以 `--app` 模式开独立窗口」的零安装兜底方案，需要一个不与「桌面版」混淆的名字。 | 启动脚本 `问心卦(桌面窗口).vbs`；README 的「方式二」 |
