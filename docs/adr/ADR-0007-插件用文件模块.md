# ADR-0007：插件用文件模块而不是 npm 包

| 项 | 内容 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-03 |
| 决策者 | 项目维护者 |
| 影响的模块 | `server/plugins.mjs`、`server/index.mjs`、`server/store.mjs`、`data/plugins/`、`data/config.json`、`web/views.js`、`data/plugins/review-watch.mjs`、`data/plugins/stats-plus.mjs`、`data/plugins/html-card.mjs` |

## 背景

插件宿主是 `server/plugins.mjs` 的 `PluginHost`。它的加载过程只有几步：`loadAll()` 先 `reset()` 清空状态，`fs.readdirSync(this.dir)` 挑出 `*.mjs`，逐个用带时间戳的查询串动态载入：

```js
const mod = await import(`${pathToFileURL(path.join(this.dir, file)).href}?t=${Date.now()}`);
const def = mod.default || mod.plugin;
if (!def || typeof def.activate !== 'function') {
  this.errors.push(`${file}：未导出 default.activate(ctx)，已跳过`);
  continue;
}
```

查询串 `?t=Date.now()` 是**热载**的实现方式：它让 Node 的模块缓存失效，从而可以不重启进程重新执行插件模块。触发入口有两处——界面「插件」页的「热载全部插件」，或 `POST /api/plugins/reload`。启停另走 `POST /api/plugins/:id/toggle`，把 `enabled` 写进 `data/config.json` 的 `plugins.<id>`，下次 `loadAll()` 时被跳过的插件仍会在清单里以 `enabled: false, loaded: false` 出现，而不是消失。

一个插件就是一个 `.mjs` 文件，导出 `{ id, name, version, description, activate(ctx) }`。`ctx` 提供的能力是固定的四类注册点加一组工具：

| 能力 | 作用 | 挂载位置 |
|---|---|---|
| `ctx.registerRoute(method, path, handler)` | 加 REST 接口 | `/api/plugins/<id>/…` |
| `ctx.registerPage({id,label,icon,order,render})` | 加侧栏页面 | `/api/plugins/<id>/page/<id>` |
| `ctx.registerPanel({id,label,order,render})` | 在卦录详情页加一块 | `/api/plugins/<id>/panel/<id>` |
| `ctx.registerExporter({id,label,ext,mime,render})` | 加一种导出格式 | `/api/records/<id>/export?format=<id>` |
| `ctx.on(event, fn)` | 订阅事件 | `app.start`、`record.created`、`record.updated`、`record.deleted`、`cast.preview` |
| `ctx.store` / `ctx.core` / `ctx.config` / `ctx.log` / `ctx.warn` / `ctx.assetsDir` | 直接用宿主的存储与全部内核 | 静态资源走 `/plugin-assets/<id>/…` |

`ctx.core` 是宿主**已载入的模块实例**（`divination`／`verdict`／`hexagram`／`calendar`／`render`／`importer`／`guaTiao`／`trend`／`schema`／`migrate`／`record`），所以插件拿到的是同一份内核，不会出现「插件里算出的卦与主程序算出的卦不一致」。

这一层能落地是有实例支撑的：随包内置三个可用样例——`data/plugins/review-watch.mjs`（按动爻之位推算应期窗口，挑出该复盘还没复盘的卦，并在详情页加一块应期进度）、`data/plugins/stats-plus.mjs`（体卦五行分布、五行 × 吉凶交叉表、卦气走势，并自注册 `GET /api/plugins/stats-plus/trend`）、`data/plugins/html-card.mjs`（离线单文件 HTML 卡片导出，自带样式、不依赖本程序也不依赖网络）。

## 决策

扩展**必须**以「数据目录下的一个 `.mjs` 文件」为单位，**不得**要求用户执行 `npm install`、**不得**依赖 `package.json` 的 `dependencies` 装包。插件**必须**通过 `activate(ctx)` 注册能力，**必须**经 `PluginHost` 载入，且**必须**支持热载（改完不重启即生效）。插件**不得**要求修改内核代码；需要内核能力时**应当**通过 `ctx.core` 取用，而**不得**复制一份实现。

## 理由

1. **零安装。** 插件的安装动作就是「把一个文件放进 `data/plugins/`」，删除动作就是删掉文件。没有依赖解析、没有版本冲突、没有 `node_modules`。这与 [ADR-0001](./ADR-0001-零第三方依赖.md) 同源：如果插件本身要靠 npm 分发，零依赖就只保住了主程序。
2. **热载让试错成本接近零。** 插件改动后 `POST /api/plugins/reload` 即可生效，配合 `ctx.log` 输出，写插件的循环是「改文件 → 点热载 → 看结果」。若每次都要重启服务、重开窗口，插件生态不会有人写。
3. **可读。** 一个插件是一份纯文本 ES 模块，用户可以打开看它到底做了什么——这一点在「保存几十年私事记录」的软件里很重要。npm 包形态会把逻辑藏进压缩产物与依赖树。
4. **内核实例共享，避免第二套实现。** `ctx.core` 给的是宿主已载入的模块，插件因此天然遵守「一处实现，多处复用」：插件要出卦签文本就用 `core.render.toSlip`（`GET /api/records/:id/export?format=slip` 走的就是它），而不自己拼一份。
5. **能力面被显式枚举。** 四类注册点加六项工具就是全部，插件不接触 HTTP 服务器内部、不接触 `Store` 的私有状态。这个边界让宿主能在不破坏插件的前提下调整内部实现。

## 后果

### 正面

- 加一个新能力不需要改内核、不需要重新打包主程序，甚至不需要重启。
- 插件可以有自己的页面、面板、接口与导出格式，用户在侧栏能直接看到（`web/app.js` 的 `paintNav()` 会把 `META.plugins.pages` 并入导航）。
- 插件失败被隔离在插件层：`loadAll()` 里 `activate()` 抛错只记录进 `errors` 并跳过该插件，其余插件继续加载；`emit()` 对每个钩子的调用都包了 `try/catch`，异步钩子的 rejection 也只 `warn`。宿主不会因为插件出错而起不来。
- 样例即文档：三个内置插件覆盖了「面板 + 事件」「自注册接口 + 页面」「导出格式」三种典型用法，照抄即可上手。
- 插件清单对前端可见（`api()` 返回页面、面板、导出器、路由与错误列表），出问题时能在界面上看到 `errors`。

### 负面

- **插件的任意代码执行风险是结构性的。** 插件由宿主 `import()` 进**同一进程**，因此它拥有宿主的全部权限：可以读写 `data/` 下任何文件（包括 `config.json` 里的 API Key）、可以发网络请求、可以结束进程。`ctx` 的边界是**约定而非沙箱**——它规定了插件「应该」怎么做事，拦不住插件「直接 `fs.rmSync`」。缓解措施只有三条：插件放在用户自己的数据目录里、用户自己决定放不放、样例只做只读与展示。这一点必须对用户说明白：**只运行你自己读过或信任的插件**。
- **错误定位靠约定。** 插件抛错只会留下 `[plugins] <file> 载入失败：…` 这样的日志（`tools/check-desktop.mjs` 一类自检能覆盖的也只是内置样例）。
- **热载不完整。** `?t=` 只让**插件模块本身**重新求值；插件若自己 `import` 了别的本地模块，那些模块仍在 Node 的模块缓存里。要彻底重载得连依赖一起带查询串，本项目没有做。
- **`reset()` 是硬回退。** 每次 `loadAll()` 都会清空 `plugins`／`routes`／`pages`／`panels`／`exporters`／`hooks`。若某个插件在 `activate()` 里启动了定时器或打开了文件句柄，热载不会替它清理——这是插件作者自己的责任。
- **接口路径被锁进插件 id。** 路由前缀是 `/api/plugins/<id>/`，id 由文件名或插件自报决定；改文件名等于改接口路径，外部脚本会跟着断。
- **面板渲染要跟得上宿主数据。** 面板拿到的是 `record`，宿主的记录结构升版（`core/migrate.mjs` 的 `CURRENT_SCHEMA` 加一）时，插件若不跟进就会渲染出错。

## 备选方案与为何不选

| 方案 | 为什么没选 |
|---|---|
| 插件以 npm 包分发，用 `npm i` 安装 | 与零依赖的立项前提冲突；且把「装插件」变成需要 Node 工具链的操作，桌面版用户做不到。 |
| 声明式插件（只写 JSON 配置，不支持任意逻辑） | 表达力不足以支撑内置样例：应期窗口推算、五行交叉统计、单文件 HTML 导出都需要真实代码。 |
| 插件跑在独立进程／Worker 里做沙箱 | 要定义一套 IPC 协议与数据同步机制，`ctx.store`／`ctx.core` 都得序列化过桥，代价值得商榷；且在单机软件里，能放插件的人本来就能改 `data/`。真要隔离，应当作为独立 ADR 单独立项。 |
| 把插件直接写进 `core/`／`server/` 当内置功能 | 会让内核不断膨胀，且用户无法在不改代码的前提下停用某个功能。 |
| 用 `eval`／`new Function` 载入插件源码 | 失去 ES 模块的 `import` 能力与语法检查，且更易被误用；`import()` 已经能同时做到热载与模块化。 |
