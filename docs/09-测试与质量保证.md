本文描述问心卦的自检体系：七套自检脚本各验什么、为什么这样设计、它们实际抓出过哪些缺陷、以及改动代码后的回归流程。本文中的项数均取自脚本实跑输出或逐行源码统计。

> **项数由机器守**：文档里凡是写成 `tools/<脚本>.mjs`（N 项）的地方，都由 [`tools/check-docs.mjs`](../tools/check-docs.mjs) 与实跑值逐条对；对不上它会点名文件与行号。所以改完自检**必须**重跑 `check-docs.mjs`，否则文档立刻撒谎。
> 附录 B 的分节明细同样要人工跟着改——那里是检查器覆盖不到的盲区（它只认反引号紧跟 `（N 项）` 的写法）。

## 一、质量目标与验收标准

### 1.1 什么叫「这个项目是好的」

问心卦的立项前提是**单机、零第三方依赖、长期使用**。因此「好」不是功能多，而是四件事：

| 目标 | 含义 | 判定方式 |
|---|---|---|
| **可复现** | 同一 `cast` 输入必得同一卦局；同一卦局重算必得同一断语 | 六次历史起卦逐项断言；断语变体按卦局指纹取散列，不用随机 |
| **可长久** | 十年后仍能跑起来；程序不在了数据还在 | `dependencies` 恒为空；卦录是纯文本 JSON；JSON Schema 与版本迁移齐备 |
| **不污染** | 测试不写用户数据；删除只进 `data/trash/`；迁移先备份 | 临时目录用 `os.tmpdir()`；桌面自检用独立 user-data-dir；迁移前强制备份 |
| **不撒谎** | 认不准就报缺，不猜；校验器必须抓得出错；模型不得编造卦象 | 解析器给出 `missing`／`unknownKeys`；校验器做负向测试；system prompt 受断言保护 |

### 1.2 可度量的验收标准

| 编号 | 标准 | 阈值 | 验证手段 |
|---|---|---|---|
| QA-1 | 七套自检全部通过 | 260 + 10 + 14 + 63 + 55 + 123 + 30 = **555 项，失败 0** | `npm run check:all` |

### 1.3 用语强度

「**必须**」表示强制要求，违反即视为缺陷；「**应当**」表示除非有明确理由否则照做；「**可以**」表示可选；「**不得**」表示禁止。

## 二、测试分层

问心卦不使用测试框架（那会引入第三方依赖）。七套自检脚本按层次划分：

| 层次 | 对应脚本 | 依赖 | 项数 | 何时跑 |
|---|---|---|---|---|
| **单元** | `tools/check.mjs`（第一至三节、第六节） | 无 | 见 §3.1 | 每次改动 |
| **集成** | `tools/check.mjs`（第四、五、七、八、十、十一节）、`tools/validate.mjs` | 无（用 `os.tmpdir()` 建临时库） | 见 §3.1、§3.7 | 每次改动 |
| **契约** | `tools/check-validate.mjs`、`tools/check-mcp.mjs` | 校验器与 MCP 子进程 | 10 + 14 | 每次改动 |
| **网关** | `tools/check-hermes.mjs` | 无（全离线，不打网络） | 63 | 改了 `hermes/`、`agent/provider.mjs` 后必须跑 |
| **端到端（网页）** | `tools/check-web.mjs` | 连不上服务时自起示例服务 | 116 | 每次改动 |
| **端到端（桌面）** | `tools/check-desktop.mjs` | 需 Electron 运行时 | 51 | 动了 `desktop/` 后必须跑 |
| **文档一致性** | `tools/check-docs.mjs` | 无（须先跑过网页与桌面两套） | 27 | 改了任何会写进文档的事实 |
| **回归** | 以上七套整体 | — | 555 | 提交前、发布前 |

分层的取舍：

- **端到端只做两层。** 网页层用「万能 DOM 桩」把 `web/app.js` 真跑起来（`check-web.mjs`）；桌面层真起 Electron（`check-desktop.mjs`），因为 preload 桥、渲染结果、窗口是否出现这三样，DOM 桩测不到。
- **网关单独成层。** Hermes 的失效方式不是崩溃，而是「协议猜错、把纯文本误判成工具调用、该重试的不重试、该熔断的不熔断」——这些都必须用固定输入逐条断言，且必须完全离线（否则测试会因网络或第三方服务而随机红）。
- **契约层同样单独成军。** 校验器与 MCP 都属于「对外承诺」，失效方式是**静默通过**——所以必须有负向测试与真子进程测试。
- **回归是一个合集。** `npm run check:all` 按 `check.mjs → check-validate.mjs → check-mcp.mjs → check-hermes.mjs → check-desktop.mjs → check-web.mjs` 串行执行，任一套失败即整体失败。

> `check:all` 中包含桌面与网页两套，因此它**需要 Electron**（网页套连不上服务时会自己起一个示例服务）。只想快速回归内核与网关时，跑前四条即可。

#### 为什么这样设计

- **卦典与爻辞用「互推自洽」而非「逐字比对」。** 逐字比对只能发现抄错，互推自洽能发现结构性错误——上下卦与六爻图不一致，会让卦象整体错位。
- **历法给两个日干支基准点。** 单点可以被任意偏移量凑对，双点才能锁住公式。
- **六个历史卦局是「金标准」。** 它们来自真实对话记录，含两种动爻取法、三种起卦法、两处历史校勘；既是回归网，也是「忠实复现原卦」这一承诺的证据。
- **迁移放在内核自检里，不留给运维。** 迁移是会毁数据的路径，必须在每次改动时都被跑到。
- **第八节里守 system prompt 硬约束的那几项，是这一套里最不像测试的测试。** 它们守的是一条产品红线：模型不得编造卦象，也不得自己编一个报数。删掉这几句 system prompt 不会有任何报错，但会让 AI 助手的可信度归零。

**为什么 MCP 必须验 stdout 纯净性**：MCP 走 stdio，宿主（Codex CLI / Claude Code / DSH）把请求写进子进程 stdin，然后**按行解析 stdout**。这条通道有一条生死线——**stdout 只允许出现 JSON-RPC 消息**。

- 只要有一行日志漏到 stdout（哪怕是一句「已就绪」），宿主就会在 JSON 解析上失败，表现为「MCP 服务器连不上」或「工具列表为空」，而**服务器这边看不出任何异常**。

**为什么必须真起 Electron 进程**：`check-web.mjs` 用的是 DOM 桩，它测不到三件事：

1. **preload 桥**。`window.__qxgDesktop` 由 `contextBridge` 注入，桩里根本没有这个概念。开发中真出现过「桥永远是 `undefined`」而控制台不报错的情况。
2. **Electron 的渲染结果与真实几何**。「侧栏不出现滚动条」「六项一屏放得下」这类断言只有在真 Chromium 里才有意义——DOM 桩的尺寸一律是 0，测了等于没测。
3. **窗口到底有没有出现**。「进程在跑但没有窗口」是本项目踩过的最贵的一个坑。DOM 桩自检永远发现不了它——服务与渲染逻辑全都正常，只有窗口不存在。

第 10、11、12 三项静态检查专门守上述坑的**代码形态**：它们不依赖运行时，能在问题发生前报出来。写成「文本正则 + `indexOf` 比较」是因为这三类错误的共同特征是**语法完全合法、运行时静默失败**，静态形态检查反而是最可靠的哨兵。

**为什么要用独立 user-data-dir**：Electron 的单实例锁是按 user-data-dir 记的。若用户桌面上正开着装好的问心卦，自检进程抢不到锁会**静默退出**（退出码 1、零输出），而脚本只会报一句「进程退出码 1 却没有任何输出」，很难对上原因。隔离之后两者互不干扰，自检也不会污染用户真实的窗口位置与配置——这也是第 5.x 节「测试隔离」原则在桌面层的落实。

## 四、已抓出的真实缺陷清单

这一节是本文最值钱的部分。下列缺陷都真实发生过，也都留下了对应的检查项。

| 缺陷 | 表现 | 被哪套抓到 | 修复手段 |
|---|---|---|---|
| agent 工具调用不存在的工具名会抛异常 | 模型幻觉出一个工具名时进程抛错，而不是把「没有这个工具」作为可读结果还给模型；agent 循环中断 | `check.mjs` | `toolkit.call()` 统一返回 `{ ok: false, error: '没有名为「X」的工具。可用工具：…' }`；补上检查项 78 |
| 卦条模板里的括号注释被当成数据 | `--template` 生成的模板自带的括注被解析器当真值读走，认出「泽水困」当成真卦名 | `check.mjs` | 解析器剥离注释与括注；补上检查项 56、57、58，要求「模板必须能被自己解析回来」 |
| 动爻取法反推被默认值挡住，导致误报校勘 | 卦条只写「数、时、动」，`inferMovingFrom()` 因 `input.movingFrom` 已有默认值而直接返回 `sum`，把「仅以报数取动爻」的原卦误记成校勘 | `check.mjs` | 反推逻辑改为「结果对得上哪一路就按哪一路还原」；补上检查项 83、84、85 |
| 服务运行期间用命令行导入的卦录，运行中的服务看不见 | `node tools/import.mjs x.txt` 落盘成功，但已开着的服务仍显示旧条数，必须重启才看到 | 手工实测发现 | `server/store.mjs` 加 `maybeRescan()`：处理请求时比一次 `records/` 目录 mtime，变了才全量重扫；补上检查项 68、69 |
| 桌面版进程在跑但没有窗口 | 任务管理器里有 `问心卦.exe`，但没有窗口；日志停在固定一行。根因是主进程顶层 `await app.whenReady()`，而 Electron 的 ready 事件要等主模块求值完成后才发出——死锁 | `check-desktop.mjs` | 改为 `app.whenReady().then(main)`，模块同步求值完；补上 90 秒超时判定与检查项 11 |
| 桌面桥 `window.__qxgDesktop` 永远是 `undefined` | 侧栏不显示「桌面版」，桌面专属按钮不出现，**控制台不一定报错**。根因是 preload 写成 `.mjs` + `import`，而 Electron 默认 `sandbox: true`，沙箱化的 preload 不能是 ES 模块，静默失败 | `check-desktop.mjs` | 改名 `preload.cjs` 并用 `require('electron')`；补上检查项 10 与 13 |
| `No handler registered for 'qxg:info'` | 页面一加载完就调 IPC，但 `ipcMain.handle` 注册晚于 `loadURL`，抛错 | `check-desktop.mjs` | `registerIpc()` 提到 `await mainWindow.loadURL()` 之前；补上检查项 12 |
| 桌面自检**静默退出**、零输出 | `check-desktop.mjs` 报「进程退出码 1 却没有任何输出」。根因是 Electron 单实例锁按 user-data-dir 记：用户桌面上正开着装好的问心卦时，自检进程抢不到锁直接退出 | 手工排查后加断言 | 自检改用 `os.tmpdir()` 下的独立 `--user-data-dir`；并在「没有输出」的分支里直接提示单实例锁这个可能原因 |
| 改 `desktop/package.json` 后 Electron 退出码 1 且零输出 | 用 `npx asar extract-file` 抽文件时，文件被写到**当前工作目录**并用内部路径的 basename 命名，把 `desktop/package.json` 覆盖成了别的清单；`main` 字段没了，Electron 无从启动 | 手工排查后写进 `AGENTS.md` 硬规矩 | 用 asar 抽文件前先 `cd` 到一个临时目录；`check-desktop.mjs` 的前 4 项静态检查会在打包或启动前就报出配置缺失 |
| 安装包漏了 `preload.cjs` | 打包后运行 `问心卦.exe`，桌面桥为 `undefined`，桌面专属入口全部失效；开发态却完全正常 | 打包后跑 `--selftest` | `build.files` 里的旧文件名 `preload.mjs` 改为 `preload.cjs` |
| 静默安装不建桌面快捷方式 | 图形化安装正常，`/S` 静默安装后桌面没有快捷方式。根因是 `oneClick: false` 的安装器把 `createDesktopShortcut: true` 做成了完成页的**勾选项**，静默安装跳过该页即跳过建快捷方式 | 静默安装实测 | `build.nsis.createDesktopShortcut` 写 `"always"` 而不是 `true` |
| 卦录「原文存录」满屏字面的 `<br>` | 导入的 DeepSeek 原文几乎每段都有换行，于是详情页里整篇都是 `&lt;br&gt;` 这样的字面标签。根因是 `web/md.js` 的段落分支把 `<br>` 拼进 `inline()` 之后才转义——`esc()` 把它二次转义成 `&lt;br&gt;` | 用户截图报障；`check-web.mjs` 补断言 | 折行改成 `buf.map((l) => inline(l)).join('<br>')`：每行各自解析行内记号，`<br>` 在 `inline()` **之外**拼；检查项「Markdown 段内换行渲染成 `<br>`，不是字面 `&lt;br&gt;`」＋「每行各自解析行内记号」 |
| 聊天框里的多行输入被折成一整段 | 用户分几行写的话，上屏后换行、列表、加粗全没了——`web/chatpanel.js` 的用户消息只做 HTML 转义（`h()`），而 HTML 把换行折成一个空格 | 用户报障；`check-web.mjs` 补断言 | 用户消息改走与模型回答同一套 `renderMarkdown()`；检查项「用户消息保留换行与格式」 |
| 复盘功能位置别扭、记下的条目改不了也删不了 | 复盘卡夹在详情页的卦象与原文之间，打断顺读；「实况」只存在于输入框、与追记分成两套（`result`／`reviewedAt` ＋ `log`），界面上表现为：保存的实况不像追记那样能回看，追记写错一个字只能重开一条 | 用户报障；`check.mjs`／`check-web.mjs` 补断言 | ① 复盘独立成页（`#/review`：左清单右面板，详情页只留入口）；② 数据模型升 v5——`result`／`reviewedAt` 并入首条条目，只剩 `status + log[]` 一个真源；③ 条目可改可删，但**默认只读**、要「开启操作」才显示按钮；④ 导出／卦条／`update_review`／插件面板一并联通 |
| 更新提示条盖在页面上；「查看更新」不能直接下载 | 横幅做成 `position: fixed` 的半透明浮条，正好压在页头标题与「总览」说明文字上（用户截图报「重叠了」）；按钮只打开发行页，还得自己在一堆资产里找安装包（「不能直接获取下载吗」） | 用户截图报障；`check-web.mjs` 补断言 | ① 横幅改成 `.app` 网格里的**一行**（`auto` 行），关着时高度 0、打开时把内容推下去，**不得**用 `display:none`（会错位）；② 服务端从 `assets[]` 挑首选 `*.exe` 并回 `assetUrl`／`size`，主按钮直链下载并在文案里写出体积，「发 行 说 明」另留一条去发行页的路 |

**共性**：十五条里有七条的失效模式是「不报错但不对」（模板注释、反推被默认值挡住、外部改动不可见、桥为 `undefined`、自检静默退出、配置被覆盖、快捷方式没建、进程没窗口）。这正是为什么本项目的自检强调**先起真进程、再断言可观测结果**，而不是只做单元断言。

## 五、测试数据与隔离

### 5.1 原则

| 原则 | 做法 |
|---|---|
| 不污染用户 `data/` | 需要写盘的检查一律在 `path.join(os.tmpdir(), 'qxg-<用途>-<Date.now()>')` 下建临时库，跑完 `fs.rmSync(dir, { recursive: true, force: true })` |
| 不污染 `%APPDATA%` | 自检不设置 `QXG_DATA_DIR`；桌面自检另用 `os.tmpdir()` 下的独立 user-data-dir，不碰 `%APPDATA%\wenxingua-desktop` |
| 不污染知识库与 schema | 负向用例在内存里改对象，不落盘到 `knowledge/`、`schema/` |
| 用后即清 | `check.mjs` 清理 `qxg-check-*`、`qxg-check-mig-*`、`qxg-check-scan-*`、`qxg-check-infer-*`；`check-validate.mjs` 清理 `data/trash/_negtest/`；`check-desktop.mjs` 清理 `qxg-selftest-<pid>/` |
| 不依赖网络 | 七套里没有任何一套需要外网；Hermes 那套连模型端点都不碰 |

### 5.2 各套脚本实际读写的路径

`check.mjs` 读 `knowledge/*.json`、`schema/*.json`、`data/records/*.json`、`data/plugins/*.mjs`（`data/records/` 为空时改用 `tools/fixtures.mjs` 的合成示例卦录，写进 `os.tmpdir()/qxg-check-rec-*` 并跑完清理），只写 `os.tmpdir()/qxg-check-*`；`check-validate.mjs` 以 `tools/fixtures.mjs` 的示例卦录为负向用例基样，写 `data/trash/_negtest/` 后删除；`check-mcp.mjs` 全部经子进程，不落盘；`check-hermes.mjs` 只读 `hermes/`、`agent/provider.mjs`，不落盘、不打网络；`check-web.mjs` 经 HTTP 读写全部接口，**会真实新增并软删一条卦录**（`origin.label === '自检临时卦'`）——用它自起的示例服务时，那条残留与临时数据目录一同清掉、不碰你的 `data/`，用你正在跑的服务（或显式 `QXG_BASE`）时则落在该服务的 `data/trash/`；`check-desktop.mjs` 只读 `desktop/` 下的文件，Electron 的日志与窗口状态写进临时 user-data-dir。

### 5.3 `check-web.mjs` 的残留与处理

`check-web.mjs` 走的是**真实接口**，因此必须有服务可用——连不上时它会用 `tools/fixtures.mjs` 造一个临时数据目录、自起一个示例服务，那条被软删的自检卦录便留在临时目录里、跑完随目录一起清掉，**不碰你的 `data/`**。若你本来就在跑自己的服务（或显式设了 `QXG_BASE`），它就用你的服务，那条残留会落在该服务的 `data/trash/`。复盘页那组断言还会**临时给第一条卦录补一条复盘条目并当场还原**（它验的是「条目真能写进去」与「默认只读」）：连自己的服务时，那一下会写进你的一条真实卦录（内容随即还原，`updatedAt` 会变一次）。这是刻意的取舍：只有走真实入口，才能验证「可入库／可删除」「条目可写」这几项。

该残留不影响任何功能，也不会被 `check.mjs` 的卦录统计计入（`data/trash/` 不是 `data/records/`），属纯文本可肉眼辨认（`dir data\trash`）。

### 5.4 会写 `data/` 的其它入口

`tools/seed.mjs` 会写 `data/records/`（六条历史起卦）；`tools/import.mjs` 不加 `--dry` 时会入库。**这两个是给用户用的工具，不是测试。** 若在开发中跑过，提交前必须确认 `data/` 里只有该有的东西（见 `AGENTS.md` 提交前自检清单）。

## 六、回归流程

### 6.1 标准流程

```bash
node --check <改动过的模块>        # 0. 语法自检
node tools/check.mjs               # 1. 内核（不需服务）
node tools/check-validate.mjs      # 2. 校验器负向能力
node tools/check-mcp.mjs           # 3. MCP stdio
node tools/check-hermes.mjs        # 4. Hermes 网关（全离线）
node server/index.mjs              # 5a. 起服务（另开一个窗口；不起也行，5b 会自起一个示例服务）
node tools/check-web.mjs           # 5b. 前端联调
node tools/check-desktop.mjs       # 6. 桌面版（动了 desktop/ 就必须跑）
node tools/validate.mjs            # 7. 全量数据校验
npm run check:all                  # 七套一步到位
```

### 6.2 改什么跑什么

| 改动范围 | 必须跑的套 | 说明 |
|---|---|---|
| `core/` 任一模块 | `check.mjs`、`check-validate.mjs`、`validate.mjs` | 内核是所有入口的共同底座；改了断语或起卦还要看六个历史卦局是否仍对上 |
| `knowledge/` | `check.mjs` | 卦典与爻辞的完整性、互推自洽会立刻反映 |
| `schema/` | `check-validate.mjs`、`validate.mjs`、`check.mjs` | 同步改 `docs/规范.md` 的字段字典与版本历史 |
| `core/migrate.mjs` | `check.mjs`、`validate.mjs` | 迁移属毁数据路径，必须全过 |
| `hermes/`、`agent/provider.mjs` | **`check-hermes.mjs`**、`check.mjs`（第八节） | 协议、路由、策略与向后兼容都在这一套里 |
| `agent/tools.mjs`、`agent/mcp-server.mjs` | `check.mjs`、`check-mcp.mjs` | 工具集与协议共用一处实现 |
| `server/index.mjs` | `check-web.mjs`、`check-mcp.mjs` | 接口与工具集共用一处实现 |

| 发布前 | 七套 + `validate.mjs` + §8 手工清单 | — |

### 6.3 什么情况算过

「过」的定义是**严格的**：

1. 每套脚本的退出码为 0；
2. 七套的「通过」计数分别为 243、10、14、63、51、95、27，**失败为 0**；
3. `node tools/validate.mjs` 的失败为 0；
4. §8 手工清单逐条打勾；
5. `data/` 目录除 §5.3 所述的自检残留外无额外改动。

任何一项不满足即为**不过**。**不得**在失败项存在的情况下提交、打包或发布。

### 6.4 失败时的定位顺序

| 症状 | 先看 |
|---|---|
| `check.mjs` 六次历史卦局对不上 | 是否改了 `core/divination.mjs` 的取法或 `core/bagua.mjs` 的五行生克 |
| `check.mjs` 卦典项失败 | `knowledge/64gua.json`、`knowledge/yaoci.json` 是否被改坏，或 `knowledge/` 不可读（会退回内置值，此时第 2 项会失败） |
| `check-validate.mjs` 有负向用例未被抓出 | `core/schema.mjs` 的 `strict` 传参、`schema/*.json` 的约束、`tools/validate.mjs` 的语义检查 |
| `check-mcp.mjs` 第 1 项失败 | `agent/mcp-server.mjs` 或其依赖是否有 `console.log` 漏到 stdout，必须改 `console.error` |
| `check-hermes.mjs` 第一节失败 | `hermes/protocols.mjs` 的解析正则；先把失败的原始模型输出打印出来看 |
| `check-hermes.mjs` 第三节失败 | `hermes/router.mjs` 的选择与排序逻辑（权重、`preferLocal`、`tags`、`enabled`、缺 Key 判定） |
| `check-hermes.mjs` 第五节失败 | 向后兼容被破坏：`agent/provider.mjs` 的对外形状变了，或旧 `agent` 段配置不再能合成目标 |
| `check-web.mjs` 第 1 项失败 | `web/app.js` 顶层是否抛错；先手动打开页面看控制台 |
| `check-web.mjs` 报「侧栏主项恰好六项」失败 | `web/app.js` 的 `NAV` 被动过；新入口应当放进 `OFF_NAV`（走命令面板），不要塞进侧栏 |
| `check-web.mjs` 某页报「缺：X」 | 该页文案被改动，或 `web/views.js` 的渲染抛错 |
| `check-web.mjs` 报「含 undefined / NaN」 | 视图模板里拼接了可能为空的对象属性 |
| `check-desktop.mjs` 超时 | 主进程里是否出现了顶层 `await`；看临时 user-data-dir 下的 `desktop.log` 停在哪一行 |
| `check-desktop.mjs` 桥项失败 | `desktop/preload.cjs` 是否存在且为 CJS，`main.mjs` 的 `webPreferences.preload` 是否指向它 |
| `check-desktop.mjs` 报「退出码 1 却没有输出」 | 多半是单实例锁；先关掉桌面上开着的问心卦（本版本已用独立 user-data-dir 规避，若仍出现请核对是否被改回） |
| `check-desktop.mjs` 几何项失败 | 侧栏被加了项；「六项一屏」是设计约束，加项应当走命令面板 |

## 七、覆盖缺口与补充计划

以下内容是**当前没有自动化覆盖**的，如实列出。

| 缺口 | 现状 | 风险 | 补充方向 |
|---|---|---|---|
| **真浏览器端到端** | `check-web.mjs` 用 DOM 桩；真浏览器只在桌面版自检里被间接覆盖（Electron 的 Chromium 加载同一套 `web/`） | CSS 细节、字体、多浏览器差异、真实事件冒泡 | 用 Electron 的 `--shot` 做视觉回归：对固定 hash 截图并与基线图比对（`main.mjs` 已具备截图能力） |
| **真实模型调用** | Hermes 那套只验「协议编织与解析」「路由与策略」，用的是构造出来的响应；真端点未自动访问 | 各家端点的实际差异、真实 function calling 行为 | 建立手工联调清单：逐家跑一次 `/api/agent/ping` 与一轮完整对话（见 §8.4） |
| **并发写** | `Store.save()` 用「写 `.tmp` → `renameSync`」原子替换，但**无锁**；两个进程同时写同一 id 时后者覆盖前者 | 多实例同时导入可能丢一条 | 加锁文件或写入前比对 mtime；或明确声明「同一时刻只应有一个写者」并写进运维手册 |
| **断电恢复** | 原子改名能避免「半截 JSON」，但 `.tmp` 残留未清理 | 断在 rename 之前会留下 `*.json.tmp` | `loadAll()` 里忽略并清理 `*.tmp` |
| **大数量性能** | 全部自检基于 6 条卦录；未测数千条时的载入、`list()` 排序、`trend` 聚合耗时 | 长期使用（十年、数千条）后可能变慢 | 造 N 条合成数据，测冷启动耗时与 `GET /api/trend` 响应时间 |
| **自定义数据目录下的自检** | 自检不设 `QXG_DATA_DIR`，未覆盖「env 模式」 | 数据目录解析的三个分支只测了 portable | 以 `QXG_DATA_DIR=<临时目录>` 跑一遍 `check.mjs` 与 `check-validate.mjs` |
| **重试与熔断的真实时序** | 策略那 12 项验的是判定函数，未验「真的等了退避时间再重试」 | 退避算法实现与判定不一致 | 注入假时钟，断言重试间隔序列 |
| **卸载与升级** | 无自动化 | 覆盖安装、卸载残留、快捷方式 | 由 §8 手工清单覆盖，并记录每次发布的结果 |
| **MCP 在真实宿主中的行为** | 自检只发原始 JSON-RPC 行 | 宿主侧握手细节、能力协商差异 | 手工清单：在 Codex CLI 与 DSH 里各接一次并调用 `cast` |
| **时区与夏令时** | 历法只按东八区语义与经度换算 | 用户在国外或系统时区非东八区 | 明确声明仅支持东八区语义，并在界面上显示所用时区 |

补计划的原则与项目其余部分一致：**优先补「静默失败」类缺口**（并发写、大数量、`.tmp` 残留、退避时序）——报错型问题用户会发现，静默型不会。
