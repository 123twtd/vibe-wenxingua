# ADR-0013：助手受控联网工具

## 背景

[ADR-0006](./ADR-0006-本地优先默认不出网.md) 把出网路径收敛为一条：「用户显式启用并配置 AI 助手（或外部 agent 经 MCP 调用同一套工具）」，并把「未启用时不发起任何外部请求」定为强制。那条决策成立的前提是——出网的**唯一目的**是把消息发给用户自己填的模型端点。

现在要让助手具备「看得见网页」的能力：用户把一段 DeepSeek 对话链接、笔记链接或任一网页地址交给它，它能把那份内容读回来再据此回答。这一类能力的目的地**不由用户预先填写**，而是由模型在对话中挑出来的。它落在 ADR-0006 那句「唯一路径」之外，因此必须由本 ADR 明确边界，而不是含糊地算作「同一套工具」的一部分。

同时必须承认一个事实：请求是**本机发出去的**。服务监听 `127.0.0.1:19730`，而抓取工具会在用户的机器上对任意外部主机发起连接。这意味着两件事——

1. **对外的风险**：助手可以被诱导去访问本机内网地址、云元数据地址（`169.254.169.254`）或服务自身的接口。这是典型的 SSRF，必须在内核层面挡住，不能靠提示词。
2. **对内的风险**：模型拼进请求 URL 或请求头的内容会离开本机。大多数情况下那只是用户给的链接，但模型**可以**把自己上下文里的片段拼进去（例如把卦录正文当查询参数）。这条泄露路径必须写明，而不是当作不存在。

## 决策

1. 助手**可以**具备联网抓取能力，但它**必须**由一个**受控的工具来源**提供，与内置工具走同一套权限与确认闸门，**不得**绕过 `createToolkit()` 另起通道。
2. 联网工具**必须**默认在工具表里（用户已明确此取向），但**每一次调用都必须经过用户确认**才真正发起请求。确认语义与「破坏性操作」**分开**：破坏性说的是「会改动你的数据」，联网说的是「会访问外部网址」，界面上的措辞与着色**不得**混为一谈。
3. 抓取**必须**遵守以下边界，任一不满足即拒绝并给出可读理由：
   - 只允许 `http` 与 `https`；
   - **先解析主机名、再校验解析出的地址**，之后才发起连接；
   - **逐跳校验重定向**，并设重定向上限；
   - 拒绝回环、私有网段、链路本地与云元数据地址；
   - 有超时与响应体积上限；只接受文本类 `content-type`。
4. 用户**可以**在 `data/config.json` 的 `agent.web` 里配置 `allow` / `deny` 域名表与开关；默认 `allow` 与 `deny` 都为空（即「不按域名预筛，但每次都要确认」）。
5. 本 ADR **取代** ADR-0006 中「唯一的出网路径」这一表述：出网路径由一条变为两条——**模型接口**与**受控联网工具**，两者都**必须**由用户显式启用，且都**不得**在未启用时发生。ADR-0006 的其余决策（不回显 Key、监听回环、不内建同步、不上传数据目录）**继续有效，一字不改**。
6. MCP 侧没有界面可以弹确认框。联网工具**可以**经 MCP 暴露，但调用方**必须**显式带 `confirm: true` 才执行；否则只得到「需要确认」的结构化响应，由调用方自行转达。这条限制**必须**写进 [Agent 设计文档](../05-Agent设计文档.md) 与 [安全与隐私设计](../11-安全与隐私设计.md)。

## 理由

1. **能力本身就是需求。** 「把一段链接的内容读回来」是这个助手最实际的一类用法（用户要整理的正是 DeepSeek 对话与笔记）。没有它，助手只能处理用户手打进来的文本。
2. **把确认粒度提到「每次调用」而不是「一次开关」。** 一个总开关的问题是：开了之后，之后每一次出网都不再有摩擦，用户也就不会再注意它在做什么。逐次确认把「你同意这一次」变成习惯动作，代价是烦一点——这是刻意的取舍。
3. **确认语义必须与破坏性分开。** 两者后果不同（改数据 vs 出网）、应对方式也不同（可从回收目录恢复 vs 内容已经发出去、不可撤回）。合并成一个「危险操作」标签会让用户误以为联网也能撤回。
4. **SSRF 必须在内核挡。** 提示词能描述规则，但挡不住精心构造的输入；而这一条一旦漏，程序就成了「本机任意端口探测器」。所以校验写在 `agent/sources.mjs` 里，并由 `check.mjs` 断言——与「卦象只能由引擎算」同一个思路：关键约束放在代码里，不放在模型的自觉上。
5. **ADR 的规矩是自己定的。** 既然定了「ADR 正文一经接受不可改写，只能新增一篇取代」，那么改口径就得付一篇新 ADR 的成本。本 ADR 明确写「取代范围仅一条」，是为了避免以后的人误以为 ADR-0006 整体失效。

## 后果

### 正面

- 助手能处理用户粘贴的链接，这是它此前做不到的一整类任务。
- 出网行为有两道明确的闸门（开关 + 逐次确认），且每一次调用都会在对话轨迹里留下一张可回看的工具卡。
- SSRF 守卫与体积/超时上限让它不会被用作内网探测器或内存放大器。
- 工具来源是**可插拔**的一层：以后接搜索、接各家 SDK、接更多 MCP 实现，都往这一层加，不改内核。

### 负面

- **外发内容不可控。** 模型拼进 URL 或请求头的文本会离开本机，可能包含卦录片段。程序能做的是「每次确认时把完整 URL 显示给人看」，做不到内容级别的审查。
- **逐次确认很烦。** 一次需要读三个链接的任务要确认三次。缓解方式是让确认卡显示目标主机与完整地址，使人能一眼判断——但不是减少确认次数。
- **出网范围从「一个用户填的端点」变成「任意用户点过同意的地址」。** 审计成本上升：以前看 `PROVIDERS` 与 `resolveConfig()` 就够，现在还要看 `agent/sources.mjs` 的守卫与白名单逻辑。
- **DNS 解析与实际连接之间存在窗口。** 「先解析再校验」挡不住严格的 DNS rebinding（解析后地址变化）。零依赖前提下不引入自定义 lookup 就做不到完全严密；当前取舍是挡住已解析到的私有地址，并把这一残余风险写在这里。
- **抓回来的内容是不可信输入。** 网页里可以写「忽略你之前的指令」。程序不解析、不执行，只是把文本交给模型——但提示注入的残余风险由使用者承担，这一点在 [安全与隐私设计](../11-安全与隐私设计.md) 里写明。

## 备选方案与为何不选

| 方案 | 为什么没选 |
|---|---|
| 由界面代抓，模型只读结果 | 效果与现在相同（仍是本机出网），却多一条前端通道，且外部 agent 经 MCP 时用不上。 |
| 用一个总开关，开了就不再逐次问 | 摩擦小，但把「知情」退化成「一次点击」。用户明确要的是每次确认。 |
| 把联网工具标成「破坏性工具」以复用确认机制 | 会让界面把它显示成破坏性工具、污染语义，也与本 ADR 第 2 条冲突。因此改为给确认机制加独立的「需确认原因」字段。 |
| 只允许 `allow` 白名单里的域名 | 最安全，但用户第一次用就得先去配置里填域名，等于给一个简单需求加一道前置作业；空白名单 + 逐次确认在体验与安全之间更平衡。 |
| 引入第三方 HTTP 客户端以获得可控 DNS | 破坏「零第三方依赖」这条立项前提（[ADR-0001](./ADR-0001-零第三方依赖.md)）。残余风险改写进本 ADR 的负面一栏。 |
| 联网工具不暴露给 MCP | 最保守，但会让「外部 agent 也能读链接」这一实际用法消失；改为要求 MCP 调用方显式带 `confirm: true`。 |
