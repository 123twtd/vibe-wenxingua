## 一、插件模型

### 1.1 一个 `.mjs` 文件就是一个插件

| 项 | 规定 |
|---|---|
| 位置 / 扩展名 | `<数据目录>\plugins\`（安装态即 `%APPDATA%\问心卦\data\plugins\`；开发态即项目里的 `data\plugins\`）；**必须**是 `.mjs`——宿主只扫描 `.mjs`，其它扩展名会被忽略 |
| 模块制式 / 插件 id | ES 模块（`export default {…}`），由宿主用 `import()` 动态载入；id 默认取**文件名去掉 `.mjs`**，若导出对象里写了 `id` 则以 `id` 为准 |
| 导出形状 / 必需成员 | `export default { id, name, version, description, author, activate(ctx) }`，也接受 `export const plugin = {…}`（宿主取 `mod.default \|\| mod.plugin`）；只有 `activate` 必须存在且是函数，缺了会记一条错误并跳过该文件 |
| 元信息默认值 | `name` 缺省用 `id`，`version` 缺省 `"0.0.0"`，`description`／`author` 缺省空串 |

最小可运行插件：

```js
// <数据目录>/plugins/hello.mjs
export default {
  id: 'hello', name: '你好插件', version: '1.0.0',
  activate(ctx) { ctx.log('你好，问心卦。'); },
};
```

### 1.2 加载过程

```
reset()                                   清空上一轮的全部注册与错误
  ↓ readdir(plugins/) 过滤 *.mjs，对每个文件：
enabled = config.plugins[id].enabled !== false      ← 未配置即视为启用
  ├─ false → 记入插件列表（loaded:false），跳过
  └─ true  → import(file + '?t=' + Date.now())      ← 缓存破坏，热载才会真的重新求值
             def = mod.default || mod.plugin
             def.activate 不是函数 → errors.push(...)，跳过
             构造 meta 与 ctx → await def.activate(ctx)
             成功 → 登记该插件；抛错 → errors.push(`${file}：${err.message}`)，该插件不注册任何东西
  ↓ routes.sort(路径长的在前)                ← 决定匹配优先级
emit('app.start', { at })                   ← 每次 loadAll 都会发，包括热载
返回 api()                                  ← 给界面用的清单
```

三个必须知道的特性：

1. **缓存破坏（`?t=Date.now()`）意味着热载会重置模块级状态。** 写在模块顶层的计数器、缓存、`Map` 都会重新初始化。需要跨热载保留的东西请落到 `ctx.store`（卦录）或 `config.json`。
2. **`loadAll()` 先 `reset()`。** 上一轮注册的路由／页面／面板／导出器／事件钩子全部作废并重建，不会残留在内存里——所以**改插件不需要重启进程**。
3. **一个插件抛错不影响别的插件。** 错误被收进 `api.errors`，其它插件照常载入，主界面照常可用。

### 1.3 热载

| 方式 | 操作 |
|---|---|
| 界面 | 「插件」页 → **「热载全部插件」** |
| HTTP | `POST /api/plugins/reload` |
| 启停 | `POST /api/plugins/<id>/toggle`，body `{ "enabled": false }`（内部也会重新 `loadAll()`） |

```bash
curl -X POST http://127.0.0.1:19730/api/plugins/reload
```

**改了插件文件就必须热载（或重启）**，Node 不会自动重读已载入的模块。

### 1.4 插件清单与状态

`GET /api/plugins` 返回 `{ ok, plugins, pages, exporters, panels, errors, dir }`：

| 字段 | 含义 |
|---|---|
| `plugins[]` | 每项：`id`、`name`、`version`、`description`、`author`、`enabled`、`loaded`、`pages[]`、`panels[]`、`exporters[]`、`routes[]`（形如 `"GET /api/plugins/x/y"`） |
| `pages[]` | 已注册页面（全局），按 `order` 升序，含 `pluginId` 与 `url` |
| `exporters[]` / `panels[]` | 已注册的导出格式与详情页面板 |
| `errors[]` | **载入错误清单**，形如 `"<文件名>：<错误信息>"` |
| `dir` | 插件目录的绝对路径 |

同一份数据也并入 `GET /api/meta` 的 `plugins` 字段，界面侧栏就靠它生成插件页入口。

## 二、完整 API 参考：`activate(ctx)`

`ctx` 由 `PluginHost.makeContext(meta, def)` 构造，每个插件实例一份。全部成员如下；`id`／`plugin`／`def` 分别是插件 id、运行时元信息（含 `file`、`loaded`、`pages` 等，宿主会继续填充）与导出的原始对象本身。

### 2.1 `ctx.registerRoute(method, subPath, handler)`

| 参数 | 类型 | 说明 |
|---|---|---|
| `method` | string | HTTP 方法，大小写不敏感（内部 `toUpperCase()`） |
| `subPath` | string | 相对路径。**不要**写 `/api/plugins/<id>/`，宿主会自动加；开头的 `/` 会被剥掉 |
| `handler` | function | 收到的是**路由 ctx**（见 §4），不是本节的 `ctx` |
| 返回 | — | 无返回值（宿主内部把条目压进 `routes` 与 `meta.routes`） |
| 最终路径 | — | `/api/plugins/<插件id>/<subPath>` |

```js
ctx.registerRoute('GET', 'hello', ({ json, store }) => json({ ok: true, count: store.list().length }));
// → GET /api/plugins/hello/hello
```

**注意**：路由按**路径长度降序**匹配，长路径优先；插件路由**先于**内置路由匹配；支持尾部 `/*` 通配，命中时 `params` 里给 `rest`。

### 2.2 `ctx.registerPage({ id, label, icon, order, render })`

| 参数 | 默认 | 说明 |
|---|---|---|
| `id` | — | 页面 id，在**同一插件内**唯一 |
| `label` | — | 侧栏与页面标题显示名 |
| `icon` | `'◇'` | 单字符图标 |
| `order` | `100` | 排序权重，小的在前（官方插件用 20／30） |
| `render` | — | `({ store, core, url }) => string \| { html?, title?, data? }` |
| 返回 | — | 页面对象，含 `url: '/api/plugins/<id>/page/<pageId>'` |
| 前端 URL | — | `#/plugin/<插件id>/<页面id>` |

```js
ctx.registerPage({
  id: 'main', label: '我的面板', icon: '◆', order: 50,
  render: ({ store }) => ({ html: `<p>共 ${store.list().length} 条卦录</p>` }),
});
```

**注意**：返回值是字符串时当 HTML 整页返回；是对象时，宿主包成 `{ ok: true, page: { id, label, ...out } }`。`render` 抛错**不会**让服务崩——路由有 try/catch，返回 400，界面把错误显示在页面卡片里。

### 2.3 `ctx.registerPanel({ id, label, order, render })`

| 参数 | 默认 | 说明 |
|---|---|---|
| `id` / `label` / `order` | `order=100` | 同 `registerPage`；`label` 是面板标题（`label` 为空而 `render` 返回对象里带 `title` 时，用 `title`） |
| `render` | — | `({ record, store, core }) => object`；**`record` 是完整卦录对象** |
| 返回 | — | 面板对象 |

```js
ctx.registerPanel({
  id: 'note', label: '我的批注', order: 10,
  render: ({ record }) => ({ html: `<p>本卦 ${record.chart.ben.fullName}</p>` }),
});
```

**注意**：面板渲染成卦录详情页里的一张卡片（服务端渲染 HTML 片段），返回 `{ html }` 最常用；`render` 抛错时宿主塞一块写有「插件面板出错：…」的 HTML，**不会**影响卦录本身与其它面板。

### 2.4 `ctx.registerExporter({ id, label, ext, mime, render })`

| 参数 | 默认 | 说明 |
|---|---|---|
| `id` | — | 格式名，**就是 `?format=` 的取值** |
| `label` | — | 界面显示名 |
| `ext` | — | 文件扩展名（不带点），用于下载文件名 |
| `mime` | `'text/plain; charset=utf-8'` | 响应的 Content-Type |
| `render` | — | `(record, { core }) => string \| Buffer` |

```js
ctx.registerExporter({
  id: 'my-fmt', label: '我的格式', ext: 'txt',
  render: (rec, { core }) => core.render.toSlip(rec),
});
```

**访问方式**：`GET /api/records/<id>/export?format=<id>`。
**注意**：**插件导出器优先于内置格式。** 若把 `id` 取成 `md`／`slip`／`json`，会**覆盖内置的同名格式**——除非你确实想这么做，否则请换个 id。

### 2.5 `ctx.store` —— 存储与配置

就是 `server/store.mjs` 的 `Store` 实例，**与内置功能共用同一份内存缓存与写盘路径**。

| 方法 | 签名 | 说明 |
|---|---|---|
| `list()` | `() => Record[]` | 全部卦录，按起卦时间倒序 |
| `get(id)` / `has(id)` / `ids()` | | 单条／是否存在／全部 id |
| `save(record)` | `(record) => Record` | **落盘**（写 `.tmp` 再 `renameSync`，原子替换） |
| `remove(id, hard)` | `(id, hard=false) => boolean` | 默认软删到 `trash/`；`hard=true` 才真删 |
| `getConfig()` / `setConfig(patch)` | | 读配置（已补默认值）／浅合并并写盘 |
| `stats()` / `backup()` / `restore(pack, {merge})` | | 计数摘要／整包备份／恢复备份 |
| `root` `recordsDir` `trashDir` `backupDir` | string | 目录绝对路径（只读） |

```js
ctx.registerPage({
  id: 'count', label: '计数',
  render: ({ store }) => ({ html: `<p>${store.list().length} 条</p>` }),
});
```

> ⚠️ `save()` 与 `remove()` 会**直接改用户的卦录**。见 §9.2。

### 2.6 `ctx.core` —— 全部内核

与内置功能同一批模块实例（不是副本），所以永远与主程序同版本、同行为。

| 键 | 模块 | 常用成员 |
|---|---|---|
| `core.divination` | `core/divination.mjs` | `cast(input)`、`METHODS`、`inferMovingFrom()` |
| `core.verdict` | `core/verdict.mjs` | `interpret(chart)`、`CATEGORIES` |
| `core.hexagram` | `core/hexagram.mjs` | `library()`（`all()`／`stats()`／`yaoText()`）、`sixLines()`、`trigramsOfLines()` |
| `core.calendar` | `core/calendar.mjs` | `calendarInfo()`、`dayGanZhi()`、`julianDay()`、`PLACES` |
| `core.record` | `core/record.mjs` | `buildRecord()`、`buildFromHexagram()`、`normalizeRecord()`、`recompute()`、`summarize()`、`makeId()`、`REVIEW_STATUS` |
| `core.render` | `core/render.mjs` | `toMarkdown()`、`toSlip()`、`toIndexMarkdown()` |
| `core.importer` | `core/importer.mjs` | `parseMany(text)` |
| `core.guaTiao` | `core/guaTiao.mjs` | `template()`、`parseGuaTiao()`、`parseGuaTiaoMany()`、`toGuaTiao()`、`FIELD_ALIASES` |
| `core.trend` | `core/trend.mjs` | `buildTrend(records, opts)`、`trendSummary()`、`DOMAINS` |
| `core.schema` | `core/schema.mjs` | `validate(obj, schema, { strict })`、`firstError()` |
| `core.migrate` | `core/migrate.mjs` | `CURRENT_SCHEMA`、`migrate()`、`migrateAll()` |
| `core.bagua` | `core/bagua.mjs` | 八卦、五行生克、旺衰、爻位 |

**硬规矩（继承自项目根 `AGENTS.md`）：卦象只能由引擎算。** 不得在插件里手写卦名、卦符、爻辞、体用生克、动爻、旺衰——一律走 `core.divination.cast()`，或从 `record.chart` 读现成快照。

### 2.7 `ctx.config` / `ctx.log` / `ctx.warn`

| 成员 | 说明 |
|---|---|
| `ctx.config` | `store.getConfig()` 在 `activate()` 时的**快照**。之后要最新值请用 `ctx.store.getConfig()` |
| `ctx.log(...args)` | 走宿主 `logger.log`（`console.log`），自动加 `[<插件id>]` 前缀 |
| `ctx.warn(...args)` | 走宿主 `logger.warn`（`console.warn`），同样加前缀 |

```js
activate(ctx) {
  const place = ctx.config.defaultPlace;      // 快照
  const theme = ctx.store.getConfig().theme;  // 最新
}
```

**注意**：桌面版的日志进 `%APPDATA%\wenxingua-desktop\desktop.log`；**不要**在插件里直接用 `console.log` 打业务日志——加了前缀才认得出是谁打的。

### 2.8 `ctx.assetsDir`

| 项 | 内容 |
|---|---|
| 类型 | string，绝对路径：`path.join(<数据目录>/plugins, <插件id>)` |
| 用途 | 存放本插件的静态资源（CSS／JS／图片／模板） |
| 对应 URL | `/plugin-assets/<插件id>/<相对路径>`（见 §5） |
| 注意 | **宿主管家不会替你创建这个目录**。要放资源就自己建（插件里可以 `import fs from 'node:fs'`，宿主不限制） |

```js
import fs from 'node:fs';
import path from 'node:path';

activate(ctx) {
  fs.mkdirSync(ctx.assetsDir, { recursive: true });
  fs.writeFileSync(path.join(ctx.assetsDir, 'style.css'), '.x{color:gold}', 'utf8');
}
```

## 三、事件清单

事件由宿主的 `PluginHost.emit(event, payload)` 触发，**同步顺序执行，无返回值**。

| 事件 | 触发时机 | 载荷结构 |
|---|---|---|
| `app.start` | **每次 `loadAll()` 之后**（启动与每次热载都会发） | `{ at: string }` —— `at` 是 ISO 时间字符串 |
| `record.created` | 新卦录落盘之后。触发点：`POST /api/records`、`POST /api/import/commit`、agent 工具 `save_record`／`save_gua_tiao` | **完整卦录对象**（含 `id`、`chart`、`reading`、`cast`、`review` …） |
| `record.updated` | 卦录被修改之后。触发点：`PATCH /api/records/:id`、`POST /api/records/:id/recompute` | **更新后的完整卦录对象** |
| `record.deleted` | 卦录被删除之后（软删与硬删都发） | `{ id: string }` —— **只有 id**，不是完整对象 |
| `cast.preview` | `POST /api/cast` 试起一卦成功之后（**不入库**） | `{ chart, reading }` —— 卦局快照与断语快照 |
| `agent.reply` | `/api/agent/chat` 一轮对话结束之后 | `{ reply: string, rounds: number }` —— `rounds` 是本次循环用掉的轮数 |

```js
activate(ctx) {
  ctx.on('app.start', ({ at }) => ctx.log('插件随宿主就绪于', at));

  ctx.on('record.created', (rec) => {
    // rec 是完整卦录：rec.chart.ben.fullName、rec.reading.grade.label 都能直接用
    ctx.log(`新卦录 ${rec.id}：${rec.chart.ben.fullName}　${rec.reading.grade.label}`);
  });

  ctx.on('record.updated', (rec) => ctx.log(`卦录 ${rec.id} 已更新`));
  ctx.on('record.deleted', ({ id }) => ctx.log(`卦录 ${id} 已删除`));
  ctx.on('cast.preview', ({ chart }) => ctx.log(`有人试起了${chart.ben.fullName}`));
  ctx.on('agent.reply', ({ reply, rounds }) => ctx.log(`助手回复 ${reply.length} 字，用了 ${rounds} 轮`));
}
```

**注意**：

- `record.deleted` 的载荷只有 `{ id }`。想在删除时留一份内容，必须在 `record.created`／`record.updated` 时自己缓存。
- **异常不会回滚。** 事件在数据已落盘之后才发；handler 抛错只记一条 warn，**不会**撤销那次写入。
- handler 返回 Promise 时宿主会挂 `.catch`，但**不会 await**——异步 handler 不阻塞触发它的那次请求。

## 四、路由处理器的 `ctx`

`registerRoute` 的 `handler` 收到的是另一套 ctx（由 `server/index.mjs` 构造）：

| 成员 | 签名 | 说明 |
|---|---|---|
| `json(data, code = 200)` | | 返回 JSON（缩进 2 空格） |
| `send(body, code = 200, headers = {})` | | 底层发送；`body` 可以是字符串或 Buffer |
| `html(body, code = 200)` | | `text/html; charset=utf-8` |
| `text(body, code = 200)` | | `text/plain; charset=utf-8` |
| `readBody(limit?)` | `async (limit = 32MB) => object` | 读请求体并 `JSON.parse`；不是合法 JSON 时返回 `{ _raw: '原文' }`；超限抛错 |
| `query(k)` | `(name) => string \| null` | 取查询参数 |
| `params` | object | 路径参数；当前只有通配路由会填 `{ rest }` |
| `store` / `core` | | 同 §2.5／§2.6 |
| `req` / `res` / `url` / `plugins` | | 原始 Node 对象（`url` 是 `URL` 实例）与宿主本体；一般不需要动 |

**返回值约定**：返回 `false` 表示「我自己处理完了」（宿主不再补响应）；返回其它值（含 `undefined`）且响应尚未结束时，宿主补发 `{ "ok": true }`。最常见的写法是直接用 `json(...)` 返回，此时响应已结束，宿主不会再补。

```js
ctx.registerRoute('POST', 'note', async ({ readBody, query, json, store }) => {
  const body = await readBody();
  const rec = store.get(query('id'));
  if (!rec) return json({ ok: false, error: '未找到该卦录' }, 404);
  json({ ok: true, title: rec.title, note: body.note || '' });
});
```

**路由匹配顺序（重要）**：主处理流程是 → 「外部改动重扫」→ **插件路由** → **插件静态资源 `/plugin-assets/`** → **内置路由** → 静态界面。所以插件路由无法遮蔽 `/api/meta` 这类内置接口（插件路由一律挂在 `/api/plugins/<id>/` 下），但**同一插件内**长路径优先于短路径。

## 五、静态资源：`/plugin-assets/<id>/…`

| 项 | 规定 |
|---|---|
| URL 形状 | `/plugin-assets/<插件id>/<相对路径>` |
| 落盘位置 | `<数据目录>\plugins\<插件id>\<相对路径>`（即 `ctx.assetsDir`） |
| 需要自己建目录 | **是**。宿主只保证 `plugins/` 存在 |
| MIME | 按扩展名映射：`.html` `.js` `.mjs` `.css` `.json` `.svg` `.png` `.woff2` `.md` `.txt`；其它一律 `application/octet-stream` |
| 缓存头 | `Cache-Control: no-cache`（改完刷新即可生效） |
| 目录穿越 | 被显式拦截：解析后的绝对路径若不以插件目录开头，返回 **403 forbidden** |
| 找不到 | 返回 404 |

```js
ctx.registerPage({
  id: 'rich', label: '带样式的页', order: 60,
  render: () => ({
    html: `<link rel="stylesheet" href="/plugin-assets/rich/style.css">
           <div class="x">这段样式来自本插件自己的目录。</div>`,
  }),
});
```

> 静态资源与「热载」无关：它们是**每次请求现读磁盘**的，改完 CSS 刷新页面就变；只有 `.mjs` 的**代码**需要热载。

## 六、三个官方示例插件逐行讲解

三个插件都在 `<数据目录>\plugins\` 下，随 `seed-data` 一起分发。它们不是玩具——是你写插件时最可靠的参考。

### 6.1 `html-card.mjs` —— 单卦 HTML 卡片（演示 `registerExporter`）

| 段 | 内容 | 要点 |
|---|---|---|
| `ESC(s)` | HTML 转义 `&` `<` `>` `"` | **凡是要拼进 HTML 的用户数据都必须过它**。标题、所问、原文全是用户输入 |
| `liuyaoHtml(chart)` | 六爻图（HTML 版） | 由 `chart.lines[i-1] === 1` 判阴阳、`chart.moving.position` 判动爻、`tiyong.tiRange`／`yongRange` 判体用归属——**全部取自卦局快照，不重新计算** |
| `hexBox(role, hx)` | 本／互／变三卦的卦符、卦名、卦德、吉凶 | 用 `hx.symbol` 与 `hx.fullName`，同样是引擎算出来的 |
| `REL_GLYPH` | 体用关系 → 图示（如 `体 ▸克▸ 用`） | 按 `relation.key` 查表，避免在模板里写 if |
| `buildHtml(rec)` | 组装整份 HTML | 依次渲染：谶语、七段定调、通俗解、古辞佐证、校勘、复盘、起卦推演与历法；样式全部内联在 `<style>` 里 |
| `activate(ctx)` | 注册导出器 + 订阅事件 | 见下 |

```js
activate(ctx) {
  ctx.registerExporter({
    id: 'html-card', label: '单卦 HTML 卡片（离线单文件）', ext: 'html',
    mime: 'text/html; charset=utf-8', render: (rec) => buildHtml(rec),
  });
  ctx.on('record.created', (rec) => ctx.log(`卦录 ${rec.id} 可导出为 HTML 卡片`));
}
```

**关键取舍**：导出的 HTML **不依赖本程序、不依赖网络**（字体走系统字体栈）——即使十年后问心卦跑不起来，这份文件双击就能看。这是「卦录要陪几十年」这一取向的兜底。
**可以照它学**：怎么把卦录安全地变成一份独立文档；`esc()` 的必要性；如何只读地消费 `chart`／`reading` 快照而不碰 `cast`。

### 6.2 `review-watch.mjs` —— 应期提醒（演示 `registerPage` + `registerPanel` + `on` + `store`）

| 段 | 内容 | 要点 |
|---|---|---|
| `WINDOW_DAYS` / `WINDOW_TEXT` | 动爻之位（1–6）→ 应期天数／文案：`10 / 30 / 90 / 120 / 180 / 365` 天 | 与断语引擎的口径一致，取上限 |
| `daysSince(localTime)` | 从 `YYYY-MM-DD HH:mm` 算已过天数 | 正则抽出年月日，**不依赖时区解析**；解析不出返回 `null`（宁可不算，不猜） |
| `due(record)` | 核心：算某条卦录的应期进度 | 读 `chart.moving.position` 与 `cast.localTime`；体卦旺／相则窗口折为六成（`factor = 0.6`，与断语引擎同一取舍）；返回 `{ limit, limitText, elapsed, remaining, overdue, ratio }`；缺动爻或时间返回 `null` |
| `registerPage({ id:'due', order:20 })` | 「应期提醒」页（经侧栏底部的插件组或命令面板进入） | 取 `review.status` 为「待应验／应验中」的卦，算 `due`，按 `ratio` 降序排，分成「应期已至」「应期将近（≥0.7）」「尚在期中」三组渲染 |
| `registerPanel({ id:'due', order:30 })` | 每条卦录详情页的「应期」面板 | 「起卦至今 N 天；应期本主〈…〉，按体气折为 M 天」＋一条进度条；缺数据时给出说明文字而不是空白 |
| `ctx.on('record.created', …)` / `esc(s)` | 新卦录入库时打一行日志；局部转义函数 | 用 `ctx.log` 而不是 `console.log`；每个需要拼 HTML 的插件都该有转义函数 |

**关键取舍**：

- **插件可以只做「读」。** 它完全不写数据，只做筛选与提醒——这是最安全、也最有用的一类插件。
- **算法口径要与内核一致。** 窗口天数与「体旺则提前」都刻意对齐了断语引擎；插件另立一套口径会让用户看到互相矛盾的说法。
- **数据不全时不猜。** `daysSince` 解析失败或缺动爻时返回 `null`，页面显示「无法推算应期」，而不是拿默认值算一个假结果。

### 6.3 `stats-plus.mjs` —— 卦气统计（演示 `registerRoute` + `registerPage`）

| 段 | 内容 | 要点 |
|---|---|---|
| `ELEMENTS` / `ELEMENT_COLOR` / `GRADES` | 五行与吉凶等级的常量表 | 等级序列与断语引擎一致（大吉／吉／中吉／平／小凶／凶） |
| `tally(records, pick)` / `cross(records, rowPick, colPick)` | 通用计数与二维交叉表 | 取不到键就跳过；用于「五行 × 吉凶」 |
| `analyze(store)` | **全部统计逻辑集中在这里** | 返回 `{ total, byElement, byRelation, byGrade, crossElementGrade, avgByElement, timeline }`；`timeline` 按 `cast.localTime` 升序，每项含 `id`／`time`／`element`／`score`／`grade`／`ben`／`title` |
| `ctx.registerRoute('GET','trend', …)` | 自注册接口 `GET /api/plugins/stats-plus/trend` | 处理器只有一行：`json({ ok: true, data: analyze(store) })` |
| `ctx.registerPage({ id:'trend', order:30 })` | 「卦气统计」页 | 三张卡片（体卦五行／体用关系／总评分布）用横向条；一张「五行 × 吉凶交叉」表；一段「卦气走势」用竖柱——每柱一卦，柱高映射 `score`，柱下字是体卦五行。页面里写明「其数据接口为 `GET /api/plugins/stats-plus/trend`，可被别的程序取用」——**插件加的不只是界面，也是接口**，这是本插件最值得学的一点 |

**关键取舍**：

- **统计逻辑与渲染分离**（`analyze` 独立于 `render`）：同一份计算既供页面用，也供 HTTP 接口用，还能被别的程序取用。
- **柱高映射要归一**：`Math.max(6, Math.round((t.score + 100) / 2))` 把 −100~+100 映射到 0~100 的高度百分比，并留 6% 下限，避免负分时柱子消失。
- **界面上写清数据来源与接口地址**，让使用者知道这一页是谁提供的、数据从哪来。

## 七、开发流程：新建 → 热载 → 调试

### 7.1 五步走

| 步 | 做什么 |
|---|---|
| 1 | 在 `<数据目录>\plugins\` 下新建 `<你的id>.mjs` |
| 2 | 写 `export default { id, name, version, activate(ctx) {…} }` |
| 3 | 到「插件」页点 **「热载全部插件」**（或 `POST /api/plugins/reload`） |
| 4 | 看「插件」页：是否出现在「已装插件」里、状态是否「已载入」、有没有错误 |
| 5 | 打开你的页面 `#/plugin/<你的id>/<页面id>`；面板去任意卦录详情页看 |

### 7.2 调试手段

| 手段 | 用法 |
|---|---|
| `ctx.log` / `ctx.warn` | 打日志，自动带 `[<插件id>]` 前缀；命令行版看服务终端，桌面版看 `%APPDATA%\wenxingua-desktop\desktop.log` |
| 「插件」页的 **载入错误** 区 | 载入期错误（语法错、`activate` 抛错、缺 `activate`）都在这里 |
| `GET /api/plugins` 的 `errors` 数组 | 同上，机器可读 |
| 自注册接口 | 把中间数据用 `registerRoute` 暴露出来（`curl http://127.0.0.1:19730/api/plugins/<id>/<path>`），比在页面里猜快得多。**`stats-plus` 就是这么做的** |
| 页面 JSON | `curl "http://127.0.0.1:19730/api/plugins/<id>/page/<pageId>"` 直接看 `html` 字段 |
| 面板错误 | 面板渲染抛错时那一块显示「插件面板出错：…」，其它面板与卦录本身不受影响 |

### 7.3 出错时的三种典型症状

| 症状 | 原因 | 处理 |
|---|---|---|
| 插件在列表里但状态「未载入」，`errors` 有一条 | 语法错、`activate` 抛错、或没导出 `activate` | 按错误信息改；改完重新热载 |
| 已载入但侧栏没有新页面 | `registerPage` 没被调用（写在某个提前 `return` 之后），或在 `await` 之后才执行 | 注册动作**应当**在 `activate` 里同步完成；需要异步准备的数据放到 `render` 里再取 |
| 页面能打开但没有内容 | `render` 返回 `undefined`，或返回对象里没有 `html` | `render` **必须**返回字符串或 `{ html }`；返回 `{ data }` 时前端会把 JSON 原样打印出来 |

### 7.4 一条容易踩的坑：注册顺序

`loadAll()` 里是 `await def.activate(ctx)`，所以异步 `activate` 是允许的；但页面与路由的注册时机决定 `GET /api/meta` 里 `pages` 的内容（最终按 `order` 升序）。**若在 `await` 之后才注册页面，热载期间可能出现短暂的「页面不存在」**——所以推荐把注册放在 `activate` 最前面，同步写完。

## 八、从零写一个插件：按类别统计并画柱状图

### 8.1 需求拆解

| 需求 | 用什么扩展点 |
|---|---|
| 侧栏出现「类别统计」页 | `ctx.registerPage` |
| 竖柱状图 | 页面 HTML（零依赖，div + 百分比高度） |
| 每类卦数与平均分 | `ctx.store.list()` + 读 `chart.score.total` |
| 数据可被别的程序取用 | `ctx.registerRoute` |
| 新增卦录时打一行日志 | `ctx.on('record.created', …)` |

### 8.2 完整代码

保存为 `<数据目录>\plugins\category-bars.mjs`（安装态即 `%APPDATA%\问心卦\data\plugins\category-bars.mjs`）。

```js
/**
 * 插件：类别统计（category-bars）
 * 演示 registerPage + registerRoute + on + store。本插件只读，不写任何数据。
 */
const BAR_AREA_PX = 140;               // 柱状图绘图区高度
/** HTML 转义：凡是要拼进 HTML 的用户数据都必须过这里 */
function esc(s) {
  return String(s ?? '').replace(/&/g, '&amp;').replace(/</g, '&lt;')
    .replace(/>/g, '&gt;').replace(/"/g, '&quot;');
}
/** 统计与渲染分离：同一份结果既给页面用，也给接口用 */
function analyze(store) {
  const records = store.list();
  const groups = new Map();
  for (const rec of records) {
    const key = rec.category || '未分类';
    if (!groups.has(key)) groups.set(key, { category: key, count: 0, scores: [], good: 0 });
    const g = groups.get(key);
    g.count += 1;
    const score = rec.chart?.score?.total;
    if (typeof score === 'number') {
      g.scores.push(score);
      if (score > 0) g.good += 1;      // 正分计为「偏吉」，只用于展示
    }
  }
  const rows = [...groups.values()].map((g) => ({
    category: g.category, count: g.count, good: g.good,
    avg: g.scores.length
      ? Math.round((g.scores.reduce((a, b) => a + b, 0) / g.scores.length) * 10) / 10
      : null,
  })).sort((a, b) => b.count - a.count || a.category.localeCompare(b.category, 'zh'));
  return { total: records.length, max: Math.max(1, ...rows.map((r) => r.count)), rows };
}
/** 竖柱状图：每根柱子 = 一个类别 */
function columnChart(data) {
  if (!data.rows.length) return '<div class="empty"><div class="big">▥</div>还没有卦录，先去起一卦。</div>';
  return data.rows.map((r) => {
    const h = Math.max(6, Math.round((r.count / data.max) * 100)); // 6% 下限，免得矮柱看不见
    return `<div style="display:inline-block;width:64px;text-align:center;margin:0 6px 10px 0;vertical-align:bottom">
      <div class="small dim" style="font-size:11px">${r.count}</div>
      <div style="height:${BAR_AREA_PX}px;display:flex;align-items:flex-end">
        <i style="display:block;width:100%;height:${h}%;border-radius:4px 4px 0 0;
                  background:linear-gradient(180deg,var(--gold-2,#e8c86a),#7d6418)"></i>
      </div>
      <div class="small" style="margin-top:6px;word-break:break-all">${esc(r.category)}</div>
    </div>`;
  }).join('');
}
/** 明细表：补上柱状图看不出的平均分 */
function table(data) {
  if (!data.rows.length) return '';
  return `<table class="md-table"><thead><tr>
      <th>类别</th><th>卦数</th><th>占比</th><th>正分卦</th><th>平均总分</th>
    </tr></thead><tbody>${data.rows.map((r) => `<tr>
      <td>${esc(r.category)}</td><td>${r.count}</td>
      <td>${data.total ? Math.round((r.count / data.total) * 100) : 0}%</td>
      <td>${r.good}</td><td>${r.avg === null ? '·' : r.avg}</td>
    </tr>`).join('')}</tbody></table>`;
}
function pageHtml(data) {
  return `
    <div class="card"><div class="card-title">类 别 分 布（共 ${data.total} 条）</div>
      <div style="overflow-x:auto;white-space:nowrap;padding:6px 0">${columnChart(data)}</div>
      <div class="small dim">柱高为该类别的卦数；柱顶数字是卦数，柱下字是类别。</div></div>
    <div class="card"><div class="card-title">类 别 明 细</div>
      ${table(data) || '<div class="small dim">无数据。</div>'}
      <div class="small dim" style="margin-top:8px">「平均总分」为该类别各卦总评分的算术平均（量程 −100 ~ +100）。
        样本少时这个数意义不大，看趋势要等卦录攒起来。</div></div>
    <div class="card tight"><div class="small dim">
      本页由插件 <span class="mono">category-bars</span> 提供；
      同数据接口为 <span class="mono">GET /api/plugins/category-bars/by-category</span>。</div></div>`;
}

export default {
  id: 'category-bars', name: '类别统计', version: '1.0.0', author: '你的名字',
  description: '按类别统计卦数与平均分，画成柱状图；数据同时以接口形式对外提供。',
  activate(ctx) {
    // 1) 自己的接口：GET /api/plugins/category-bars/by-category
    ctx.registerRoute('GET', 'by-category', ({ json, store }) => {
      json({ ok: true, generatedAt: new Date().toISOString(), data: analyze(store) });
    });
    // 2) 侧栏页面：#/plugin/category-bars/bars
    ctx.registerPage({
      id: 'bars', label: '类别统计', icon: '▥', order: 40,
      render: ({ store }) => ({ html: pageHtml(analyze(store)) }),
    });
    // 3) 订阅事件：新卦录入库时记一行日志（自动带 [category-bars] 前缀）
    ctx.on('record.created', (rec) => ctx.log(`新卦录 ${rec.id}（${rec.category || '未分类'}）`));
    ctx.log('类别统计插件已就绪');
  },
};
```

### 8.3 逐段说明书

| 段 | 为什么这么写 |
|---|---|
| `esc()` | 类别名等都是用户输入。**拼进 HTML 前必须转义**，否则一个含 `<` 的类别名就能破坏页面结构 |
| `BAR_AREA_PX` | 柱状图用「容器固定高度 + 柱子百分比高度」实现，零依赖、自动适应宽度 |
| `analyze(store)` | **统计与渲染分离**，这是 `stats-plus` 的核心手法：一份逻辑，页面与接口共用；改口径只改一处 |
| `Math.max(1, ...rows.map(r => r.count))` | 防除零：只有一条卦录时 `max` 至少是 1 |
| `good` 计数 | 只做展示的辅助列。**不要在插件里自行判定吉凶等级**——等级是断语引擎的事（`rec.reading.grade.label`），这里只用总评分正负做粗略分档 |
| `avg` 为 `null` | 缺 `chart.score` 的历史卦录不该被当成 0 分算进平均——`null` 是「没有数据」，不是「0 分」 |
| 柱高 6% 下限 | 数量为 1 而最大值为 50 时柱子会矮到看不见，给个下限保证可见 |
| `localeCompare(b.category, 'zh')` | 同数量时按中文拼音序排，输出稳定（不用默认字典序） |
| 三处 `register*` 都在 `activate` 顶部同步执行 | 见 §7.4：避免热载期间出现「页面不存在」的短暂窗口 |
| 页面底部写明接口地址 | 让别人（包括以后的你）知道这页可以当接口用 |

## 九、能力边界与风险（**必读**）

### 9.1 插件是任意代码

| 事实 | 后果 |
|---|---|
| 插件在主进程内、以**你的用户权限**执行 | 它能做你在这个账户下能做的一切：读写任意文件、发起网络请求、启动子进程（`node:child_process`）、读写注册表 |
| 插件能 `import` 任意 Node 内置模块 | 宿主不做沙箱、不做能力限制、不做签名校验 |
| 插件能读 `data/config.json` | 里面有**明文的模型 API Key** |
| 插件能 `ctx.store.save()`／`remove()` | 能改、能删你的卦录（`remove(id, true)` 是**真删**，不进 trash） |
| 插件能覆盖内置导出格式 | 把导出器 id 取成 `md`／`slip`／`json` 就会顶掉内置格式 |
| 插件能注册长路径路由 | 在同一插件内，长路径优先匹配 |

**规矩**：**不得**运行来源不明的插件；装之前**应当**通读源文件，重点看 `fs`／`child_process`／`net`／`fetch` 的用法、`store.save`／`store.remove` 的调用、以及 `config` 的读写；只在 `data/plugins/` 里放插件——这是**唯一**的插件目录，也便于整体备份与审计。

### 9.2 数据安全的三条自律

1. **能只读就只读。** 像 `review-watch` 那样只筛选、只展示，是最有价值的形态。
2. **要写就先想清楚。** 需要改卦录时：不要绕过 `store.save()` 直接 `fs.writeFileSync` 到 `records/`（那会破坏原子替换，也可能让内存缓存与磁盘不一致）；不要删数据，要「隐藏」就在配置里记标记或把状态写进 `review`；迁移类操作**必须**先备份（照 `server/store.mjs`：先写 `backups/pre-migration/`，再落盘）。
3. **不要存私密信息。** 插件若要落盘中间数据，放 `ctx.assetsDir`，不要污染 `records/` 与 `config.json`。

### 9.3 硬规矩（继承自项目根 `AGENTS.md`）

| 规矩 | 对插件的含义 |
|---|---|
| 零第三方依赖 | 插件**应当**只用 Node 内置模块与浏览器原生 API。想加功能就自己写几十行，不要引库——否则十年后这个插件跑不起来 |
| 卦象只能由引擎算 | **不得**在插件里手写卦名、卦符、爻辞、体用生克、动爻、旺衰。一律用 `ctx.core.divination.cast()` 或从 `record.chart` 读 |
| 用户数据不可删改 | 见 §9.2 |
| 正文一律 UTF-8 | 写文件一律带 `'utf8'`；**不要**用 PowerShell 的 `Get-Content -Raw` / `Set-Content` 往返改含中文的插件文件 |
| 面向用户的文字要有分寸 | 页面文案不用「能量」「磁场」这类含糊词，不用绝对断言 |
| 注释解释为什么 | 不复述代码在做什么 |

### 9.4 插件做不到的事

| 做不到 | 说明 |
|---|---|
| 加新的**侧栏分组** | 侧栏常驻主项恒为六项（总览／卦录／走势／起卦／导入／助手），加上底部唯一的「插件」组，都写死在 `web/app.js` 的 `NAV`／`OFF_NAV` 与 `paintPluginGroup()` 里；插件页只能进那个插件组与命令面板，别的分组加不了 |
| 改内置页面的 HTML | 没有「覆写视图」的钩子。要改内置页就得改 `web/views.js`（属内核扩展，见 §10） |
| 加新的**起卦法**；阻塞或改写已有接口的响应 | `METHODS` 在内核里，插件不能扩展它；插件路由只在自己命名空间下，没有中间件／响应拦截机制 |
| 取消事件订阅 | 没有 `off()`；只能靠热载清空全部钩子 |
| 影响 MCP 服务 | MCP 是**另一个进程**（`agent/mcp-server.mjs`），只加载 `agent/tools.mjs` 的工具集，**不加载插件**。插件注册的接口与页面只在 HTTP 服务里可用 |
| 后台常驻任务 | 没有定时器／调度钩子。要周期做事只能靠外部（如系统计划任务打你的接口） |

## 十一、兼容性承诺

### 11.1 插件 API 的稳定性

| 承诺 | 内容 |
|---|---|
| **稳定的（1.x 内不会破坏）** | `activate(ctx)` 的调用约定；`ctx` 上的 `id`／`plugin`／`store`／`core`／`config`／`log`／`warn`／`assetsDir`；`registerRoute`／`registerPage`／`registerPanel`／`registerExporter`／`on` 的名字与参数形状；路由处理器 ctx 上的 `json`／`send`／`html`／`text`／`readBody`／`query`／`store`／`core`；六个事件名；`/plugin-assets/<id>/…` 的 URL 约定；`GET /api/plugins` 的响应形状 |
| **可以新增（不算破坏）** | `ctx` 上新增成员；新增事件名；`register*` 的选项对象新增可选字段；`api()` 的 `plugins[]` 新增字段；`ctx.core` 新增模块；`GET /api/plugins` 的响应新增字段 |
| **不保证稳定的** | 界面内部的 CSS 类名（`.card`、`.bar-row`、`.md-table`、`--gold-2` 等）——它们不是插件 API；`ctx.plugin` 对象的内部结构（只读用途）；`errors[]` 的文案格式；`chart`／`reading` 快照的**新增字段**（既有字段不删，但新字段可能随断语引擎演进增加） |
| **不承诺跨大版本** | 上述「稳定的」部分在**大版本**（2.0）中可能变更。届时必须在本文件与发布说明里给出迁移指引 |

### 11.2 弃用策略

| 阶段 | 做法 |
|---|---|
| 标记弃用 | 在本文档与发布说明中列明「弃用什么、替代是什么、从哪个版本起弃用」；**保留其功能至少一个大版本**（1.x 内不删） |
| 兼容期 | 旧写法继续工作。若旧写法有安全隐患（如能绕过数据保护），可以提前移除，但**必须**在发布说明里显著标注为破坏性变更 |
| 移除 | 只在大版本进行。移除时**必须**提供从旧写法到新写法的对照示例 |

插件的自我防护——**应当**做能力探测，缺什么就降级并在页面上说明，而不是直接抛错：

```js
activate(ctx) {
  if (typeof ctx.registerExporter !== 'function') {
    ctx.warn('本版本的问心卦不支持 registerExporter，导出功能已跳过。');
    return;                       // 其余注册照旧，或整体降级
  }
  // …
}
```

### 11.3 数据侧的兼容性（与插件强相关）

- **卦条 v1 的字段名与别名不会删改，只会新增别名。** 旧文件永远能读——所以插件里按旧别名解析卦条是安全的。
- **卦录 JSON 只做向前迁移，不做破坏性重写。** `data/records/` 下的文件永远可以被后来的版本读入；插件的 `reading`／`chart` 快照同理——引擎升级后旧快照保持不变，只有新录入与显式「重算」才用新引擎。
- **数据是纯文本 JSON，不依赖本程序也能读。** 即使插件与程序都不在了，`records/` 里的东西依然在。
