## 一、三种运行形态

| 维度 | 命令行 + 浏览器 | Electron 桌面版 | MCP 服务 |
|---|---|---|---|
| **依赖** | Node.js ≥ 18 | 无（Electron 自带 Chromium + Node 运行时） | Node.js ≥ 18 |
| **启动方式** | `node server/index.mjs --open`；或双击 `启动问心卦.bat` | 双击 `问心卦.exe`／安装包；或 `cd desktop && npm start` | `node agent/mcp-server.mjs`（由宿主拉起） |
| **界面** | 系统浏览器（Edge／Chrome／任意） | 独立窗口 + 托盘 + 中文菜单 | 无界面（JSON-RPC over stdio） |
| **端口** | 固定 `127.0.0.1:19730`（可改） | 先试 19730，被占则让系统分配空闲端口 | 不监听端口 |
| **进程模型** | 一个 `node.exe` | 一个 `问心卦.exe`（服务跑在同一进程内，不 spawn 子进程、不弹控制台） | 一个 `node.exe` 子进程，由宿主管理 |
| **数据目录** | 项目内 `data\`（不可写则退回 `%APPDATA%\问心卦\data`） | 安装态 `%APPDATA%\问心卦\data`；开发态项目内 `data\` | 同命令行版 |
| **适用场景** | 开发调试、服务器无桌面环境、想看请求日志 | 日常使用（推荐）；不想装 Node | 把起卦／查卦能力接给 Codex CLI、Claude Code、DSH 等外部 agent |
| **卸载影响** | 删目录即卸载，`data\` 一并没了（先备份） | 卸载不删数据 | 无（无状态） |

> 还有第五种入口：**零安装兜底**。双击 `问心卦(桌面窗口).vbs` 会静默起服务（无控制台窗口），再用系统自带的 Edge／Chrome 以 `--app` 模式开一个没有地址栏、没有标签页的独立窗口；关掉窗口自动停服务。它仍然需要 Node.js。

## 二、环境要求

| 项 | 要求 | 实测／依据 |
|---|---|---|
| **Node.js** | ≥ 18 | 根 `package.json` 的 `engines.node` 为 `>=18`；开发环境实测 Node **v24.16.0** |
| **操作系统** | Windows 10 / 11（x64） | 打包目标为 `nsis` + `x64`；开发与截图环境为 **Windows NT 10.0.26200** |
| **Electron** | 33.4.11（声明 `^33.2.0`） | `desktop/node_modules/electron/package.json` |
| **electron-builder** | 25.1.8（声明 `^25.1.8`） | `desktop/node_modules/electron-builder/package.json` |
| **内置运行时** | Chromium 130.0.6723.191、Node 20.18.3 | `desktop.log` 中主进程启动记录 |
| **可选浏览器** | Edge 或 Chrome（仅零安装兜底与命令行版需要） | `问心卦(桌面窗口).vbs` 依次查找 Program Files 下的 `msedge.exe` / `chrome.exe` |
| **网络** | 运行期**完全不需要**。仅「AI 助手」调用模型、以及首次 `npm install` 需要 | 内核零第三方依赖；模型可换成本地 Ollama 完全离线 |
| **磁盘** | 程序约 180 MB（免安装目录）／约 78 MB（安装包）；数据每条卦录约 20–30 KB | `问心卦.exe` 实测 188,784,128 字节；安装包 81,919,423 字节 |
| **Python + Pillow** | 仅重新生成图标时需要 | `desktop/build/make-icon.py`；图标已生成，日常无需 Python |

## 三、安装步骤

### 3.1 方式一：安装包（推荐）

```bat
:: 1) 关闭正在运行的问心卦
:: 2) 双击安装包
desktop\dist\问心卦-安装包-1.1.0.exe

:: 静默安装（不弹界面，跳过完成页）
desktop\dist\问心卦-安装包-1.1.0.exe /S
```

安装器为 Assistive（`oneClick: false`）形态：中文向导、可改安装目录、可选是否为所有用户安装。安装完成后桌面与开始菜单都会出现「问心卦」快捷方式（`createDesktopShortcut: "always"`，静默安装同样会建）。实测安装位置示例：`F:\Apps\wenxingua-desktop\`，其中含 `问心卦.exe`、`Uninstall 问心卦.exe`、`resources\`（`app.asar`、`app\`、`seed-data\`）。

首次启动会自动做一件事：把随包附带的**三个官方示例插件**复制到 `%APPDATA%\问心卦\data\`。随包数据里**不含卦录、也不含 `config.json`**，所以装完打开是**空库**——先起一卦，或用「导入」页录一条旧卦。

### 3.2 方式二：免安装目录

```bat
:: 整个目录拷到任意位置（U 盘亦可），双击即可
desktop\dist\win-unpacked\问心卦.exe
```

`win-unpacked` 是自包含的：拷走整个文件夹就能跑，不需要安装、不需要 Node、不写注册表。数据仍在 `%APPDATA%\问心卦\data`（不随目录走）——若希望数据跟着 U 盘走，见 §5.4。

### 3.3 方式三：命令行 + 浏览器

```bash
# 首次：克隆/解压出项目目录即可，无需 npm install（零依赖）
cd 问心卦

node server/index.mjs                # 起服务，默认 127.0.0.1:19730
node server/index.mjs --open         # 顺便打开浏览器
node server/index.mjs --port 8080    # 换端口
node server/index.mjs --host 0.0.0.0 # 换绑定地址（默认只绑本机）

# 或双击 启动问心卦.bat（有桌面版则优先开桌面版）
```

看到如下横幅即成功：

```
  ┌──────────────────────────────────────────────┐
  │            问  心  卦   ·   卦录台            │
  └──────────────────────────────────────────────┘
   版本      v1.1.0
   地址      http://127.0.0.1:19730/
   数据目录  …\问心卦\data
   卦典      64 卦 / 爻辞 64 卦
   卦录      6 条
   插件      3 个已载入

   按 Ctrl+C 停止服务
```

环境变量 `QXG_PORT`、`QXG_HOST` 等价于 `--port`、`--host`。

### 3.4 方式四：零安装兜底（桌面窗口）

```bat
:: 双击即可：隐藏控制台起服务 + Edge/Chrome --app 独立窗口
问心卦(桌面窗口).vbs

:: 想建快捷方式（桌面 + 开始菜单，带卦符图标）
powershell -ExecutionPolicy Bypass -File .\创建快捷方式.ps1
```

`创建快捷方式.ps1` 按优先级挑目标：已打包的 `问心卦.exe` → 开发态 `electron.exe` → `问心卦(桌面窗口).vbs`。

### 3.5 方式五：MCP 服务（给外部 agent 用）

无需安装，直接配置宿主即可。脚本绝对路径为 `<项目绝对路径>/agent/mcp-server.mjs`。

Codex（`~/.codex/config.toml`）：

```toml
[mcp_servers.wenxingua]
command = "node"
args = ["<项目绝对路径>/agent/mcp-server.mjs"]
```

Claude Code / DSH（`.mcp.json`）：

```json
{ "mcpServers": { "wenxingua": { "command": "node",
  "args": ["<项目绝对路径>/agent/mcp-server.mjs"] } } }
```

界面上「AI 助手」页底部有可直接复制的现成片段，`GET /api/agent/mcp` 也会返回同样的内容。

MCP 暴露 **21 个工具**、**3 个资源**（全部卦录／卦条规范／统计）与 **2 个提示模板**（`divine`、`review_due`）。

### 3.6 从源码跑桌面版（改代码时用）

```bat
cd desktop
set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
set ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
npm install
npm start          :: 或 npm run dev（带开发者工具）
```

开发态（`electronApp.isPackaged === false`）的**数据目录是项目里的 `data\`**，代码根目录是项目根——改 `web/` 后按 `Ctrl+R` 刷新界面即可生效，不必重新打包。

## 四、打包构建

### 4.1 命令

```bash
npm run dist          # 出 NSIS 安装包到 desktop\dist\（= npm --prefix desktop run dist）
npm run dist:dir      # 只出免安装目录 desktop\dist\win-unpacked\
cd desktop
npm start             # electron .          —— 正常启动
npm run dev           # electron . --dev    —— 带开发者工具
npm run selftest      # electron . --selftest —— 自检（与 check-desktop.mjs 同源）
npm run icon          # python build/make-icon.py —— 重新生成图标
```

`desktop/package.json` 的 `scripts` 共六项：`start`／`dev`／`selftest`／`icon`／`dist`（`electron-builder --win nsis --x64`）／`dist:dir`（`electron-builder --win dir --x64`）。根 `package.json` 的 `dist` 与 `dist:dir` 只是转发。

### 4.2 `desktop/package.json` 的 build 配置逐项解释

**包元信息**

| 配置项 | 值 | 作用与注意 |
|---|---|---|
| `name` | `wenxingua-desktop` | 包名。**决定了 Electron 的 userData 目录**：`%APPDATA%\wenxingua-desktop`（日志、窗口状态、数据目录偏好都在这里）。改名会让老用户的日志与窗口记忆「看起来丢了」（实际是换了目录） |
| `version` | `1.1.0` | 与根 `package.json` 保持一致；安装包名与「关于」对话框都取它 |
| `description` / `author` / `license` | 问心卦 · 桌面版（Electron 外壳；内核仍是零依赖的纯 Node）／`问心卦`／`MIT` | 写进 exe 属性与安装器信息 |
| `main` / `type` | `main.mjs` / `module` | 主进程入口用 ESM。`check-desktop.mjs` 会断言两者。**preload 不受 `type` 影响**——它必须是独立的 `.cjs` |
| `devDependencies` | `electron: ^33.2.0`（实测 33.4.11）、`electron-builder: ^25.1.8`（实测 25.1.8） | 必须是 **devDependencies**：运行期零依赖这条硬规矩允许构建期依赖，但不得进 `dependencies` |

**`build` 段**

| 配置项 | 值 | 作用与注意 |
|---|---|---|
| `build.appId` | `local.wenxingua.desktop` | 安装器、AppUserModelID 与快捷方式的身份标识。**必须**与 `main.mjs` 里 `electronApp.setAppUserModelId('local.wenxingua.desktop')` 一致，否则任务栏分组、通知归属会错 |
| `build.productName` | `问心卦` | 决定可执行文件名（`问心卦.exe`）、开始菜单文件夹与安装目录名 |
| `build.copyright` | `问心卦 · 本地单机程序` | 写进 exe 版本信息 |
| `build.directories.output` | `dist` | 产物目录，即 `desktop\dist\` |
| `build.directories.buildResources` | `build` | 构建资源目录，图标就放在这里 |
| `build.files` | `main.mjs`、`preload.cjs`、`package.json`、`build/icon.png`、`build/tray.png`，另加两条排除：`!dist/**`、`!node_modules/**/{test,__tests__,tests,example,examples,docs,doc}/**` | 进 `app.asar` 的文件清单。**实测 `app.asar` 内恰为这五项**（`build/` 下只有 `icon.png` 与 `tray.png`；清单里的 `package.json` 被 electron-builder 重写成了 260 字节的最小版，源码那份是 2.3 KB）。**`preload.cjs` 必须在这个清单里**——曾经漏过，症状是打包后桌面桥为 `undefined` |
| `build.extraResources[0]` | `from: ".."`, `to: "app"`，filter 为 `core/**`、`server/**`、`agent/**`、`hermes/**`、`web/**`、`schema/**`、`knowledge/**`、`tools/**`、`package.json`、`README.md`、`AGENTS.md`、`LICENSE*`、`docs/**/*.md` | 把内核代码复制到 `resources/app`（主进程按 `process.resourcesPath + '/app'` 定位它）。filter 里的 `docs/**/*.md` 只收 Markdown，不收 `docs/` 下的截图 |
| `build.extraResources[1]` | `from: "../data"`, `to: "seed-data"`，filter 为 `plugins/**` | 随包数据**只含三个官方示例插件**。**卦录（`records/**`）与 `config.json` 都不在随包范围**——程序首次运行会自建 `config.json` 默认值，`records/` 保持为空 |
| `build.win.target` | `[{ "target": "nsis", "arch": ["x64"] }]` | 只出 64 位 NSIS 安装包。`check-desktop.mjs` 断言 `target[0].target === 'nsis'` |
| `build.win.icon` | `build/icon.ico` | 安装器与 exe 的图标来源。因 `signAndEditExecutable: false`，**exe 文件本身不会带上它** |
| `build.win.artifactName` | `问心卦-安装包-${version}.${ext}` | 安装包文件名；实测产物为 `问心卦-安装包-1.1.0.exe` |
| `build.win.signAndEditExecutable` | `false` | 见 §4.3 坑二 |

> **随包数据只允许放程序自带的示例插件。** `data/` 里的用户数据——卦录、会话、`config.json`——**不得**进入任何分发的二进制；开源发布时，那等于把作者的私人记录公开。

**`build.nsis` 段**

| 配置项 | 值 | 作用与注意 |
|---|---|---|
| `oneClick` | `false` | Assistive 安装器：有向导、可改安装目录。**这一项是「静默安装不建快捷方式」那个坑的前提** |
| `perMachine` | `false` | 默认按当前用户安装（不需要管理员权限） |
| `allowToChangeInstallationDirectory` | `true` | 让向导出现目录选择页（Assistive 模式下默认不出现） |
| `createDesktopShortcut` | `"always"` | 见 §4.3 坑三 |
| `createStartMenuShortcut` | `true` | 建开始菜单快捷方式 |
| `shortcutName` | `问心卦` | 快捷方式显示名。`check-desktop.mjs` 会断言 |
| `installerIcon` / `uninstallerIcon` | `build/icon.ico` | 安装器与卸载器的图标 |
| `installerLanguages` | `["zh_CN"]` | 安装向导语言；实测生成的 NSIS 脚本里 `addLangs` 只插入 `MUI_LANGUAGE "SimpChinese"` |
| `language` | `"2052"` | 2052 = 简体中文（LCID） |
| `deleteAppDataOnUninstall` | `false` | **卸载不删数据**。数据在 `%APPDATA%\问心卦\data`，与安装目录分离 |

### 4.3 三个已实测的坑

**坑一：Electron 二进制要走镜像。** Electron 的二进制放在 GitHub 上，国内常连不上，`npm install` 会卡住或超时。

```bat
set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
set ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
npm install
```

若报 `connect ETIMEDOUT` 但 `node_modules\electron\dist` 里只有一个 `LICENSES.chromium.html`，说明 **zip 下好了却没解压**——从 `%LOCALAPPDATA%\electron\Cache\<hash>\electron-v33.x.x-win32-x64.zip` 手动解压到 `node_modules\electron\dist` 即可。

**坑二：`winCodeSign` 解压需要符号链接权限，故设了 `signAndEditExecutable: false`。** Windows 上 electron-builder 下载的 `winCodeSign` 压缩包里含 **macOS dylib 的符号链接**，解压需要 Windows 开发者模式或管理员权限，否则构建**直接失败**。本项目在 `build.win` 里设 `signAndEditExecutable: false` 绕开它。

代价是 **exe 文件本身不带我们的图标**；但**窗口图标、托盘图标、快捷方式图标都是对的**（它们分别来自 `build/icon.png`、`build/tray.png` 与 `build/icon.ico`）。

要恢复 exe 内嵌图标：先开启 Windows 开发者模式，再去掉 `build.win.signAndEditExecutable` 这一项重新构建。

**坑三：`createDesktopShortcut` 必须写 `"always"` 而不是 `true`。** `oneClick: false` 的安装器会把「创建桌面快捷方式」做成**完成页的一个勾选项**；写 `true` 时静默安装（`/S`）会跳过完成页，于是**静默安装不建桌面快捷方式**。写 `"always"` 才会无条件创建。

### 4.4 打包产物的结构（实测）

```
desktop/dist/
├─ 问心卦-安装包-1.1.0.exe            81,919,423 字节（约 78 MB）
├─ 问心卦-安装包-1.1.0.exe.blockmap   增量更新用的块映射
├─ builder-debug.yml                  本次构建的解析结果（排查配置问题的第一手材料）
└─ win-unpacked/                      免安装目录（问心卦.exe 实测 188,784,128 字节）
   ├─ *.dll / *.pak / *.bin / locales/    Electron 运行时
   └─ resources/
      ├─ app.asar        主进程外壳：main.mjs、preload.cjs、build/icon.png、build/tray.png、
      │                  以及 electron-builder 合成的最小 package.json（name/version/main/type）
      ├─ app/            内核代码（CODE_ROOT）：agent/ core/ hermes/ knowledge/ schema/ server/
      │                  tools/ web/ docs/（仅 .md）+ package.json + README.md + AGENTS.md
      ├─ seed-data/      随包数据：只有 plugins/（3 个官方示例插件）；不含卦录与 config.json
      └─ elevate.exe     NSIS 提权辅助程序
```

要点：

- **`app.asar` 与 `resources/app/` 是两回事。** asar 里是桌面外壳（来自 `build.files`）；`resources/app/` 是内核代码（来自 `extraResources`）。主进程按 `process.resourcesPath + '/app'` 定位内核。
- **两者都不含 `desktop/` 与 `data/` 目录本身**（`extraResources` 的 filter 是白名单），否则体积翻倍。
- **`seed-data/` 里只有 `plugins/`**，不含卦录、也不含 `config.json`。首次运行会把它复制到用户数据目录（只在数据目录为空时），于是 `plugins\` 得到 3 个官方插件，`records\` 为空、`config.json` 由程序自建默认值。
- 每次构建后都应先看一眼 `builder-debug.yml`，它列出了本次真正生效的文件通配符清单——「安装包里少了某个文件」这类问题，答案通常就在这里。

### 4.5 构建前置校核

`build` 配置与 `main`、`devDependencies` 是打包的硬前提。打包前**必须**确认 `desktop/package.json` 同时具备：`main: "main.mjs"`、`type: "module"`、`devDependencies.electron`、`devDependencies["electron-builder"]`、`build.win.target`、`build.nsis.shortcutName === "问心卦"`。这几项恰好就是 `node tools/check-desktop.mjs` 的前 4 项静态检查——**打包前先跑它**，比构建失败再回头看配置便宜得多。

> ⚠️ **一个已发生过的坑：`desktop/package.json` 被覆盖。** `npx asar extract-file <asar> <内部路径>` 会把文件写到**当前工作目录**并用内部路径的 basename 命名。开发中曾在 `desktop/` 目录下执行 `asar extract-file … "dsh/package.json"`，结果 `desktop/package.json` 被那份清单整个覆盖（只剩 `name`／`private`／`version`／`type`／`dependencies` 五个键，**`main` 没了**）。症状是 **Electron 退出码 1 且没有任何输出**——因为没有 `main` 就无从启动。
>
> 结论：**用 asar 抽文件前先 `cd` 到一个临时目录**；一旦出现「Electron 静默退出」，第一件事就是核对 `desktop/package.json` 是否完整，跑 `node tools/check-desktop.mjs`，它的前 4 项会立刻给出结论。

## 五、数据目录与迁移

### 5.1 解析顺序

程序按下面的顺序决定数据目录，**先命中者生效**：

| 优先级 | 条件 | 结果 | `mode` |
|---|---|---|---|
| 1 | 设了环境变量 `QXG_DATA_DIR` | 用它（绝对化） | `env` |
| 2 | 桌面版：userData 下的 `data-dir.json` 记录了一个存在且有效的目录 | 用它（用户在菜单里选过） | `chosen` |
| 3 | 桌面版开发态 | 项目里的 `data\` | `dev` |
| 4 | 桌面版安装态 | `%APPDATA%\问心卦\data`，空的则把随包 `resources/seed-data`（只有示例插件）复制进去 | `appdata` |
| 5–6 | 命令行版：`<代码目录>\data` 存在且可写 → 用它（便携模式）；不可写 → `%APPDATA%\问心卦\data`（空的则把随包 `seed-data`（只有示例插件）复制进去） | 命令行版的两种落点 | `portable` / `appdata` |

桌面版之所以**在 import 服务之前**就把数据目录定好（写 `QXG_DATA_DIR`），是为了避免服务自己挑到安装目录里的 `data/`——那样一升级就被覆盖。

界面上随时能看到当前用的是哪个：侧栏底部、「关于问心卦」对话框、以及 `GET /api/meta` 的 `app.dataDir` 与 `app.dataMode`。

### 5.2 目录内容

```
<数据目录>\
├─ records\       一条卦录一个 JSON（<id>.json，id 形如 202609280338-01）
├─ trash\         删掉的卦录（软删进这里，?hard=1 才真删）
├─ backups\       备份；pre-migration\ 存迁移前原件
├─ plugins\       插件（一个 .mjs 一个插件；<id>\ 可放该插件的静态资源）
└─ config.json    默认地点、定时辰之法、插件开关、AI 配置
```

`data/records/` 的文件是**纯文本 JSON**，不依赖本程序也能读。这是刻意的存储取向：卦录要陪几十年，纯文本最耐久。

### 5.3 首次运行带入的随包数据（只有插件）

安装态首次启动时，若 `records/` 为空（或不存在），程序把 `resources/seed-data/` 整个目录复制到数据目录。随包 `seed-data/` 里**只有 `plugins/`**（3 个官方示例插件）——`records/` 与 `config.json` 都不在随包数据里。所以首次运行只得到 `plugins\`，`records\` 是空的、`config.json` 由程序自建默认值：装完打开是**空库**。**只在为空时复制**，所以升级不会覆盖你的数据。

### 5.4 如何更换数据目录

**桌面版（图形化）**：菜单 **「数据 → 更换数据目录…」**，选一个新目录后程序会提示「需要重启后生效」，并提供「立即重启」。选择被记进 `%APPDATA%\wenxingua-desktop\data-dir.json`。

> ⚠️ **原目录的数据不会自动搬过去。** 需要手动把旧目录的 `records\`、`plugins\`、`config.json` 复制到新目录。想整个带走就在换目录之前先复制。

**桌面版／命令行版（环境变量）**：设置 `QXG_DATA_DIR` 指向目标目录。它的优先级高于一切，适合把数据放到 OneDrive、git 仓库或移动硬盘；**免安装版想让数据跟着 U 盘走**也用它（设为可执行文件旁边的 `data` 子目录即可——默认不这么做，是为了避免升级覆盖）。

```bat
set QXG_DATA_DIR=D:\我的卦录
node server\index.mjs
```

## 六、配置项手册

配置文件：`<数据目录>\config.json`（UTF-8、纯文本、可直接编辑；程序缺字段时用默认值补齐）。下表依据 `server/store.mjs` 的 `DEFAULT_CONFIG`。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `schema` | number | `1` | 配置文件自身的结构版本 |
| `appName` | string | `"问心卦"` | 显示名 |
| `defaultPlace` | string | `"兰州"` | 起卦台与卦条里未写「地」时用的默认地点 |
| `defaultLongitude` | number | `103.83` | 默认经度（东经）。**真太阳时按它换算，改它会改变时辰从而改变整个卦** |
| `useTrueSolarTimeByDefault` | boolean | `true` | 默认是否用真太阳时定时辰。**推荐保持 `true`** |
| `movingFromByDefault` | string | `"sum"` | 默认动爻取法：`sum`＝数与时辰之和除六（梅花易数常法）；`number`＝仅以报数除六（旧稿偶见） |
| `theme` | string | `"ink"` | 界面主题标识 |
| `plugins` | object | `{}` | 插件开关表：`{ "<插件id>": { "enabled": false } }`。**未列出的插件默认启用**（判定条件是 `enabled !== false`） |
| `backupDir` | string | `"backups"` | 备份子目录名 |
| `lastSeenVersion` | string | `""` | 上一次「看过更新内容」的版本号（界面弹一次更新说明卡用） |
| `updateCheck` | boolean | `true` | 启动后是否问一次 GitHub 的发行版接口（**本程序唯一的主动外呼**，见 §11 与 [11-安全与隐私设计.md](11-安全与隐私设计.md) §6.3.3）。关掉后程序完全不出网 |
| `agent.enabled` / `agent.provider` | boolean / string | `false` / `"deepseek"` | 是否启用 AI 助手；服务商预设：`deepseek`／`openai`／`hermes`／`ollama`／`custom` |
| `agent.baseUrl` / `agent.apiKey` / `agent.model` | string | `""` | 覆盖预设的端点（留空用预设值）／**明文存储的 Key**（见 §11）／模型名 |
| `agent.temperature` / `agent.maxTokens` / `agent.maxRounds` | number | `0.6` / `0` / `6` | 采样温度／单次回复上限（**0 = 不带 `max_tokens`**，由服务商定；填小值会把长回答截成半句）／agent 循环的最大轮数（工具调用轮次上限） |
| `agent.useNativeTools` | boolean | `true` | `true`＝用模型原生 function calling；`false`＝文本协议降级（Hermes 的 `text-fence`：模型输出 ```json {"tool":…} ```，程序自己解析），本地 7B 小模型用这个 |
| `agent.contextWindow` | number | `0` | 上下文窗口覆盖值（token）。**`0` = 用「模型名 → 窗口」预设**（`deepseek-*` → 1000000，`gpt-*`／`o1`／`o3`／`o4` → 128000，其余 → 未知）；填正数则助手面板的「上下文占用」chip 按它算占比 |

服务商预设（真源在 `hermes/targets.mjs`）：

| id | 预设 baseUrl | 是否需要 Key |
|---|---|---|
| `deepseek` | `https://api.deepseek.com/v1` | 是 |
| `openai` | `https://api.openai.com/v1` | 是 |
| `hermes` | `http://127.0.0.1:8000/v1` | 否 |
| `ollama` | `http://127.0.0.1:11434/v1` | 否 |
| `custom` | 空（必须自己填） | 否 |

> **改配置的推荐路径是界面**（「AI 助手」页与各页的设置项），它会走 `POST /api/agent/config`、`POST /api/config` 或 `store.setConfig()`；手改 `config.json` 也可以，但**必须在程序停止时改**，否则运行中的进程会在下次写回时覆盖你的编辑。

## 七、备份与恢复操作手册

### 7.1 备份

| 方式 | 操作 | 产物 | 适用 |
|---|---|---|---|
| **整包 JSON（界面）** | 「总览」页点「整包备份（JSON）」 | 一个 JSON 文件，含 `meta`／`config`／`records` | 推荐：可跨机、可版本化 |
| **整包 JSON（桌面版菜单）** | 菜单「数据 → 导出整包备份…」 | 弹保存框，默认文件名 `问心卦-备份-YYYY-MM-DD.json` | 推荐的桌面操作 |
| **整包 JSON（命令行）** | `curl -o backup.json "http://127.0.0.1:19730/api/export?format=json"` | 同上 | 脚本化／定时任务 |
| **目录级复制** | 直接复制整个 `<数据目录>`（含 `records\`、`plugins\`、`config.json`） | 目录副本 | 最省事、最完整（连 `trash\`、`backups\` 一起带走） |
| **版本化** | 在数据目录里 `git init`，把 `records/` 与 `config.json` 纳入 | git 历史 | 想要逐次可回退 |

```bat
:: 目录级备份（先停掉程序，或至少确认没有正在进行的导入）
xcopy /E /I /Y "%APPDATA%\问心卦\data" "D:\备份\问心卦-data-%DATE:~0,4%%DATE:~5,2%%DATE:~8,2%"
```

> **不要把 `data\` 放进同步盘或提交到公开仓库**：`config.json` 里有明文的模型 API Key，`records\` 里有你几十年的私事。详见 [11-安全与隐私设计.md](11-安全与隐私设计.md)。

### 7.2 恢复

| 方式 | 操作 | 注意 |
|---|---|---|
| **整包恢复（接口）** | `curl -X POST -H "Content-Type: application/json" --data-binary @backup.json http://127.0.0.1:19730/api/restore` | 默认 `merge: true`：同 id 的卦录被更新，新 id 被新增；**不会删除**现有卦录 |
| **整包恢复（界面）** | 「导入」页 → 「恢复 JSON 备份」 | 同上 |
| **命令行恢复** | `node tools/import.mjs backup.json` | 等价于 `store.restore(pack, { merge: true })` |
| **目录级还原** | 停程序 → 用备份覆盖 `<数据目录>` → 启程序 | 最彻底。**必须先确认目标路径正确**，覆盖不可逆 |
| **单条恢复** | 从 `data\trash\` 里把 `<id>-<时间戳>.json` 拷回 `data\records\<id>.json` | 软删的卦录都还在 trash 里 |
| **迁移回退** | 从 `data\backups\pre-migration\` 取回原件，覆盖 `records\` 下对应文件 | 见 §8.3 |

### 7.3 恢复后的自检

恢复完**必须**跑一遍：

```bash
node tools/validate.mjs     # 结构合法性与语义约定
node tools/check.mjs        # 全部卦录可重算、可导出
```

## 八、升级流程

### 8.1 程序升级（数据不动）

```bat
:: 1) 停止正在运行的程序（托盘 → 退出；命令行版按 Ctrl+C）
:: 2) 备份数据（见 §7.1，强烈建议）
:: 3) 覆盖安装新版本：直接双击新安装包即可
desktop\dist\问心卦-安装包-<新版本>.exe

:: 免安装版：把新的 win-unpacked 覆盖旧的即可
```

**升级不会碰数据**：程序装在安装目录／`win-unpacked`，数据在 `%APPDATA%\问心卦\data`（或你自选的位置），两者分离。`seed-data`（只有示例插件）只在数据目录为空时才会被复制进去。

### 8.2 数据迁移（结构升级时）

卦录带 `schema` 号（当前为 **1**）。载入时若某条卦录的版本低于当前版本，程序按 `core/migrate.mjs` 的 `MIGRATIONS` 登记表**逐级迁移**，并且**先把原件备份到 `data\backups\pre-migration\<id>-v<旧版本>-<时间戳>.json`，再落盘**。

迁移发生在 `Store` 构造时（即程序启动时），日志会打印：`[store] <id> 已自 v0 迁移到 v1`。

**缺失迁移函数时，该条按原样载入并告警，不会丢数据**（`[store] xxx 迁移失败，按原样载入：缺少 v1 → v2 的迁移函数`）。

### 8.3 升级前备份在哪、如何回退

| 时刻 | 备份在哪 | 内容 |
|---|---|---|
| 你手动导出的整包 | 你选的位置（如 `D:\备份\问心卦-备份-2026-10-03.json`） | 全部卦录 + 配置 |
| 迁移自动生成的 | `<数据目录>\backups\pre-migration\<id>-v<旧版本>-<时间戳>.json` | **单条**卦录迁移前的原件 |
| 目录级备份 | 你复制的目录 | 一切 |

回退步骤：

```bat
:: 1) 停止程序
:: 2) 找到迁移前原件（按 id 与时间戳辨认）
dir "%APPDATA%\问心卦\data\backups\pre-migration"

:: 3) 覆盖回 records\（示例）
copy /Y "%APPDATA%\问心卦\data\backups\pre-migration\202609280338-01-v0-1759500000000.json" ^
        "%APPDATA%\问心卦\data\records\202609280338-01.json"

:: 4) 重启程序，并跑校验
node tools\validate.mjs
```

> 注意：迁移后的文件已被新结构覆盖，**回退意味着放弃迁移后的那一次写入**。所以迁移前的那份备份是唯一退路——这也正是 `pre-migration/` 目录存在的理由。
>
> 若新版程序有缺陷导致反复迁移出错，最快的止损是**先回退程序版本**（装回旧安装包），再处理数据。

### 8.4 旧卦录的断语快照不变

升级断语引擎后，**旧卦录的 `reading` 快照保持不动**；只有新录入与手动点「重算断语」才会用新引擎。所以升级不会让你过去看到的断语「变样」。想用新引擎看旧卦，逐条点重算即可。

## 九、故障排查手册

| 症状 | 可能原因 | 处理 |
|---|---|---|
| **端口被占用，服务起不来**：命令行版打印「端口 19730 已被占用」并退出 1 | 另有一个命令行版在跑；或 19730 被别的程序占用 | 换端口：`node server/index.mjs --port 19731`，或设 `QXG_PORT`；也可以先找到占用者：`netstat -ano \| findstr :19730` 再 `tasklist \| findstr <PID>`。**桌面版不需要处理**——它发现 19730 被占会自动让系统分配一个空闲端口（实测日志中出现过 `http://127.0.0.1:56684/`） |
| **桌面版没有窗口**（进程在跑、任务管理器里有 `问心卦.exe`，但没有界面） | ① 主进程写了顶层 `await app.whenReady()`，死锁；② 环境变量 `ELECTRON_RUN_AS_NODE=1` 让 Electron 退化成纯 Node；③ 已有实例在运行，本实例主动退出 | ① 见 `desktop/main.mjs` 的写法：必须是 `app.whenReady().then(main)`，模块同步求值完；② 清掉变量再启动：`set ELECTRON_RUN_AS_NODE=` 或 PowerShell `Remove-Item Env:\ELECTRON_RUN_AS_NODE`（`tools/check-desktop.mjs` 已自动清）；③ 再点一次启动会把已有窗口前置，不会开第二个 |
| **桌面桥 `window.__qxgDesktop` 是 `undefined`**：侧栏不显示「桌面版」，桌面专属按钮不出现 | preload 写成了 ES 模块（`.mjs` + `import`）——Electron 默认 `sandbox: true`，沙箱化的 preload 不能是 ESM，会**静默失败** | 确认 `desktop/preload.cjs` 存在且用 `require('electron')`，且 `main.mjs` 的 `webPreferences.preload` 指向它。跑 `node tools/check-desktop.mjs`，第 10 项会直接指出 |
| **新导入的卦录看不见** | 服务进程的缓存没刷新；或导入到了**另一个数据目录** | ① 正常情况下程序会自己发现：处理请求时会比一次 `records/` 目录的 mtime，变了就重扫（日志 `[store] 检测到外部改动，已重扫：N → M 条`）——若日志里没有这行，说明改动不在当前数据目录里；② 打开侧栏底部或「关于」对话框核对数据目录；命令行导入默认用**项目里的** `data\`，而安装态桌面版用的是 `%APPDATA%\问心卦\data`，两者不同——这是最常见的原因 |
| **卦典／爻辞缺失或告警**（界面上卦典不全，或自检第 5 项报 warning） | `knowledge/64gua.json`、`knowledge/yaoci.json` 被改坏、缺失，或路径不可读 | 跑 `node tools/check.mjs`，第一节的 8 项会定位到具体是哪一类问题（缺卦／缺爻辞／上下卦告警／卦符与卦序不符）。修好后重启生效。`knowledge/` 的改动只需重启，不需要重新打包 |
| **插件报错导致页面异常** | 插件语法错、`activate()` 抛错、渲染函数返回了非预期结构 | 打开「插件」页：底部的**「载入错误」**区会逐条列出出错的文件与错误信息；也可以 `GET /api/plugins` 看 `errors` 数组，或看服务控制台/日志里的 `[plugins] xxx 载入失败：…`。**处理**：停用该插件（插件页的「停用」按钮，或把 `config.json` 的 `plugins.<id>.enabled` 设为 `false`），修好后再「热载全部插件」。一个插件载入失败**不会**影响其它插件与主界面 |
| **模型连不上 / 401 / 超时** | ① 未填 API Key（`deepseek`／`openai` 预设需要）；② baseUrl 写错或多写了结尾斜杠；③ 网络不通或需要代理；④ 模型名不存在；⑤ 本地 Ollama 没起；⑥ 目标被熔断（连续失败达到阈值） | ① 助手页「测连通」会明确报「DeepSeek 需要 API Key」；② 填自定义端点时不要带结尾 `/`（程序会自己去掉）；③ 完全离线可用 `ollama` 预设（`http://127.0.0.1:11434/v1`，无需 Key）；④ 点「拉模型列表」核对模型名；⑤ 先 `ollama serve` 并 `ollama pull qwen2.5:7b`；⑥ 连续失败会触发熔断，路由会跳过该目标并给出原因，稍后自动恢复。**401 报错**说明 Key 无效或过期，重新生成后填回 |
| **助手面板的余额 chip 显示「余额 —」** | 当前厂商**不提供余额接口**（只有 DeepSeek 有公开的 `GET /user/balance`；ollama、hermes、自建端点都没有） | **这是设计行为**，不是坏了。点一下 chip 会打开该厂商的控制台地址（认得出的话）让你自己去查；认不出控制台就只给一句提示。程序对这类厂商**一个请求都不发** |
| **余额 chip 显示「余额 ?」** | 查询失败：未填 Key、Key 无效／无权限、超时 8 秒、或被私网守卫拦下 | 悬停看 `title` 里的原因；点一下重试（绕过服务端 60 秒缓存）。先确认「助手」页的 Key 有效、`baseUrl` 指向 `api.deepseek.com`；401/403 说明 Key 无效或没有余额查询权限。**Key 只进请求头，不会出现在响应或日志里** |
| **上下文 chip 只显示 token、没有百分比** | 该模型名没被预设表收录（`contextWindowPreset === 0`，例如本地 `qwen2.5:7b`） | **这是设计行为**——「未知」不编造百分比。想看占比，可在 `data/config.json` 的 `agent.contextWindow` 里填一个正数（token）显式指定窗口 |
| **整轮什么都没输出**（只有一行 token 脚注，没有回答气泡） | 模型这一轮只吐了思维链、正文为空；或模型名写错、Key／额度有问题 | 界面上会有一条虚线红边的兜底说明列出这三种原因。先到「助手」页核对**模型名**（DeepSeek 官方只有 `deepseek-chat` 与 `deepseek-reasoner`，写成别的名字多数端点会拒或返回空）与「单次回复上限」，再点「测连通」 |
| **本地小模型不调工具**（回复里直接讲卦，不调 `cast`） | 多数 7B 模型不支持原生 function calling | 把「工具调用方式」切成**文本协议降级**（`agent.useNativeTools: false`，对应 Hermes 的 `text-fence`）：模型输出 ```json {"tool":"cast","args":{…}} ```，程序自己解析。若用的是 Hermes 系模型，改用 `hermes` 预设（自动识别为 `hermes-xml`） |
| **卸载后数据还在吗** | 数据在 `%APPDATA%\问心卦\data`，与安装目录分离；构建配置未启用 `deleteAppDataOnUninstall`，卸载程序只删安装目录 | **数据默认保留**。卸载后请自行确认 `%APPDATA%\问心卦\data\records\` 仍在——在即数据完好。想彻底清干净见 §11 |
| **桌面快捷方式没建** | 安装时用了 `/S` 静默安装，而 `createDesktopShortcut` 被写成 `true`（被做成完成页的勾选项，静默安装跳过该页） | 本版本已写 `"always"`，静默安装也会建。若仍没有：手工运行 `创建快捷方式.ps1`，或确认 `build.nsis.createDesktopShortcut === "always"` 后重新打包 |
| **安装时构建报错、解压 `winCodeSign` 失败** | 该压缩包含 macOS dylib 的符号链接，解压需要开发者模式或管理员权限 | 见 §4.3 坑二：保持 `build.win.signAndEditExecutable: false`；或开启 Windows 开发者模式 |
| **界面空白／样式全丢** | `web/` 被改坏，或 `GET /` 返回了 JSON 错误 | 打开浏览器开发者工具看控制台与网络；命令行版看服务控制台的报错；`node tools/check-web.mjs` 会逐页报出哪一页渲染失败 |
| **导入认不出卦** | 粘贴文本的格式与解析器支持的三种（DeepSeek 对话式／紧凑表格式／分行标签式）都不符 | **这是设计行为**：解析器「宁可少认，不可错认」，认不准会列出「缺什么」而不是猜。改用**卦条 v1**（`node tools/import.mjs --template` 生成模板），它是保证稳定的导入契约 |
| **校勘里出现不符** | 原卦用的是另一路取法（如仅以报数取动爻、下卦取数与时之和除八） | 这是**存录**而非错误。程序会尽量反推原取法并忠实还原；反推不出时按「已知卦象」保留原卦并记入校勘。原述完整保留在 `claimed` 与「原文存录」中 |

## 十、日志与诊断

### 10.1 日志位置

| 形态 | 日志位置 | 怎么看 |
|---|---|---|
| **桌面版**（含开发态） | `%APPDATA%\wenxingua-desktop\desktop.log`（即 Electron userData；实测该文件存在且逐次追加）。开发态**同时**打到启动它的控制台 | 用记事本打开，或 `Get-Content "$env:APPDATA\wenxingua-desktop\desktop.log" -Tail 40`；开发态也可看 `cd desktop && npm start` 的那个窗口 |
| **命令行版** | 标准输出／标准错误 | 起服务的那个终端窗口 |
| **MCP 服务** | 标准错误（`stderr`） | 由宿主（Codex/Claude/DSH）收集；**stdout 只允许 JSON-RPC**，不得用来打日志 |
| **插件** | 走宿主 logger：`ctx.log()` 进标准输出（带 `[<插件id>]` 前缀），`ctx.warn()` 进标准错误 | 加日志用 `ctx.log`／`ctx.warn`，不要用 `console.log` |

> 日志也可从菜单直达：**「帮助 → 打开启动日志」**会在系统默认程序里打开这份文件，紧邻的「在文件管理器里定位日志」则用于选中它。日志文件不存在时会弹窗告知预期路径，而不是静默失败。

### 10.2 日志里有什么

桌面版每次启动都会记一段结构化信息，字段固定，便于比对：

```
[<ISO 时间>] --- main.mjs 启动 --- {"electron":"33.4.11","chrome":"130.0.6723.191","node":"20.18.3","packaged":false,"resourcesPath":"…","argv":[…]}
[<ISO 时间>] 代码根目录 <CODE_ROOT>
[<ISO 时间>] 数据目录已定 {"dir":"…","mode":"dev|appdata|chosen"}
[<ISO 时间>] app ready，开始初始化
[<ISO 时间>] 服务模块已载入
[<ISO 时间>] 服务已监听 {"url":"http://127.0.0.1:<port>/","port":<port>,"host":"127.0.0.1"}
[<ISO 时间>] 窗口已创建，开始 loadURL
[<ISO 时间>] loadURL 完成
```

**「日志停在哪一行」就是诊断结论**：

| 最后一行 | 说明 |
|---|---|
| `--- main.mjs 启动 ---` 之后没有了 | 主进程在模块求值阶段卡住（典型是顶层 `await`）或 preload/依赖加载失败 |
| 停在 `数据目录已定` 之前 | 数据目录解析抛错（权限、路径非法） |
| 停在 `服务模块已载入` 前 | 服务代码载入失败（`server/index.mjs` 或其依赖语法错） |
| 有 `服务已监听` 但没有 `窗口已创建` | 建窗口阶段失败 |
| 有 `loadURL 完成` 但界面空白 | 前端问题，看渲染进程控制台（`npm run dev` 开开发者工具） |

主进程还挂了两个兜底：

```js
process.on('uncaughtException', (err) => log('uncaughtException', err));
process.on('unhandledRejection', (err) => log('unhandledRejection', err));
```

### 10.3 把自检脚本当诊断工具用

自检脚本不只是给开发者的，它们是最好的分诊工具。**按症状挑一套**：

| 症状 | 跑这个 | 它告诉你什么 |
|---|---|---|
| 「卦象/断语好像不对」 | `node tools/check.mjs` | 六个历史卦局、卦典、历法、断语七段、走势、迁移、agent 工具——一次给出 152 项结论 |
| 「导入的文件不认」 | `node tools/validate.mjs 我的卦条.txt` | 该文件的逐条问题（缺什么、哪个键名认不出），**不落盘** |
| 「某条卦录是不是坏了」 | `node tools/validate.mjs data/records/<id>.json` | 结构与语义问题清单 |
| 「MCP 接不上」 | `node tools/check-mcp.mjs` | stdout 纯净性、协议往返、未知方法处理 |
| 「某个页面坏了」 | `node tools/check-web.mjs`（连不上服务时会自起一个示例服务） | 逐条路由渲染结果与接口约定 |
| 「桌面版有问题」 | `node tools/check-desktop.mjs` | 外壳文件、preload 形态、IPC 注册顺序、真窗口内 32 项断言 |
| 「模型接入坏了」 | `node tools/check-hermes.mjs` | 四类协议的编织与还原、路由选择、重试与熔断、旧配置兼容——全离线，不打网络 |

另外三个专用开关：

```bash
node tools/import.mjs 卦条.txt --dry        # 只解析不落盘，先看认得对不对
node server/index.mjs --open                # 起服务并自动开浏览器
electron . --shot=out.png --shot-hash=#/trend   # 桌面版真窗口截图（排查渲染问题）
```

实测安装目录（示例）为 `F:\Apps\wenxingua-desktop\`，卸载器名为 `Uninstall 问心卦.exe`。

**卸载只删安装目录。** 数据在 `%APPDATA%\问心卦\data`，与程序分离，卸载时保留。

### 11.2 彻底清理（确认不再需要数据时）

**执行前必须确认每个路径确实是问心卦的目录，删除不可逆。**

| 要清理的东西 | 路径 | 说明 |
|---|---|---|
| 程序 | 安装目录（如 `F:\Apps\wenxingua-desktop\`） | 卸载器已处理 |
| **卦录与配置** | `%APPDATA%\问心卦\` | 含 `data\records\`、`data\trash\`、`data\backups\`、`data\plugins\`、`config.json`（**含明文 API Key**） |
| 桌面版运行痕迹 | `%APPDATA%\wenxingua-desktop\` | 日志、窗口状态、`data-dir.json`、Chromium 缓存 |
| 零安装兜底的浏览器配置 | `%LOCALAPPDATA%\问心卦\窗口配置\` | `--user-data-dir` 指向的独立配置目录 |
| 快捷方式 | 桌面与 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\问心卦\` | `.lnk` |
| 从源码跑的临时产物 | `<项目>\data\trash\_negtest\`、`%TEMP%\qxg-*` | 自检残留 |

```bat
:: 全部清理（逐条执行，先看清楚再回车）
rmdir /S /Q "%APPDATA%\问心卦"
rmdir /S /Q "%APPDATA%\wenxingua-desktop"
rmdir /S /Q "%LOCALAPPDATA%\问心卦"
```

### 11.3 只想清空卦录、保留程序

停掉程序，删除 `<数据目录>\records\` 下的文件即可（**先备份**）。下次启动时 `records/` 仍为空——随包的 `seed-data` 只含示例插件、**不含卦录**，不会把任何卦录带回来。
