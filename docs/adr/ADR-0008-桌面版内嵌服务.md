# ADR-0008：桌面版把服务内嵌进 Electron 主进程

| 项 | 内容 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-03 |
| 决策者 | 项目维护者 |
| 影响的模块 | `desktop/main.mjs`、`desktop/preload.cjs`、`server/index.mjs`、`server/store.mjs`、`web/app.js`、`tools/check-desktop.mjs`、`desktop/build/make-icon.py` |

## 背景

桌面版的内核**一行没改**，只是加了一层壳：`desktop/main.mjs` 直接 `import` `server/index.mjs`，在**同一个进程**里起服务。

```js
const mod = await import(pathToFileURL(serverEntry).href);
const srv = mod.app;
started = await srv.listen(19730, '127.0.0.1', { quiet: true });
```

端口被占（例如另开着一个命令行版）时退到 `listen(0, '127.0.0.1')` 让系统分配空闲端口，窗口照常打开。`started.url` 既用于 `mainWindow.loadURL(APP_URL)`，也用于「外链一律交给系统浏览器」的判定：`setWindowOpenHandler` 与 `will-navigate` 只在 `url.startsWith(APP_URL)` 时放行。

数据目录在 `import` 服务**之前**定好，并把结果写进环境变量交给服务：

```js
process.env.QXG_DATA_DIR = DATA.dir;
```

`server/index.mjs` 的 `resolveDataDir()` 把 `QXG_DATA_DIR` 排在最高优先级，因此桌面版能决定数据落在哪。桌面版的解析顺序是：用户显式选过的（`userData/data-dir.json`）→ 开发态用项目里的 `data/` → 安装态用 `%APPDATA%\问心卦\data`，并在首次为空时从随包的 `seed-data` 复制一份初始卦录。**绝不放在安装目录里**——升级会覆盖 `resources/app`。

渲染进程与主进程之间只有一条窄通道：`desktop/preload.cjs`（必须是 CJS）用 `contextBridge.exposeInMainWorld('__qxgDesktop', …)` 暴露 `isDesktop`、`info()`、`openDataDir()`、`openBackups()`、`exportBackup()`、`revealRecordFile(id)`、`chooseDataDir()`、`onNavigate(fn)`；窗口用 `contextIsolation: true`、`nodeIntegration: false` 创建。主进程侧对应的 `ipcMain.handle` 在 `loadURL` **之前**注册。

打包形态与之配合：`desktop/dist/` 下同时有 `win-unpacked/`（免安装，整个文件夹拷到哪都能跑）与 `问心卦-安装包-1.1.0.exe`（NSIS 安装器，约 78 MB）。`resources/` 下是 `app.asar`、`app`（代码根目录）与 `seed-data`。

## 决策

桌面版**必须**把本地服务跑在 Electron 主进程内（同进程 `import`，不 spawn 子进程）。**不得**在启动时弹出控制台窗口，**不得**要求用户机器上安装 Node。数据目录**必须**在 `import` 服务之前通过 `QXG_DATA_DIR` 指定，且**不得**落在安装目录内。渲染进程**必须**以 `contextIsolation: true` ＋ `nodeIntegration: false` ＋ CJS preload 的方式创建，**必须**在 `loadURL` 之前完成 `ipcMain.handle` 注册。

## 理由

1. **什么都不用装。** Electron 自带 Chromium 与 Node 运行时，所以安装包里不需要额外的 Node，用户也不需要配环境。README 对比里写得很直白：命令行版才需要 Node.js 18+。
2. **不闪黑窗。** Windows 上 spawn 一个 `node.exe` 会弹出控制台窗口，或者需要额外手段隐藏它（项目里保留的零安装兜底方案 `问心卦(桌面窗口).vbs` 用的就是隐藏控制台的老办法）。同进程起服务从根上没有这个窗口。
3. **少一套进程生命周期要管。** 不需要处理子进程崩溃、孤儿进程、端口占用后的重试握手、退出时的杀子进程。`before-quit` 里只 `await serverHandle?.close()` 就够干净。
4. **与内核的耦合面最小。** `server/index.mjs` 导出 `app`（一个带 `listen`／`close` 的对象）并遵守 `QXG_DATA_DIR` 约定，此外不需要为桌面版做任何改造。这条「内核一行没改」的性质让四种形态（命令行、桌面窗口、桌面版源码、安装包）共用同一份实现。
5. **文档与调试路径统一。** 桌面版加载的是 `http://127.0.0.1:<port>/`，因此 `node tools/check-web.mjs` 验证过的路由与渲染，在桌面窗口里同样成立；排查也可以直接用浏览器打开同一地址。

## 后果

### 正面

- 安装器中文、可改安装目录、建桌面与开始菜单快捷方式、卸载不删卦录。
- 免安装版可放 U 盘：`win-unpacked/` 整个拷走即可运行。
- 单实例锁（`requestSingleInstanceLock()`）保证第二次双击只前置已有窗口，不会起第二个服务。
- 窗口尺寸、位置与最大化状态记在 `userData/window-state.json`，并在屏幕配置变化导致窗口跑到屏外时退回默认位置。
- 菜单与托盘可直接跳转（`#/cast`、`#/trend`）并打开数据目录／备份目录／回收目录；`core` 的「打开数据目录」「导出整包备份」在界面上也有对应按钮。
- 有可断言的验收路径：`--selftest` 在**真实窗口**里跑一组断言（桌面桥存在、桥能取版本与数据目录、状态栏显示「桌面版」、逐页路由渲染、卦录详情七段俱全），`--shot=<png>` 截图后退出，两者都由 `tools/check-desktop.mjs`（53 项）驱动。

### 负面

- **主进程承压。** HTTP 服务、插件宿主、存储、窗口与渲染协调全在一个进程里。任何**同步**的重活（`loadAll()` 遍历全部卦录、整包导出拼接、插件里同步读写大文件）都会卡住主进程，进而卡住窗口——Electron 的主进程阻塞等于界面无响应。当前数据规模下不成问题，但这是结构性约束，不是偶发问题。
- **端口仍是本机可见的。** 服务真的在 `127.0.0.1:<port>` 上监听，同机其他进程可以访问 `data/` 的接口（含 `/api/agent/tool/:name` 这条「直接执行任一工具」的路径）。桌面版没有额外的鉴权层。
- **四个真踩过的坑必须一直绕开。** ①主进程不能写顶层 `await app.whenReady()`（ready 事件要等主模块求值完成后才发，顶层 await 会让模块求值挂起，直接死锁，现象是「进程在跑、没有窗口」）；②preload 必须是 `.cjs` ＋ `require`（沙箱化的 preload 不能是 ES 模块，写成 `.mjs` 会**静默失败**，`window.__qxgDesktop` 永远是 undefined 却不报错）；③`ipcMain.handle` 必须在 `loadURL` 之前注册（否则报 `No handler registered for 'qxg:info'`）；④环境里若带着 `ELECTRON_RUN_AS_NODE=1`，Electron 会退化成纯 Node、没有窗口，启动前必须清掉（`tools/check-desktop.mjs` 已自动清）。这些坑都由静态检查或真起窗口的自检守着，但它们的代价是：**改桌面外壳必须跑 `check-desktop.mjs`**。
- **打包环节有平台相关的绕行。** Windows 上 `winCodeSign` 的 7z 内含 macOS dylib 的符号链接，解压需要开发者模式或管理员权限，否则构建直接失败；项目用 `signAndEditExecutable: false` 绕开，代价是 exe 文件本身不带自家图标（窗口图标、托盘、快捷方式图标不受影响）。`createDesktopShortcut` 必须写 `"always"` 而不是 `true`，否则 `oneClick: false` 的安装器会把它做成完成页的勾选项，静默安装时就跳过不建。这两条都是实测踩出来的。
- **窗口外壳依赖 Electron 的版本节奏。** 升级 Electron 大版本要重跑桌面自检，并复核上述四个坑是否仍然成立。

## 备选方案与为何不选

| 方案 | 为什么没选 |
|---|---|
| 主进程 spawn 一个 `node server/index.mjs` 子进程 | 需要用户机器上有 Node，或者用 `process.execPath` ＋ `ELECTRON_RUN_AS_NODE=1` 把 Electron 当 Node 用（把上面第 4 个坑变成常态）；还要多管一套子进程生命周期与端口握手。 |
| 不用 Electron，只保留浏览器形态 | 就失去了「独立窗口、独立任务栏图标、托盘、开始菜单快捷方式」，也失去「什么都不用装」的体验；项目仍保留浏览器形态作为开发与调试入口（方式三）与零安装兜底（方式二）。 |
| 用 Tauri／NW.js 等其它外壳 | 会引入 Rust 工具链或另一套运行时，与零依赖取向冲突；且 `desktop/` 现有实现与 `server/index.mjs` 的耦合面已经很小，换壳收益有限。 |
| 把服务与界面都放进渲染进程（无 HTTP 服务） | 内核是 Node 侧代码（`node:fs`／`node:path`），渲染进程在 `nodeIntegration: false` 下拿不到；要么开 `nodeIntegration`（安全上不可接受），要么把内核改写成浏览器兼容版（破坏「一处实现」）。 |
| 桌面版单独维护一份数据目录逻辑 | 会与命令行版产生两套判断，出现「桌面版看得见、命令行看不见」这类问题。当前做法是共用 `QXG_DATA_DIR` 约定，两处解析逻辑都写在各自模块里但语义一致。 |
